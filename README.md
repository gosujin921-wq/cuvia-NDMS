# CUVIA 재난안전관제시스템

## 현재 단계: Phase 2 방향 수립

이 저장소의 현재 코드는 창원특례시 재난안전관제 **Phase 1 프로토타입**이다.
완성된 제품 사양이 아니며, Phase 2에서는 기존 화면 구조를 참고하되 이벤트 수집·해석·예측·대응의
제품 방향을 다시 정리한다.

Phase 2의 목표는 기능과 재난유형을 많이 추가하는 것이 아니다.

> **어떤 이벤트를 수집하고, 어떻게 하나의 사건으로 해석하며, 디지털트윈 예측과 대응에 어떻게
> 활용하는지를 대표 데모로 보여준다.**

Phase 2 계획의 정본과 읽는 순서는 [`docs/고도화/README.md`](./docs/고도화/README.md)가 관리한다.
계획이 확정되기 전에는 현재 코드를 신규 요구사항의 근거로 사용하지 않는다.

## Phase 1 프로토타입

현재 구현은 시 전체 조망에서 시작해 지구·센서·CCTV로 좁히고, 경보 이력과 주민 전파를 거쳐
3D 침수 분석까지 이어지는 흐름을 보여준다. Phase 2에서는 이 자산을 유지·재편·제거 후보로 다시
검토한다.

| 화면 | 무엇 |
|---|---|
| SCR-01 | 종합상황 |
| SCR-02 | 재난관제 (구 SCR-03 상황대응을 흡수해 결번) |
| SCR-04 | 통계·분석 |
| SCR-05 | 디지털트윈 |
| SCR-06 | AI 검색 |
| SCR-07 | 보고서 |

```bash
cd designs
corepack pnpm install
corepack pnpm dev      # http://localhost:5400
```

## 폴더

| 폴더 | 무엇 |
|---|---|
| [designs/](./designs/) | 앱. Vite + React + Tailwind v4 ([실행법](./designs/README.md)) |
| `docs/` | 작업 문서·참고자료·매뉴얼 |

> ⚠ **`docs/` 는 `고도화/` 만 저장소에 실린다**(`.gitignore`). 나머지는 인증키가 든 문서와
> 대용량 참고자료(84MB)라 새로 클론하면 **없다.** 필요하면 별도로 받는다.
> 안에 무엇이 있는지는 아래 "문서" 절에 적어 둔다.

CCTV 스틸은 원본 PNG(`designs/cctv-src/`)와 서빙본 JPG(`designs/public/cctv/`)가 둘 다 실려 있다.
원본을 고치면 `cd designs && node scripts/cctv-build.mjs` 로 서빙본을 다시 굽는다.

## 변경 기준

Phase 2 방향 수립 중에는 **계획 문서가 목표 사양이고, 코드는 현재 상태를 보여주는 참고 구현**이다.
기존 프로토타입을 유지보수할 때만 아래 코드 위치를 현재 동작의 기준으로 사용한다.

| 무엇 | 어디 |
|---|---|
| 확정값(원장 32건 · 발령 기준 · 침수영향 · SOP · 전파) | `src/demo/*.ts` |
| 화면 동작 | `src/pages/` · `src/components/` |
| 시연 중 변하는 상태 | `src/state/ScenarioProvider.tsx` |
| DS 진입점 | `src/ds.ts` 한 곳 |

작업 규율은 [CLAUDE.md](./CLAUDE.md) 가 든다.

(`04 §11` 등)가 가리키지만 더 이상 갱신하지 않는다. Phase 1 동작 확인에는 코드가 우선하고,
Phase 2 목표 판단에는 `docs/고도화/README.md`의 단일 정본이 우선한다.

## 추후 개발로 넘길 때

이 데모는 이관을 전제로 짰다. Phase 1 코드 감사에서 남은 핵심은 다음과 같다.

- DS 는 `src/ds.ts` 한 경로로만 받는다. 제품으로 옮길 때 **이 파일의 재수출 대상만** 바꾼다
- 화면은 `demo/` 의 **원시 배열이 아니라 파생 함수**를 문다. 데이터 원본을 갈아도 시그니처만 지키면 화면이 안 바뀐다
- 남은 일 셋: 동기 함수를 비동기로 · `ScenarioProvider` 를 연출/업무/UI 셋으로 분리 · 시연 트랙 분기 걷어내기
