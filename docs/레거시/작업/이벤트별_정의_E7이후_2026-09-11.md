## E7 CCTV·VLM

| 항목 | 내용 |
|---|---|
| 무엇인가 | VLM이 CCTV 장면을 문장으로 해석한 결과. "차로 일부 물고임 추정, 신뢰도 0.82". 분석 계층이며, 영상 자체가 아니라 영상에 대한 판단 하나가 이벤트다. 센서 한 건이나 VLM 문장 하나를 곧바로 사건이라고 부르지 않는다(01 §1) |
| 종합상황 | 두 자리. D0에서는 예측 강수와 침수흔적도로 고른 **감시 우선 카메라**가 하단 스트립에 서고 "왜 이 카메라인지" 한 줄이 붙는다(요약설명자료 1단계). D1~D2에서는 큐 행 근거 종류에 "영상 물고임 추정" |
| 사건 화면 | 영상·현장 자리. CCTV 영상(스틸 또는 클립)과 VLM 문장을 **나란히**. 문장 옆에 신뢰도, 모델·버전, 분석시각. 담당자가 영상을 보고 [확인] [추가 확인] [오탐]을 누른다. 시스템이 판독한 것이 아니라 사람이 확인한 것으로 기록된다. 타임라인에 분석 시각과 확인 시각이 각각 눈금 |
| 디지털트윈 | 계산에 안 들어간다. 침수 시작을 눈으로 확인한 근거로 근거·한계 칸에 선다. 종료 후에는 예측 침수심과 비교하는 실제 장면(검증) |
| 대응 | 위험도 4축의 확실성에 쓰인다. 센서·시설·예측과 영상이 같은 방향이면 확실성이 높고, 어긋나면 그 자체가 반대 근거다(02 D3). 전파문에는 직접 안 들어간다 |
| 모의훈련 | 시나리오가 정한 장면 표본을 같은 자리에 띄운다. 훈련 대상은 영상을 보고 확인·오탐을 판단하는 것 |
| 데모 값 | 합성. Phase 1 보유 스틸 18장·클립 2개 중 사건에 맞는 것(도심 침수 시작, 배수문 외수위 상승, 수로 합류부 수위 상승)을 쓰고, VLM 문장·신뢰도·모델명은 시나리오로 정한다. 정상 장면 하나를 섞어 VLM이 "이상 없음"을 낸 카메라도 보인다. 오탐 하나를 넣어 담당자가 [오탐]을 누르는 장면을 만든다 |
| Phase 1 자산 | 종합상황 CCTV 스트립, 조기경보 하단 CCTV 독(2대)과 큰 보기, 집중 팝업의 영상 영역(카메라 전환 칩), 교차검증 패널의 "CCTV 현장 확인" 행(담당자가 열기 전엔 미확인). 스틸·클립 20개. 없는 것은 VLM 문장·신뢰도·모델명과 담당자 판정 버튼 |

Phase 1 원칙 하나는 그대로 가져온다. **시스템이 영상을 판독한 것처럼 만들지 않는다.** VLM은 추정을 내고, 사건으로 확정하는 것은 담당자다. 요약설명자료의 "VLM이 침수 시작을 포착하고 기상 상황을 반영해 오탐을 거른다"는 문장은 D2 장면에서 "예측강우와 방향이 맞아 오탐 가능성 낮음" 한 줄로 보인다.

## E0 실측강우

| 항목 | 내용 |
|---|---|
| 무엇인가 | 강우계가 잰 시간당 강수량. E1 예측강우가 "앞으로"라면 E0은 "지금" |
| 종합상황 | 상단 스트립에는 안 선다. 지도 비 레이어가 예측(E1)이므로 실측은 사건 화면 몫이다 |
| 사건 화면 | 계측 추이 패널에 관로·도로수위와 같은 시간축으로. 근거 목록에 "실측강우 17:00~17:30 누적 28mm". D3 위험 요인 "강우 지속"의 근거 |
| 디지털트윈 | 지금의 유입량. 침수 모형 입력. 현재 상태 칸에 강우와 추세 |
| 대응 | 위험 요인에 인용 |
| 모의훈련 | 시나리오 조건 "강우 강도"가 대신한다(E1과 같은 자리) |
| 데모 값 | 시나리오 값. E1 예측이 오른 뒤 실측이 따라 늘고, 그 뒤 관로수위가 오른다. D8에서 약해진다. 예측(E1)과 실측(E0)이 같은 시각에 나란히 보여야 "예측이 맞았다"가 읽힌다 |
| Phase 1 자산 | 계측 추이 패널에 강우량계 항목이 있다(봉암 트랙). 그대로 쓴다 |

## E3 조위 (예측조위 · 실측조위)

| 항목 | 내용 |
|---|---|
| 무엇인가 | 마산만 조위. 예측조위(E3a)는 만조 시각과 높이의 전망, 실측조위(E3b)는 지금 값. 대표 사건에서 조위는 침수 모형의 경계조건이지 별도 해안 사건이 아니다(03 §6 A) |
| 종합상황 | 큐 행에 직접 안 선다. D0 상황 "예측강우가 만조 시간과 겹친다"가 감시 우선순위 근거에 한 줄로 |
| 사건 화면 | 교차검증 근거 행에 실측조위와 천문조 대비 편차, 만조 시각. 근거 목록에 "만조 19:10 예측 · 현재 조위 높음, 자연배수 불리". D3 위험 요인 "높은 조위" |
| 디지털트윈 | 자연배수 제약. 예측조위는 앞으로의 조건, 실측조위는 지금 조건. 시간 조절에서 만조 시각이 눈금 하나로 선다. C 해안 월류 유형에서는 이 값이 주인공이 된다 |
| 대응 | 위험 요인에 인용. 통제 시점을 만조 전으로 잡는 근거 |
| 모의훈련 | A의 "만조 겹침" 시나리오와 C의 "태풍 편차 증가" 시나리오가 이 값을 바꾼다 |
| 데모 값 | 시나리오 값. 사건 기준시각 뒤 1~2시간에 만조가 오도록 둔다. 실측조위는 만조를 향해 오르고, 예측조위는 만조 높이 하나. 실제 조위 자료가 오면 값만 교체 |
| Phase 1 자산 | 교차검증 패널의 조위 4칸(천문조·실측·해일 편차·만조)과 배수 수지 4칸(외수위·내수위·자연배수 차단·만조). 서항 트랙에서 다 만들어 둔 것이라 그대로 쓴다 |

## E9 현장 관측·조치 보고

| 항목 | 내용 |
|---|---|
| 무엇인가 | 현장 담당자가 보낸 보고. 도로 통행 불가 확인, 통제 완료, 펌프 점검 결과, 사진. 원천 계층이고 시스템이 만든 것이 아니라 사람이 넣은 것이다 |
| 종합상황 | 큐 행의 처리상태가 대응중·통제로 바뀌는 근거. 직접 표시는 없다 |
| 사건 화면 | 영상·현장 자리에 "현장 보고 18:05 · 남측 도로 통행 불가 · 사진 1". 이력 탭에 보고 시각과 담당자. D7 "현장 담당자의 도로 통제·시설 점검 결과" |
| 디지털트윈 | 검증값. 종료 후 예측 침수심·도달시간과 비교하는 실제 결과의 하나(E5 실측과 함께) |
| 대응 | 실행 결과 칸에 붙는다. 통제 요청의 "성공"은 이 보고로 확정되고, 미응답이면 대체조치로 넘어간다. Phase 1의 [유선 보고 기록]이 이 자리다 |
| 모의훈련 | 훈련에서는 시나리오가 정한 보고가 자동으로 들어온다. 훈련 이력에는 담당자의 대응 선택만 남는다 |
| 데모 값 | 사용자 입력·수동. 셋이면 된다. 통제 완료 보고 하나, 펌프 점검 결과 하나, 종료 전 "도로 통행 재개" 하나. 시연자가 누르는 것이 아니라 시나리오 시각에 들어온다 |
| Phase 1 자산 | SOP 패널의 [유선 보고 기록]과 실행 결과 행. 이력 탭의 대체 조치 줄. 보고를 이벤트로 받는 구조는 새로 세운다 |

## E10 데이터 지연·결측·복구 판정

| 항목 | 내용 |
|---|---|
| 무엇인가 | 시스템이 "이 원천이 늦다, 빠졌다, 돌아왔다"를 판정한 것. 파생 계층. 01 예시 "강우계 6분 미수신" |
| 종합상황 | **데이터 상태 패널**의 주인공. 지연·결측·의심 원천과 그 영향을 받는 사건. Phase 1 기관 연계 현황(정상/끊김)을 이 패널로 재편한다 |
| 사건 화면 | 근거 목록의 해당 줄에 경고. "조위 12분 지연 · 이 구간 불확실". D2 "의심·지연 데이터 경고". 헤더의 데이터 표시에도 반영 |
| 디지털트윈 | 근거·한계 칸. 결측·지연 구간을 계산 제한으로 표시한다. 그 구간의 예측은 불확실성이 높다 |
| 대응 | 확실성 축을 낮추는 근거. 전파 실패(경남 연계 끊김)는 이 이벤트가 아니라 실행 결과(Action 상태)다. 헷갈리지 않게 가른다 |
| 모의훈련 | 시나리오가 정한 결측 하나 |
| 데모 값 | 시나리오 값. 둘이면 된다. D2 즈음 조위 지연 하나(복구까지 포함), D7 즈음 도로수위계 결측 하나. 둘 다 "복구" 이벤트로 닫아서 상태가 돌아오는 것까지 보인다 |
| Phase 1 자산 | 종합상황 기관 연계 현황 패널, 조기경보 팝업의 통신끊김 표시(마지막 수신 시각). 원천별 지연·결측을 이벤트로 세우는 구조는 새로 만든다 |
