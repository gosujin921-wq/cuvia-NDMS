# 이벤트별 정의 초안

> 상태: 방향 논의 초안. 정본 인용 금지. 이벤트마다 확인이 끝나면 02 §5 뒤에 "이벤트별 정의" 절로 옮기고
> 이 파일은 지운다.
>
> 작성: 2026-09-11. 02 §5.1 표의 이벤트 E0~E10을 하나씩 같은 틀로 적는다. 기획 범위만 적는다. 무엇인지,
> 화면 어디에 어떻게 보이는지, 디지털트윈·대응·모의훈련에서 무슨 역할인지, 데모에서 어떤 값으로 보여줄지,
> Phase 1에 무엇이 있는지. 데이터 필드·규칙 ID·API 인증 같은 개발 항목은 01·02 §5.4가 갖고 있으므로 여기
> 적지 않는다.
>
> 데모 값은 전부 지금 예상값으로 만든다. 실제 값이 오면 그 자리만 갈아 끼운다(README §8.2). 실제 값이
> 이미 있는 것은 E1 예측강우 하나다.
>
> 순서: E8 → E1·E2 → E4·E5 → E6 → E7 → E0·E3·E9·E10.

## E8 침수예측판

| 항목 | 내용 |
|---|---|
| 무엇인가 | 침수 모형이 낸 "언제 어디가 얼마나 잠기나". 유효 시각별 침수심과 도달시간. 새로 나오거나 갱신될 때마다 이벤트 하나 |
| 종합상황 | 후보 행에 "예측: 40분 뒤 남측 침수 예상" 한 줄. 예측이 후보의 근거 중 하나다 |
| 사건 화면 | 근거 목록에 "17:20 침수예측판 · 18:00 남측 침수심 0.3m · 도로 2 · 대상자 120명". 관측·영상과 같은 줄. 갱신되면 새 줄이 쌓인다. 줄 끝에 [디지털트윈 보기]. 타임라인에는 유효 시각이 미래 눈금으로 선다 |
| 디지털트윈 | 이 이벤트가 디지털트윈 화면의 결과 그 자체다. 3D 지도의 침수심, 시간 조절 눈금, 영향 결과의 기준 전망 열 |
| 대응 | 담당자가 고른 예측판이 대응 팝업으로 넘어가고 권고 카드에 "18:00 전망" 기준이 표시된다 |
| 모의훈련 | 같은 예측판을 훈련 시나리오의 조건으로 쓴다. 배수 대응 대안은 계수를 적용한 판이 하나 더 |
| 데모 값 | 합성. 배수권역 셋 정도에 유효 시각 +10·+30·+60분마다 침수심 하나와 도달시간 하나. 기준 판 하나, 배수 대응 판 하나. 도로 통제는 판을 새로 만들지 않고 대상자만 뺀다. 상승 방향은 관로·조위·펌프 순서와 맞춘다 |
| Phase 1 자산 | 트윈 페이지의 지형·수면 코드는 표현 자산이다. 권역별 침수심 값을 받아 그리는 쪽으로 바꾼다 |

## E1 예측강우

| 항목 | 내용 |
|---|---|
| 무엇인가 | 기상 예측이 낸 시간당 강수량 격자. 상향 갱신될 때 이벤트 |
| 종합상황 | D0의 출발점. 예측 강수가 오르면 침수흔적도와 결합해 감시 우선구역과 CCTV를 고른다. 화면에는 예측 기준시각·유효시간과 감시 우선순위 근거. 지도에는 비 격자 레이어 |
| 사건 화면 | 근거 목록에 "17:00 예측강우 · 19시 17.8mm/h · 기준 16:00". 특보와 나란히 맥락 줄 |
| 디지털트윈 | 앞으로의 유입량. 침수 모형의 경계조건. 근거 칸에 "계산에 사용" |
| 대응 | 직접 쓰이지 않는다. 권고 사유에 "예측강우 상향"이 인용된다 |
| 모의훈련 | 시나리오 조건 "강우 강도"가 이 값을 대신한다. Phase 1 사전 모의분석의 조건 셀렉트 그 자리 |
| 데모 값 | 실제 값. Open-Meteo 2024-09-21 창원 격자가 이미 있다. 시연 시각에 맞춰 다시 굽기만 한다 |
| Phase 1 자산 | 강수 격자 파일과 지도 비 레이어. 종합상황 기상 카드는 제거하고 레이어만 남긴다 |

## E2 호우특보

| 항목 | 내용 |
|---|---|
| 무엇인가 | 기상청 특보의 발표·변경·해제. 단계(주의보·경보), 발표·발효·종료 시각, 대상 지역 |
| 종합상황 | 상단 스트립의 특보 배지. 감시 강화의 공식 맥락. 특보만으로 사건 후보를 만들지 않는다 |
| 사건 화면 | 헤더에 특보 단계와 유효시간. D3에서 "공식 특보: 단계, 발표·갱신시각, 유효시간, 대상지역". 위험도 4축과는 별개다. 특보는 맥락이고 4축은 이 사건의 판단이다. 타임라인에 발표·변경·해제 눈금 |
| 디지털트윈 | 계산에 안 들어간다. 근거 칸에 맥락으로만 |
| 대응 | 전파문 CAP 필드의 출발점. 특보의 심각도·긴급도·확실성·대상지역을 전파문이 이어받는다. 재전파는 "갱신" |
| 모의훈련 | 시나리오가 특보 단계를 정해 둔다. 배경이다 |
| 데모 값 | 합성 통보문. 2024-09-20 창원 주의보 → 경보(완료보고 p.60이 확인한 사실)를 사건 시각에 맞춰 둔다. 기상청 실제 통보문이 오면 문안과 시각만 교체 |
| Phase 1 자산 | 종합상황 스트립의 특보 배지. Phase 1은 특보를 사건에서 파생하는데, Phase 2는 특보가 독립 이벤트다 |

## E4 관로수위 (관측 · 급상승)

| 항목 | 내용 |
|---|---|
| 무엇인가 | 관로수위계 값(관측)과, 짧은 시간에 너무 빨리 올랐다는 판정(급상승). 급상승은 시스템이 관측에서 계산한다 |
| 종합상황 | 급상승이 후보를 만드는 핵심 징후다. 큐 행 최초 징후 칸에 "관로수위 30분 +0.4m" |
| 사건 화면 | 계측 추이 패널의 주인공. 최근 6시간 그래프, 발령 기준선, 추세 요약(30분 변화량·초과 기준·다음 기준까지). 행마다 "사건에 연결된 이유"와 관측·수신 시각. 급상승은 근거 목록에 "관로수위 30분 +0.4m · 변화율 기준 초과"로 따로. 타임라인에는 급상승 판정 시각이 후보 생성 직전 눈금 |
| 디지털트윈 | 지금 상태. 관로 여유와 침수 시작 판단에 쓰인다. 현재 상태 칸에 값과 추세 |
| 대응 | 위험도 4축의 추세와 위험 요인 "관로 상승"에 인용 |
| 모의훈련 | 시나리오 조건이 시계열을 대신한다. 담당자가 바꾸는 값은 아니다 |
| 데모 값 | 합성 시계열. 예측강우 상향 뒤 실측강우가 늘고 그 뒤 관로수위가 오른다. 반복 알람은 하나로 묶고 횟수만 적는다. 지연·결측을 하나 넣어 D2 "의심·지연 데이터 경고"가 서게 한다 |
| Phase 1 자산 | 계측 추이 패널이 그래프·기준선·추세 요약을 다 갖고 있다. 없는 건 급상승을 이벤트로 따로 세우는 것과 "연결된 이유" 한 줄 |

## E5 도로수위 (관측 · 기준 진입)

| 항목 | 내용 |
|---|---|
| 무엇인가 | 도로수위계 값(관측)과, 정한 기준에 들어갔다는 판정(기준 진입) |
| 종합상황 | 큐 행 근거 종류에 "도로수위 기준 진입". 관로 급상승과 같은 구역·시간에 나타나면 "여러 센서가 함께 움직임"으로 후보 조건이 된다 |
| 사건 화면 | 계측 추이에서 관로수위와 같은 시간축에 나란히. D2 "관로 상승이 지표면 영향으로 이어지는가"의 근거. 기준 진입은 "도로수위 경계 기준 진입 HH:MM"으로 따로. 타임라인 눈금. 종료 후에는 하강·해제 시각이 D8 눈금 |
| 디지털트윈 | 지금 상태이자 나중의 실제값. 사건 중에는 지표면 영향 확인, 종료 후에는 예측 침수심과 비교하는 실제값 |
| 대응 | 위험 요인과 완화 요인 양쪽에 인용. D3 완화 요인 "아직 낮은 도로수위" |
| 모의훈련 | 시나리오 조건 |
| 데모 값 | 합성 시계열. 관로수위가 오른 뒤 시간차를 두고 따라 오른다. 시간차를 0으로 두지 않는다. D2에서는 일부 지점만 기준을 넘는다. D8에서 하강·해제까지 만든다. 예측판 유효 시각과 같은 시각의 값을 두어 예측 대 실제 비교가 되게 한다 |
| Phase 1 자산 | 계측 추이 패널 공용. "위험" 접미 표시명 규칙은 처리상태 8종이 대신하므로 없앤다 |

## E6 펌프·저류시설

| 항목 | 내용 |
|---|---|
| 무엇인가 | 배수펌프장 가동 대수·가용성과 저류시설 여유의 변화. 시설물 시스템이 보내는 운영 상태 |
| 종합상황 | 큐 행에는 직접 안 선다. 공간 개요의 "데이터 장애 위치"와 데이터 상태 패널에 시설 상태 |
| 사건 화면 | 현재 상태 칸에 펌프 가용성과 저류 여유. 근거 목록에는 **악화 조건**으로 "배수펌프장 가용 2/3대 · 17:10 정지". 별도 사건이 아니라 이 사건의 조건이다. 타임라인에 상태 변경 눈금 |
| 디지털트윈 | 배수 여유가 침수 모형에 들어간다. **대안 축**이다. "배수 대응" 대안은 펌프를 회복시켜 다시 계산한 것 |
| 대응 | D6 시설 점검·운영 요청이 여기서 나온다. 요청·승인·결과 확인까지. 실제 원격제어는 하지 않는다. Phase 1 봉암 트랙의 "배수펌프장 확인" 항목이 그 자리 |
| G 파생 | 펌프 고장이 별도 담당 조직·조치·처리상태를 가져야 할 때만 기반시설 장애 사건으로 갈라지고 관계선이 그어진다. 데모에서 이 순간을 한 장면으로 보인다 |
| 모의훈련 | 훈련에서 담당자가 바꿔 보는 핵심 값. "펌프 고장 심화" 시나리오는 이 값을 낮춘 것, 배수 대응은 회복시킨 것 |
| 데모 값 | 합성. 펌프 3대 중 1대가 사건 전부터 정지(악화 조건). 저류시설 하나에 여유 값 하나. 배수 대응 대안은 정지 펌프 회복으로 침수심 0.6배, 도달 +20분, 지속 0.7배(예시 계수). G 파생 장면용으로 침수 뒤 남은 펌프가 하나 더 멈추는 이벤트를 D7 뒤 D8 전에 둔다. 시설 요청 결과는 "확인대기 → 성공"과 "미응답 → 대체조치" 하나씩 |
| Phase 1 자산 | 조기경보 지도의 방재시설 마커(배수문·배수펌프장), 교차검증 패널의 배수문 폐쇄·펌프 가동 행, 봉암 트랙의 배수펌프장 CCTV 컷과 SOP 항목. 시설 상태를 이벤트로 받는 구조는 새로 세운다 |
