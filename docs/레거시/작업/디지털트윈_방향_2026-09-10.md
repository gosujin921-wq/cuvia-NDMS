# 디지털트윈 방향 초안

> 상태: 방향 논의 초안. 정본 인용 금지. 결정이 끝나면 IA·02·03·01·README에 반영하고 이 파일은 지운다.
>
> 작성: 2026-09-10. Phase 1 디지털트윈 화면(SCR-05)과, 사건 화면에서 트윈 화면으로 이동하는 방식이
> 어색하다는 문제에서 시작했다. 결론은 다음과 같다. 디지털트윈은 따로 이동하는 화면이 아니다. 담당자가 보고
> 있는 지도를 미래 시점으로 바꿔서 보여주는 **디지털트윈 화면**이다. 사건이 진행 중일 때는 사건 화면 안에서
> 예측 이벤트를 눌러 열고, 사건이 없을 때는 모의훈련 메뉴에서 시나리오를 골라 연다. 두 경우 모두 같은
> 디지털트윈을 쓴다.
>
> 근거: 요약설명자료 v0.2 2장 4단계·8단계와 3장 비교표, REV 1.0 p.19, 01 §6·§8, 03 §4·§6, IA §8·§13,
> 02 D0·D3~D5·§5.5, Phase 1 코드 인벤토리(2026-09-10 22시). 레거시 문서는 근거로 쓰지 않고 참고만 했다.
> 무엇을 가져오고 무엇을 버렸는지는 §8에 있다.

## 1. 디지털트윈은 무엇인가

디지털트윈은 두 가지로 이루어진다. 현재 관측값에서 출발한 앞으로의 상태를 담은 **예측 결과**와, 그 결과를 지금
보고 있는 지도 위에 그려 현재 사건 상태와 비교하게 하는 **디지털트윈 화면**이다. 예측 결과는 CUVIA 계산일 수도,
외부 모델 수신일 수도 있고, 데모에서는 합성 예측면(계산 주체 `해당 없음`)이다(03 §2, 01 §11). 담당자가 다른
화면으로 이동하는 것이 아니라, 보고 있던 지도의 시점이 미래로 바뀐다.

- 시뮬레이션과 다른 점. 시뮬레이션은 "수위가 4.2m가 되면 어디가 잠기는가"처럼 사람이 정한 숫자에서
  출발한다. 디지털트윈은 "지금 수위가 3.4m다. 이 조건이 유지되면 40분 뒤 4.2m가 된다. 그때 어디가
  잠기는가"처럼 현재 관측값에서 출발한다. **사용자는 결과값인 수위·침수심을 직접 조작하지 않는다. 시간과
  지원되는 대안 조건을 고르고, 수위·침수심은 그 결과로 표시된다.**
- 미래를 보는 이유. 대응에는 시간이 걸린다. 판단하고, 승인받고, 전파하고, 주민이 이동하는 데 시간이 든다.
  그래서 화면은 예측 시각과 함께 **지금부터 남은 시간**을 표시한다.
- 전망은 두 가지를 나란히 보여준다. **기준 전망**은 지금 조건이 그대로 유지될 때의 결과이고, **대안 전망**은
  조건을 바꿨을 때의 결과다.

디지털트윈 화면의 구성 요소는 다섯 개다. 사건 화면에서 열든 모의훈련에서 열든 같은 구성 요소를 사용한다.
같은 기능을 두 벌 만들지 않는다.

| 구성 요소 | 하는 일 | Phase 1 자산 |
|---|---|---|
| 3D 지도 | 지도가 3D로 전환되고, 지형과 건물 위에 시간대별 침수심과 영향 대상(도로·건물·대상자)이 표시된다 | flood-scene 유지. 수면 하나를 올리던 방식을 배수권역 단위 침수심으로 바꾸고 영향 대상 표시를 추가 |
| 시간 조절 | 예측 시각을 옮긴다. 눈금은 예측판의 유효 시각이고 남은 시간을 함께 표시한다 | TimelinePanel 유지 |
| 대안 선택 | 그대로 / 도로 통제 / 배수 대응 중 하나를 고른다 | 신설 |
| 영향 결과 | 기준 전망과 대안 전망을 두 열로 비교한다. 침수심·범위·건물·통제 도로·대상자 | ImpactResultCard 유지. 열 제목만 바뀐다 |
| 근거·한계 | 사용한 모델·버전·입력·기준시각·품질·가정을 보여준다 | AnalysisBasisCard에 항목 추가 |

**3D는 유지한다.** 같은 지도를 3D로 전환하는 것이므로 어느 경로로 열어도 3D를 잃지 않는다.

시간 조절에는 Phase 1의 규칙 둘을 그대로 적용한다. 첫째, 시연 시각 이후에 실제로 일어난 일은 눈금에
넣지 않는다. 결과를 미리 알고 판단하는 화면이 되면 "계측이 기준에 닿기 전에 결정했다"는 메시지가
무너진다. 둘째, 판단에 쓰는 값은 눈금값이고, 눈금 사이의 값은 "사용자가 고른 시각"으로 구분해 표시한다.

## 2. 디지털트윈 화면을 여는 두 가지 경우

| | 사건이 진행 중일 때 | 사건이 없을 때 (모의훈련) |
|---|---|---|
| 무엇을 눌러 여는가 | 사건 화면의 **예측 이벤트**(E8 침수예측판 갱신) | 모의훈련 메뉴의 **훈련 시나리오** |
| 어디에 열리는가 | 사건 화면의 지도가 그 자리에서 3D 디지털트윈 화면으로 바뀐다 | 사이드바 [대응 모의훈련] → 시나리오 목록 → 트윈 페이지(Phase 1 SCR-05) |
| 기준 조건 | 현재 관측값 | 시나리오가 정한 조건 |
| 결과가 어디로 가는가 | 사건의 권고·SOP·전파문에 반영된다. [이 전망으로 대응 검토] 버튼 | 훈련 이력에만 기록된다. 사건 기록에는 들어가지 않는다 |
| 기능 이름 | 디지털트윈 | 디지털트윈 모의훈련(사전 조건분석) |
| 화면 제목 | 사건 헤더 그대로 | "대응 모의훈련 · 시나리오명" |

두 경우 모두 시간 조절·대안 선택·영향 결과·근거 카드를 같이 쓴다. 다른 것은 어디서 열었는지와 결과가
어디로 가는지뿐이다.

### 2.1 사건이 진행 중일 때: 예측은 이벤트다

예측 결과는 별도 화면에서 보는 것이 아니라, 관로수위나 CCTV 분석처럼 **이벤트 하나로 사건에 들어온다.**
문서도 이미 그렇게 정해져 있다. E8 침수예측판 갱신이 이벤트이고, 01은 예측판을 사건의 `forecasts[]`
필드에 연결한다. 화면에서는 다음과 같이 보인다.

| 화면 자리 | 무엇이 보이는가 |
|---|---|
| 종합상황의 사건 우선 큐 | 후보 행에 "예측: 40분 뒤 남측 침수 예상"이 한 줄 추가된다 |
| 사건 화면의 근거 목록 | "17:20 침수예측판 · 18:00 남측 침수심 0.3m · 도로 2 · 대상자 120명"이 관측·영상과 같은 줄에 선다. 예측판이 갱신되면 같은 자리에 새 줄이 쌓인다 |
| 사건 타임라인 | 과거 눈금만이 아니라 **미래 눈금**(예측 유효 시각)이 표시된다. "예측이 먼저 움직였다"를 가장 적은 비용으로 보여주는 장면이다 |
| 예측 줄을 누르면 | 사건 화면의 지도가 그 시각의 3D 디지털트윈 화면으로 바뀌고 다섯 구성 요소가 지도 위에 표시된다. 다른 화면으로 이동하지 않는다 |
| 다음 행동 | 돌아갈 화면이 없다. [이 전망으로 대응 검토] 버튼이 선택한 시각과 대안을 가지고 대응 팝업을 연다. 권고 카드에 "18:00 전망 · 도로 통제 기준"이 표시된다 |

- 긴급할 때는 예측을 열지 않고 바로 승인할 수 있다. 디지털트윈 화면은 권장 단계이지 필수 단계가 아니다.
- Phase 1의 [디지털트윈으로 확인하기] 버튼과 "검토 완료" 표시는 없어진다. 담당자가 선택한 전망을 기록하는
  것으로 대신한다.
- 예측이 사건 후보의 근거가 된다. 01 §7.1에 반영 완료(2026-09-11). 갱신 사실만으로는 후보를 만들지 않고
  영향 기준을 넘은 예측 결과만 근거가 된다. 후보는 담당자가 확인해야 사건이 되므로, 확인 전 자동화를 제한하는
  원칙은 그대로다.

### 2.2 사건이 없을 때: 모의훈련은 같은 디지털트윈을 사건 없이 쓴다

모의훈련은 비교표에서 경쟁 5사가 모두 X이고 CUVIA만 ◎인 항목이다. 사이드바 메뉴로 올린다. Phase 1 트윈
페이지를 이 메뉴의 실행 화면으로 쓴다. 사건 화면에서 트윈 페이지로 이동하는 경로가 없어졌으므로, 그
페이지는 여기서 쓴다.

| 화면 | 보이는 정보 |
|---|---|
| 시나리오 목록 | 시나리오명 · 원천 사건 · 바뀐 조건 한 줄 · 훈련 목표 한 줄 · 마지막 실행(일시·소요시간·결과 한 줄) |
| 실행 | 트윈 페이지가 사전 조건분석 상태로 열린다. 지구·유형·조건이 시나리오대로 채워져 있다. 제목은 "대응 모의훈련 · 시나리오명" |
| 훈련 대응 | [이 전망으로 대응 검토] → 대응 팝업이 훈련 상태로 열린다. SOP 선택·전파문 작성·승인을 연습한다. 실제 전파는 나가지 않는다 |
| 이력 | 실행일 · 참여자 · 선택한 대응 · 소요시간. 사건 ID를 갖지 않는다 |

- 시나리오는 **대표 사건의 조건을 바꾼 세 건**이다. 원래 조건 그대로 / 펌프 고장이 더 심한 경우 / 만조가
  겹치는 경우. 새 데이터를 만들지 않는다. "대응 이력으로 시나리오를 만든다"는 원본 문구가 그대로 보이고,
  디지털트윈의 대안 축(E6 펌프, 조위)을 훈련에서도 같은 구성 요소로 쓴다. IA-05 D8의 "훈련 시나리오 후보
  만들기" 카드는 이 메뉴로 연결된다.
- 훈련 목표는 셋 중 하나다. 선제 통제 결정, 배수 요청, 전파 문안. 난이도·담당 조직·참여자·예약은 P1
  SOP·승인 확인이 끝난 뒤에 정한다.
- 훈련에서 나온 숫자가 실제 사건 근거와 같은 자리에 표시되면 통계가 오염된다. Phase 1 사전 모의분석이
  지키던 규칙대로 훈련 이력은 사건 기록과 분리한다.
- 만들지 않는 것: 시나리오 편집기, 과거 이력 기반 자동 생성, 예약, 의사결정 분기 실행. 목록과 실행까지만
  만든다. 새로 만드는 화면은 목록 하나다.
- 이름은 README §8.3을 따른다. 메뉴는 `대응 모의훈련`, 디지털트윈 화면 안에서 조건을 바꾸는 기능은
  `사전 조건분석`. Phase 1 코드의 "drill · 사전 모의분석"은 `사전 조건분석`으로 바꾼다.

## 3. 디지털트윈 화면이 바꾸는 것과 바꾸지 않는 것

| 디지털트윈 화면이 채우는 것 | 디지털트윈 화면이 바꾸지 않는 것 |
|---|---|
| 담당자가 선택한 예측판과 유효 시각 | 실제 계측값과 계측 단계 |
| 영향 범위·대상자·통제 도로·시설 | 사건 처리상태 |
| 권고의 근거와 반대 근거 | 승인된 대응수준 |
| SOP 초안의 대상·구간·문안 | 전파·통제의 실제 실행 여부 |
| 사용한 자료·모델·가정 | 도시 대응단계 |

관측이 경보 3.4m이고 전망이 대피 기준을 넘더라도, 지도 핀과 계측 단계는 경보 그대로다. 디지털트윈 화면은
"선제 대응 권고의 근거"를 덧붙일 뿐이다.

## 4. 계산과 근거: 이벤트마다 디지털트윈이 무엇을 받고 무엇을 내는가

정본의 재료를 연결한 표다. 이벤트는 02 §5.1, 트윈 계약은 03 §6 A, 이벤트 유형은 01 §6에서 가져왔고 새 값은
만들지 않았다. 사건에서 열 때와 모의훈련에서 열 때 계산은 같고, 이벤트의 **출처만** 다르다.

### 4.1 계산 흐름

```text
[경계조건]  E1 예측강우 · E2 특보 · E3a 예측조위      → 앞으로의 조건
[관측]      E0 실측강우 · E3b 실측조위 · E4a 관로수위 · E5a 도로수위 → 지금 상태
[시설]      E6a 펌프 가용성 · E6b 저류 여유              → 배수 여유
        ↓  침수 모형 (계산 주체는 CUVIA가 방향. 데모는 합성 예측면)
[예측판]    E8 침수예측판 = 유효 시각별 침수심 면 + 도달시간
        ↓  영향 계산 (도로·건물·대상자 기준 데이터와 겹침. Phase 1 영향 데이터로 가능)
[영향]      영향 도로·건물·시설·대상자, 최초 침수 예상시각, 최대 침수심, 지속시간
        ↓  대안 (E6 조건을 바꾸거나 통제 시점을 넣어 다시 계산)
[비교]      기준 전망 대 대안 전망
        ↓  검증 (사건 종료 후)
[실제]      E5a 도로수위 · E7 영상 · E9 현장 결과와 예측판 비교
```

### 4.2 이벤트별 역할

| 이벤트 | 디지털트윈에서의 역할 | 계산에 주는 것 | 화면에 근거로 보이는 것 | 사건에서 열 때 출처 | 훈련에서 열 때 출처 |
|---|---|---|---|---|---|
| E0 실측강우 | 관측 | 현재 유입량 | 현재 상태 칸의 강우와 추세 | 창원 계측(미확보, 합성) | 시나리오 조건 |
| E1 예측강우 | 경계조건 | 앞으로의 유입량 | 근거 카드 "예측강우 N mm/h, 기준시각" | Open-Meteo 재생 | 시나리오 조건 |

  기능이 두 벌 생기지 않는다.

  통제"는 침수는 같고 노출만 줄여 다시 계산한 것이다. 03 §6 A의 대안 조건(펌프 가용성, 배수·저류 조건, 통제
  시점)과 같다.

### 4.4 대안 셋의 값

| 대안 | 침수 | 영향 | 값의 출처 |
|---|---|---|---|
| 그대로 | 기준 전망 | 기준 영향 | 합성 예측면 |
| 도로 통제 | 기준과 같음 | 통제 도로만큼 노출 감소, 대상자 감소 | Phase 1 영향 데이터로 가능 |
| 배수 대응 | 침수심·지속시간 감소 | 그에 따라 감소 | 기준 예측면에 계수를 곱한 합성 예측면(아래) |

**배수 대응의 값 규칙.** 수리 모형이 없으므로 물리량을 계산하는 것처럼 꾸미지 않는다. 인과 관계만 적고
값은 시나리오 편집값으로 둔다.

- 인과: 펌프 가용성이 회복되면 배수 여유가 늘어 수위 상승률이 준다. 그래서 최대 침수심이 낮아지고, 도달
  시각이 늦어지고, 지속시간이 짧아진다.
- 규칙: 대안 예측면은 기준 예측면에 계수 셋을 적용해 만든다. **침수심 배율**(예 0.6), **도달시간 지연**(예
  +20분), **지속시간 배율**(예 0.7). 펌프 회복 시점 이후 구간에만 적용한다.
- 계수는 02 §5.5의 상대 시각과 같은 시나리오 편집값이며 모델 성능이 아니다. 실제 모델 결과를 받으면
  계수를 버리고 예측판을 교체한다.
- 도로 통제는 침수면이 같고 통제 도로에 있는 대상자·차량만 제외하므로 계수가 필요 없다.

### 4.5 유형이 바뀌면 디지털트윈 화면에서 무엇이 바뀌는가

§4.1~§4.4는 A 도시 배수·침수 하나만 다룬다. 유형은 03 §5의 A~G 유형군이다. 데모에서 시간 조절·대안 선택이
동작하는 모의 예측 화면을 갖는 유형은 A·C이고(둘 다 합성 예측면, 계산 주체 `해당 없음`), D·F는 정지된 개념
예시다. 자산이 있다는 것과 계산 능력은 다르므로 어느 유형도 "계산한다"고 쓰지 않는다. 03 §5가 정한 대로 유형이 바뀌어도
**디지털트윈 화면의 구성 요소 다섯은 같고, 상태 변수·시간축·공간 표현·대안 축·핵심 결과만 바뀐다.** 아래는
03 §6·§8·§9·§11 표에서 그 다섯 행을 뽑아 A와 나란히 놓은 것이다.

| | A 도시 배수·침수 | C 해안 경계·월류 | D 이동 전선·확산 | F 지반·구조 영향 |
|---|---|---|---|---|
| 데모 역할 | 대표 데모. 합성 예측면의 모의 예측 화면 | 비교 설계 R1. 계약·미확보 조건과 합성 예측면의 모의 예측 화면 | 비교 개념 R0. 정지된 개념 예시 | 비교 개념 R0. 정지된 개념 예시 |
| 상태 변수 | 관로·도로수위·침수심이 배수망을 따라 변한다 | 조위·파랑·월류량이 해안 경계를 넘어 저지대로 들어온다 | 화선·농도가 바람·지형을 따라 한 방향으로 이동한다 | 진동·변위·경사가 시설 손상·사면 불안정으로 이어진다 |
| 시간축 | 분 단위, 10·30·60분 | 만조 전후 | 분·시간별 전선 이동 | 직후 즉시 평가 또는 누적·급변 감시 |
| 공간 표현 | 배수권역·관로·도로·건물별 침수심 면 | 해안선·방호시설·월류 지점·저지대 침수면 | 이동 전선 또는 연기·농도 띠, 풍하측 영향권, 대피경로 | 영향권, 시설별 상태, 사면 변위 벡터, 출입 구역 |
| 대안 축 | 펌프 가용성·저류, 통제 시점 | 수문·방호시설, 해안도로 통제·대피 시점 | 차단선·진압자원, 풍향 변화, 대피 방향 | 출입통제 범위, 우회, 점검·보강 우선순위 |
| 핵심 결과 | 최초 침수시각, 최대 침수심, 지속시간, 영향 도로·건물·대상자 | 월류 시작시각·구간, 침수 범위·지속, 배수 제약 | 도달시간, 영향권, 농도, 안전·비안전 경로 | 손상·붕괴 가능성, 추가 변위, 사용·통행 가능성 |
| 예측 이벤트 | E8 침수예측판 | 해일·월류 예측판 | 확산 예측판 | 즉시 평가 결과 |
| Phase 1 자산 | 봉암 내수침수 트랙 | 서항 폭풍해일 트랙, 조위 4칸 비교 | 없음. 바람 격자만 있음 | 주남저수지 지반변위 원장 1건. 화면 없음 |

- **사건 화면에서 여는 방식은 유형과 관계없이 같다.** 어느 유형이든 예측 이벤트가 근거 목록에 서고, 누르면
  지도가 미래 시점으로 바뀐다. C는 Phase 1 서항 자산의 합성 예측면으로 같은 모의 예측 화면을 보여준다(§7 채택
  1번). 준비도는 R1이므로 계약·미확보 조건을 근거 카드에 함께 표시하고 모델 결과로 말하지 않는다. D·F는 누르면
  지도 대신 정지된 개념 카드가 열린다(README §8.2).
- **모의훈련은 A가 확정이고 C는 결정 대기다.** 훈련 시나리오는 대표 사건의 대응 이력에서 만드는데(02 §11), C는
  Phase 2 대표 사건과 대응 이력이 없고 해안통제·대피 기준(03 §8 확인 조건)도 미확인이다. §4.7의 C 훈련 표는 후보다.
  <!-- 결정 대기: C 모의훈련 포함 여부. 포함하면 C용 SOP·전파 문안이 필요하고 03 §16 "전체 업무 흐름 복제 안 함"과 대조해야 한다 -->
- **집중호우·태풍은 유형이 아니다.** 03 §13대로 기상 조건이며 A·B·C·F·G의 경계조건(E1·E2)으로 들어온다.
  Phase 1이 "집중호우"를 유형으로 둔 것은 여기서 정리된다.
- **E 열돔·G 기반시설 장애**는 디지털트윈 화면이 없다. E는 장기 후보이며 Phase 1 지구본은 제외한다. G는 대표
  사건 안에서 펌프 장애가 악화·파생 관계로 보이는 것으로 충분하다.

Phase 1 유형 여섯과의 대응: 내수침수→A, 폭풍해일→C, 하천범람→B(확장 설계, 화면 없음), 지반변위→F,
열돔→E, 집중호우→유형 아님(기상 조건).

### 4.6 D 개념 카드를 산불로 채우는 방법

D는 R0이므로 계산 화면처럼 만들지 않는다. 카드 한 장으로 "무엇을 넣으면 무엇이 나오는지, 지금 무엇이
없는지"를 설명한다. 정리 순서는 A와 같다. 근거를 확인하고, 03 §9 표를 사례로 채우고, 카드 내용으로 옮긴다.

**대표 사례는 산불이다.** 03 §13이 D의 첫 항목으로 두고 있고, 창원에 산지가 있으며, 산림청과 지자체가 함께
대응하는 자연재난이라 CUVIA의 포지셔닝에 맞는다.

**근거와 데이터 상태**

| 무엇 | 어디서 | 상태 | 카드에서의 역할 |
|---|---|---|---|
| 바람(풍향·풍속) | Open-Meteo 격자. Phase 1 `public/weather/wind-field.json` | 있음 | 화선이 퍼지는 방향. 실제 값으로 그릴 수 있는 유일한 입력 |
| 습도·기온 | Open-Meteo | 기온 있음, 습도는 같은 API | 확산 속도 조건 |
| 지형·경사 | MapTiler 지형 | 있음 | 오르막에서 빨리 번진다는 근거 |
| 임상도(산림 분포·연료) | 산림청 | 확인 필요 | 연료 조건. 없으면 "필요한 입력"으로 표시 |
| 산불위험예보 | 산림청 국가산불위험예보시스템 | 확인 필요 | D0 감시 우선대상의 근거가 될 수 있음 |
| 확산 예측 모델 | 국립산림과학원 산불확산예측 | 확인 필요. CUVIA 계산 아님 | 계산 주체 `외부 모델 수신`. 카드에 "이 모델의 결과를 받아 표현한다"고 적는다 |
| 산불 발생 이력 | 생활안전지도 | 확인 필요 | 카드 밖. 감시 우선순위 근거 |

**03 §9 표를 산불로 채운 것**

| 항목 | 산불 |
|---|---|
| 상태 변수 | 화선이 바람·경사·연료를 따라 한 방향으로 이동한다 |
| 주요 입력 | 발화 위치, 풍향·풍속, 습도, 지형·경사, 임상, 진화 자원 위치, CCTV·열영상 |
| 시간축 | 분·시간별 전선 이동. 눈금은 확산 범위가 마을·도로에 닿는 시각 |

### 4.7 유형별로 사건 화면에서 보여줄 것과 모의훈련에서 할 수 있는 것

§4.5의 유형 표를 사건 화면과 모의훈련으로 나누어 다시 쓴 것이다. 사건 화면에서는 예측 이벤트가 어떻게
보이고 누르면 무엇이 켜지는지, 모의훈련에서는 어떤 시나리오로 무엇을 연습하는지를 적었다. 전제는 둘이다.
A·C 모두 합성 예측면으로 시간 조절·대안 선택이 동작하는 모의 예측 화면을 갖는다(§7 채택 1번, 계산 주체
`해당 없음`). D·F는 정지 카드이므로 훈련이 없다. C 훈련은 §4.5대로 결정 대기다.

## 5. IA에서 바뀌는 것

- **IA-03 트윈 비교는 독립 업무 공간이 아니라 사건 작업공간의 예측 모드**가 된다. 업무 공간은 넷이 되고,
  디지털트윈이 그 안에 들어간다. README §8.2의 7-2 결정(트윈 독립 페이지)은 바뀐다.
- **대응 모의훈련이 사이드바 메뉴**가 된다. IA-A01 운영 관리와 별도다. Phase 1 트윈 페이지를 실행 화면으로
  쓴다.
- IA-05 D8의 훈련 진입 카드는 이 메뉴로 가는 링크가 된다.
- 문서가 열어 두었던 "IA-03~05를 독립 페이지로 갈지 집중 모드로 열지"의 답은 IA-03만 바뀐다. IA-04 팝업,
  IA-05 독립 페이지는 그대로다.

## 7. 무엇이 쉬워지고 무엇을 잃는가

쉬워지는 것. 사건 화면에서 다른 페이지로 이동하는 전환이 없다. 예측은 합성 이벤트를 원장에 적으면 되고,
목록과 타임라인은 이미 있다. 디지털트윈 화면 구성 요소 다섯 중 넷이 Phase 1에 있다. Phase 1 트윈 페이지는
버리지 않고 훈련 실행 화면으로 쓴다.

추가 고도화 둘(2026-09-10 사용자 결정으로 채택, 정본 반영 완료).

1. **C도 합성 예측면의 모의 예측 화면을 갖는다.** Phase 1 서항 자산이 있어 비용이 낮다. A와 C 두 유형이 같은
   화면에서 다르게 움직이는 것이 "유형별 트윈"의 증명이 된다. 준비도는 R1 그대로, 계산 주체는 `해당 없음`이다.
   자산이 있다는 것과 계산 능력은 다르므로 "계산한다"고 쓰지 않는다(01 §11, 03 §15 R1). README §8.2·03
   §8·§16·§18·IA §8에 이 표현으로 반영했다(2026-09-11).
2. **G 파생을 장면으로 만든다.** 펌프 장애가 독립 고장 기준을 넘는 순간 별도 사건으로 분리되고 관계선이
   그어진다. 사건 관계 표시 하나로 "복합재난"이 화면에 보인다.

잃는 것. "디지털트윈"이라는 메뉴 이름이 없어진다. 비교표의 "디지털트윈·3D 시각화"를 보여줄 자리가 사건
지도의 3D 전환과 모의훈련 페이지 두 곳으로 나뉜다. 시연 대본에서 "지금 보시는 것이 디지털트윈입니다"를
사건 지도가 3D로 바뀌는 순간에 말해야 한다.

## 10. 남은 것

핵심 방향 결정은 끝났다. 배수 대응 값 규칙은 §4.4, 모의훈련 목록은 §2.2에 있다. 결정 대기는 하나다. C 모의훈련
포함 여부(§4.5).

디자인 단계로 넘기는 것: 사건 지도 위에 시간 조절과 대안 선택을 놓을 자리. 이벤트 상세 구조가 바뀔 수
있으므로 화면 배치를 잡을 때 정한다. 방향에는 영향이 없다.
