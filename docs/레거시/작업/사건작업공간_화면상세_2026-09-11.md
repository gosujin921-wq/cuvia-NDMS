## 0. 왜 판단 국면이 먼저인가, 언제 팝업인가

다른 CUVIA(KISA·CSMS)는 이벤트가 카메라 한 장면이라 판단이 얇다. 접수 뒤 바로 SOP로 간다. 재난안전은 판단이 곧 대응의
입력이라 국면이 둘이다.

- 사건이 이벤트 하나가 아니다. 관로·도로수위·조위·펌프·영상·예측판이 시간을 두고 들어와 하나로 묶이고, 같은 사건인지 사람이
  확인한다.
- 아직 안 벌어진 일에 대응한다. 어디까지·언제·얼마나 잠기는지가 전망에서 나오고 그 전망이 권고를 정한다.
- 대응의 무게가 다르다. 도로 통제·주민 전파·시설 요청은 외부로 나가고 되돌리기 어렵다. 사건 확인 전 자동화는 내부로
  제한하고 외부 전파·시설 요청은 승인 뒤다(README §8.1).
- 범위가 유동적이다. 지점·구역·전역 중 어느 범위로 대응할지가 판단이다.
- 특보와 사건 위험도는 다른 축이다.

그릇은 레거시 정본 03 §0-9 규칙 그대로다.

| 하는 일 | 그릇 | 이유 |
|---|---|---|
| 사건을 확인·판단한다 | 사건 작업공간 지도 + 우측 레일 | 판단 근거(지도·CCTV·계측)와 판정이 같은 프레임에 보여야 한다 |
| 전망을 비교한다 | 같은 지도가 예측 화면으로 | 현재와 미래를 같은 공간에서 가른다 |
| 승인·실행한다 (SOP · 전파 · 시설 요청) | 대응 실행 집중 팝업 | 조작 밀도가 가장 높다. 340px 레일의 체크박스는 시연장에서 읽히지 않는다. 활성 조작면은 하나 |
| 실행 결과를 확인한다 | 우측 레일 · 이력 | 결과는 무대로 돌아와 지도·타임라인과 함께 읽는다 |
| 종료 사건을 열람·검증한다 | 기록·검증 화면 | 표는 원장이지 무대가 아니다 |

판단이 대응을 늦추지 않는다. 내부 자동 조치는 후보 생성 순간 이미 돌고, 긴급 시 판단·전망을 건너뛰고 바로 대응 팝업을
열 수 있다(§3 긴급 경로).

참조가 공유하는 규칙 (종합상황 초안 §1과 같고, 이 화면에 더 붙는 것만 적는다)

- 판단은 레일, 실행은 집중 팝업. 팝업이 열린 동안 활성 조작면은 팝업 하나이고 레일의 같은 조작은 요약·비활성으로 눕는다
- 진입 경로가 달라도 실행 화면은 하나다. 레일 `[대응 실행]`, 지도 마커 `[이 사건 대응하기]`, 전망 `[이 전망으로 대응 검토]`가 같은 팝업을 연다
- 팝업은 별도 상태를 만들지 않는다. 닫으면 결과가 레일과 이력에 그대로 이어진다
- 우측 레일의 모드 전환은 패널 탭(`Tabs variant="panel"`). 카드 헤더 행은 위험도 배지 왼쪽, 처리상태 오른쪽 끝. 처리상태에 독자 색을 주지 않는다
- 선택은 핸들러 하나가 한다. 목록 행 클릭 = 지도 강조 + 팝업 + 관련 목록 스크롤. 재클릭 해제, Esc는 팝업 → 선택 → 상위 순으로 물러난다
- 이력은 `<ol>` 세로형. 실패 줄만 danger 점. 확인창 버튼은 행위 동사. 값이 없으면 `-`
- SOP는 두 축을 동시에 읽힌다. `우선순위(MUST · SHOULD · MAY)`와 `실행방식(자동 · 수동)`. 상태는 `대기 · 진행 중 · 완료 · 실패` 네 값. 자동은 먼저 끝나 있고 수동은 사람이 누른다

팝업 규칙 (레거시 정본 03 §0-9 · §2, 차수 N 수용 기준을 그대로 잇는다)

- 진입로 셋이 같은 팝업이다. 레일 `[대응 실행]`, 지도 마커 `[이 사건 대응하기]`, 전망 `[이 전망으로 대응 검토]`(선택 시각·대안을 권고 기준으로 실어 보낸다)
- 열린 동안 레일의 같은 조작은 요약·비활성. 승인·체크·실행은 팝업에서만
- 실행 중(승인 확인창 → 결과 도착 사이)에는 닫기 잠금. ESC·배경 클릭 정책은 관제 팝업 원본과 같다. 닫히면 연 버튼으로 포커스 복귀
- 닫으면 결과가 레일 `대응 요약`과 이력에 이어진다. 팝업은 별도 상태를 만들지 않는다
- 긴급 경로: 확인됨이면 판단 갱신·전망 없이도 연다. 권고 카드는 `전망 기준 없음 · 긴급 대응`을 적고 SOP 항목은 권고 기본안으로 선다

### SOP 항목과 자동 대응 시점

항목은 권고가 만든다. 내부 자동은 후보 생성 순간 완료이고 밖으로 나가는 것은 자동이라도 승인 뒤 돈다(README §8.1 승인 경계).
문안은 데모 예시이며 운영 SOP 확정값이 아니다.

| 우선순위 | 실행 | 항목 | 담당 · 단계 | 시점 |
|---|---|---|---|---|
| MUST | 자동 | 사건 CCTV 집중 배치 | 시스템 | 후보 생성 17:14 완료 |
| MUST | 자동 | 담당기관 통보 · 교통과 · 하수과 · 안전총괄과 | 시스템 · 담당기관 | 승인 17:46 완료. 수신자별 성공·실패 |
| MUST | 자동 | 주민 전파 · CAP 문안 · 알림톡 · 마을방송 · 전광판 · 기관 통보 | 시스템 · 주민 전파 | 한 항목. 전파문 확인 뒤 실행. 채널 결과는 줄 아래. 마을방송 실패 → `[대체조치]` 유선 연락 |
| MUST | 수동 | 해안도로 저지대 구간 통제 | 교통과 · 현장 조치 | 승인 → 진행 중 → 현장 결과로 완료 18:06 |
| MUST | 수동 | 제2배수펌프장 2호기 점검·재가동 요청 | 하수과 · 현장 조치 | `가동 여부` 표시. 재가동 18:36 완료 |
| SHOULD | 수동 | 신포 지하차도 진입부 현장 확인 | 안전총괄과 · 현장 조치 | 완료 18:15. 완료 시 현장 보고(E9) 연결 |
| SHOULD | 자동 | 관련 CCTV 구성 · 배수관리용 폴 | 시스템 | 후보 생성 17:14 완료 |
| MAY | 자동 | 사건 영상·예측판 보존 | 시스템 | 후보 생성 17:14 완료 |

- 승인은 권고 단위다. `[전체 승인·실행]`과 `[부분 승인 n]`은 전파문 확인창을 한 번 거친 뒤 남은 수동 항목을 순서대로 실행한다. 첫 승인 시각·승인자가 `대응 승인` 결정으로 남고 처리상태가 `대응중`이 된다
- 실제 원격제어는 없다. 시설 항목은 `요청 · 승인 · 결과 확인`까지만 기록한다
- 수동 항목의 완료는 담당자가 결과를 보고 남기는 것이다. 현장 확인 항목은 줄이 펼쳐져 좌측 영상 컷 + 한 줄 메모로 완료한다. 통제·요청 항목은 기관 결과 도착으로 완료한다

### 화면 전환 시나리오

이동은 두 번뿐이다. 종합상황에서 사건 작업공간으로, 마지막에 기록·검증으로. 그 사이 판단·전망은 같은 지도 위에서 바뀌고
대응은 그 위에 팝업으로 떴다가 닫힌다.

1. 종합상황(지도). 17:13 복합 징후가 잡히면 `감지` 카드가 같은 자리에서 `후보 · 확인 필요` 사건 카드로 바뀌고 서항 이름표에 점 색·펄스가 붙는다. 내부 자동 조치 세 건은 이 순간 완료된다
2. 사건 작업공간(지도). 카드를 누르면 `/scr-02/seohang`. 지도가 사건 범위로 맞춰지고 좌측 근거, 우측 판단, 하단 카메라. `[검토 인수]` → `[사건 확인]`. 17:33 위험도 갱신
3. 디지털트윈(같은 지도). 예측 줄 `[디지털트윈 보기]` → 우측이 전망 탭, 지도에 침수 범위. 대안·유효 시각 선택
4. 대응 실행 팝업. `[이 전망으로 대응 검토]` → 팝업. 지도는 뒤에 흐리게. 사건 개요에서 권고 확인 → SOP 대응 탭에서 `[전체 승인·실행]` → 전파문 확인창 → `대응중`. 결과 도착 뒤 마을방송 실패 → `[대체조치]`, 잔여 조치 진행, `[통제로 전환]`
5. 사건 작업공간으로 복귀(지도). 팝업을 닫으면 레일 `대응 요약`과 이력에 결과가 이어져 있다. 캡슐 `통제`
6. 기록·검증(별도 화면). `[종료 검토]` → `/scr-04`. 예측 대 실측, 타임라인, 보고서 초안, `이 사건으로 훈련 시나리오 만들기`

긴급 경로: 2에서 확인됨이 되는 즉시 `[대응 실행]`이나 마커 `[이 사건 대응하기]`로 4로 갈 수 있다. 3은 건너뛴다.

## 6. 우측 레일 탭과 대응 진입

| 탭 · 버튼 | 표시 | 열리는 조건 | 바뀌는 것 |
|---|---|---|---|
| 판단 탭 | 처리상태 점 | 항상 | 지도는 현재 상태 |
| 전망 탭 | 유효 전망 수 (`전망 3`) | 유효 예측판이 있을 때. 없으면 잠기고 `유효한 전망 없음` | 같은 지도에 선택 유효시각 침수 범위 |
| `[대응 실행]` | 승인 뒤 `대응 실행 · 5/8` | 확인됨 이후 항상 (긴급 경로). 그 전에는 없다 | 집중 팝업이 뜬다. 지도·레일은 뒤에 흐리게 |

- 카드 안 버튼(`디지털트윈 보기` · `이 전망으로 대응 검토`)은 탭·팝업을 열고 맥락(전망 · 유효시각 · 대안)을 실어 보낸다
- 팝업을 닫으면 판단 탭으로 돌아오고 `대응 요약`이 갱신돼 있다

## 7. 근거 줄 해부와 선택

```
[종류 아이콘] 수위 · 10분간 관로수위 64 cm 상승 ──────────── 17:10
             서항 간선관로 수위계 · CUVIA 규칙 [확인 필요]
             ⟲ 복합 징후 알림 · 같은 배수권역 · 시간창 17:00~17:13     [디지털트윈 보기]
```

- 1행: 종류 라벨 + 요약, 오른쪽 끝 관측시각. 수신시각은 툴팁
- 2행: 위치 · 출처기관, 품질 태그, 확인 필요 태그
- 3행: 연결 이유. 예측 줄만 오른쪽에 `[디지털트윈 보기]`
- 미연결 줄은 흐림 처리, 3행이 `사건에 연결되지 않음 · 같은 지구`

선택 규칙

1. 줄 클릭 = 근거 선택 + 주체 지도 강조·이동 + 관측 카드 주체 전환 + 현장영상이면 도크 타일 강조
2. 지도 핀·팝업 클릭 = 같은 선택. 팝업 `[근거에서 보기]`는 좌 2의 그 줄로 스크롤
3. 같은 줄 재클릭 = 해제. Esc = 큰 보기 → 팝업 → 선택 순으로 물러난다
4. 선택 근거는 탭·팝업을 옮겨도 유지되고 팝업 사건 개요의 권고 근거에 표시된다(IA §14)

## 10. 결정 (2026-09-14)

README §8.2에 옮겨 적는다. 구현하면서 실제 화면을 보고 바꿀 수 있는 것은 `구현 후 재검토`로 표시했다.

- 그릇은 9월 10일 결정으로 돌아간다. 판단·전망은 사건 작업공간 지도 + 우측 레일, 대응은 집중 팝업(좌 영상 · 우 400 세 탭 사건 개요·SOP 대응·이력 · 바닥 액션 바). 9월 11일 초안이 정본에 넣은 "우측 패널 기본"은 결정 이력이 없어 되돌린다. 이유는 §0
- 팝업 규칙은 레거시 정본 03 §0-9·§2를 그대로 잇는다. 진입로 셋이 한 팝업, 열린 동안 활성 조작면 하나, 실행 중 닫기 잠금, 닫으면 결과가 레일·이력으로
- 내부 자동 조치(CCTV 집중 배치 · 관련 CCTV 구성 · 영상·예측판 보존)는 후보 생성 순간 완료. 담당기관 통보·주민 전파·시설 요청은 자동이라도 승인 뒤
- 긴급 경로. 확인됨부터 `[대응 실행]`과 마커 `[이 사건 대응하기]`가 항상 서고, 판단 갱신·전망 없이 팝업을 연다. 권고 카드에 `전망 기준 없음 · 긴급 대응`
- SOP 구조는 CSMS SOP 대응 탭. 그룹 축은 우선순위(MUST · SHOULD · MAY), 완료 항목만 접는다
- 대응 흐름 4단계는 CSMS 부품·단계 키·상태 문구 그대로, 이름만 `상황실 관제 · 담당기관 · 주민 전파 · 현장 조치`
- 주민 전파는 SOP 한 항목. CAP 문안 하나에 채널별 결과가 줄 아래
- 통제 전환은 필수 조치 완료로 잠그지 않는다. 실행 결과가 도착한 뒤 풀린다. 필수 조치 게이트는 종료가 든다
- 좌측 열 폭은 우선 420. 구현 후 재검토
- 미연결 이벤트는 근거 아래 접힌 구분. 구현 후 재검토
- 이력은 판단 탭·팝업에서 최신이 위. 기록·검증은 오래된 것이 위
- 병합·분리·관계 지정은 자리만. 판단 탭 액션 바 더보기에 잠긴 항목
- 대응중·통제에서 지도에 통제 대상 도로·시설을 강조한다. 구현 후 재검토
- 전망 탭 `[현재 상태로]`는 바닥에 둔다. 탭 클릭으로도 돌아간다
