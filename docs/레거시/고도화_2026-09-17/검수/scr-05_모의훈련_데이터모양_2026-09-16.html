6. 검수 결과 — 결정

우리 방향(훈련하고 시뮬해서 개선한다)과 기준 ①②③에 비추어 판단했습니다. 아홉 중 여덟은 그대로 채택, 하나는 고쳐서 채택, 둘을 새로 추가했습니다.

#결정근거판정
E-1대응에 현상/노출 표시를 붙이고 훈련의 핵심 판단은 현상 대응 기준 ③이 이미 이 구분을 담고 있다 — 현상 대응은 트윈 결과(도달·범위·강도)가 나오고 노출 대응은 여유 시간뿐이다. 창원천을 통제로 물었을 때 결과가 안 읽힌 이유가 이것이었다. 노출 대응을 훈련에서 빼는 것은 아니다 — 조치로는 실행하되 위계에서 아래다 채택
E-2지침은 대응의 target·level 범위까지 · 없으면 비움 · 목표 시간 안 넣음 목표 시간은 기준 ③의 경로 시험을 못 넘는다(모델·공식 기준·원장 어디에도 없다). 지어내면 훈련이 채점이 된다. 단, 재난안전법 시행령·현장조치 행동매뉴얼에 있을 수 있으므로 정본의 `남은 확인`에 남긴다 채택
E-3훈련 시나리오(정지점·조건·발동 규정)를 사건마다 적고, 없으면 훈련 불가 Phase 2는 창원천 하나지만 구조는 사건마다여야 확장된다. 준비 안 된 사건을 조용히 다른 것으로 대체하지 않는 것은 IA §5.2 예외 처리와 같다 채택
E-4조치 가능 시각은 대응의 선택지에만 적고 정지점과 겹치는 것만 뜬다 CLAUDE.md "두 벌이 된 것은 위로 올린다". 같은 시각을 두 곳에 적으면 한쪽만 고쳐져 조용히 어긋난다 채택
E-5고쳐서 채택 — 판 id 와 보고서용 표시값을 둘 다 저장한다 처음 안(판 id만)은 틀렸다. 판을 고치거나 실개발에서 모델을 교체하면 과거 훈련의 결과가 소급해서 바뀐다. "그때 이렇게 나왔다"는 기록이 아니게 된다. 다시 열기는 판 id로, 보고서는 저장된 값으로 읽는다 — 지금 AnalysisResult 가 restore + compareRows 로 쓰는 문법과 같다 수정
E-6훈련 기록과 분석 결과는 다른 물건. 분석 결과는 전망 탭에 남긴다 저장 단위가 다르다(훈련 한 회 = 조치 여러 건 + 조건 + 강평 / 분석 한 건 = 조건 하나 + 비교). 다만 개선 항목은 한 목록이다(README §2.3) — 출처만 `훈련`·`검증`으로 갈린다 채택
E-7조합 판은 빌드 때 미리 27벌(조건 3 × 방류 3 × 통제 3) 훈련 중에 계산하면 화면이 값을 만드는 셈이라 "사전 작성 판을 쓰고 실시간 계산처럼 부르지 않는다"와 부딪힌다. 지금 COMBOS 루프와 같은 방식이라 새 구조가 아니다. 둔치 통제(S1)는 결과판이 없어 조합에 안 들어간다 채택
E-8규칙으로 만든 판은 근거 카드에 "규칙 계산"이라고 적는다 기준 ③의 신뢰 조건. 지금 roadOn 이 이미 그렇게 적고 있다 채택
E-9WhatIfDrill 과 v1 화면 코드를 지운다 v2에 질문 고르기가 없다. 단 코드 단계에서 한 번에 교체한다 — 지금 지우면 화면이 깨진 채로 남는다 채택
E-10추가 — 훈련 진행 상태는 세션이 들고, 사건·조건은 주소가 든다 지금까지 정하지 않았다. 내 조치 목록과 지금 정지점은 길고 자주 바뀌어 주소에 싣지 않는다. 새로고침하면 훈련이 처음으로 돌아간다 — 데모에서 수용하고 문서에 적는다. 사건·조건은 주소가 들어 링크로 열 수 있다(IA §5.2) 결정
E-11추가 — 안 한 조치는 actions 에 안 넣는다. "실제와 같게"는 기준 판이 표현한다 미실시를 따로 기록하면 "안 함"이라는 상태가 생기고, 그 결과를 보여줄 판이 없다. 훈련의 질문은 "할까 말까"가 아니라 "언제 할까"다(README §2.3). 기준 판이 곧 "실제와 같은 시각에 한 것"이다 결정

결정하지 않고 남기는 것

무엇왜 남기나
SOP 단계별 목표 시간근거를 못 찾았다. 재난안전법 시행령·현장조치 행동매뉴얼 확인 대상. 정본 `남은 확인`에 적는다
훈련 중단·재개Phase 2에서 정의하지 않는다. 나가면 훈련이 끝난다
창원천 외 사건의 훈련 시나리오I4 선택 범위. 구조는 사건마다 적게 열어 둔다
유사 사례 조회(①-4)유사 판단 기준이 없다. Phase 2에서 뺀다
