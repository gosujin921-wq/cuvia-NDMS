# 초안 폴더 규칙

이 폴더는 정본(`README.md`, `01`~`03`, IA MD)에 넣기 전에 방향을 정리하는 임시 작업메모 자리다.
여기 있는 파일은 정본이 아니며 어디서도 인용하지 않는다.

## 무엇을 여기 쓰나

- 방향을 같이 고민하는 문서, 검토 결과, 구현 계획처럼 **확인을 거쳐야 정본에 들어가는 것**.
- 정본 여러 곳에 흩어질 내용을 한 번에 보려고 모아 두는 것.

## 무엇을 여기 쓰지 않나

- **결정.** 결정은 정본 `README.md` §8.2에 날짜와 함께 적는다. 초안에 적은 결정은 레거시로 넘어가면 사라진다.
- 정본에 이미 있는 내용의 복사. 정본 절 번호로 가리킨다.
- 데모 값·수치의 정본. 값의 정본은 02 §5.4·§5.5다. 초안은 제안이다.

## 쓰기 전에

1. 참조할 정본 절을 그 자리에서 다시 읽는다. 어제 본 것으로 쓰지 않는다. 정본은 다른 세션이 고쳤을 수 있다.
2. 이 폴더와 `../../레거시/작업/`을 본다. 같은 주제의 초안이 이미 흡수됐는지 확인한다.
3. 제안과 결정을 가른다. 제안은 "제안", 이미 정해진 것은 "결정(날짜)"로 적는다. 선택이 남은 것은 선택지를 나란히 적는다.

## 파일 머리

```
# 제목

> 상태: (방향 논의 초안 | 검토 작업메모 | 작업 계획 초안). 정본 인용 금지. 확인 뒤 <정본 절>에 반영하고 `레거시/작업`으로 옮긴다.
>
> 작성: YYYY-MM-DD. 무엇에서 출발했고 무엇을 정리하는지 두세 문장.
>
> 근거: 참조한 정본 절과 원본.
```

파일명은 `<주제>_<YYYY-MM-DD>.md`. 같은 주제를 이어 쓰면 새 파일을 만들지 말고 같은 파일에 절을 더한다.

## 흐름

```
작성 (이 폴더) → 사용자 확인 → 정본에 반영 → 레거시/작업으로 이동
```

- 반영은 정본을 소유한 세션이 한다. 초안을 쓴 세션은 정본을 고치지 않는다. "정본 고쳐"라는 말이 있을 때만 그 자리만 고친다.
- 반영이 끝나면 파일을 `docs/레거시/작업/`으로 옮기고 루트 `.gitignore`의 화이트리스트에 파일명을 한 줄 추가한다. 레거시는 작업 이력이지 근거가 아니다.
- 반영 뒤 정본 `README.md` §11에 완료 줄을 남긴다.

## 글

- 한국어 설명문으로 쓴다. 비유("렌즈", "무대", "도착")와 번역체를 쓰지 않는다. 주어는 담당자·화면·시스템이다.
- 이 프로젝트가 쓰는 말을 바꾸지 않는다. 디지털트윈, 화면, 사건, 이벤트, 대응 모의훈련.
- 개발 항목(필드명·규칙 ID·API 인증)은 구현 계획에만 적고 기획 메모에는 적지 않는다.
- em 대시를 쓰지 않는다.
