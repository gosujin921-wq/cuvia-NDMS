# CUVIA NDMS Phase 2 기능 및 정보구조도

> 상태: IA 기준안 - 재검수 잔여항목 반영·엑셀 동기화 완료. 2026-09-16 `/scr-05` 를 모의훈련(IA-07 · 옛 IA-03M)으로 고치고 전망 탭 대안 비교를 되살림(README §2.3)
>
> 기준일: 2026-09-11
>
> 역할: Phase 2의 화면 구성, 화면 역할, 정보 객체, 대표 데모 동선과 기존 화면 판정을 정의한다.

## 1. IA의 목적

이 문서는 기존 화면과 패널의 수를 다시 세는 목록이 아니다.

> **센서·API·VLM과 디지털트윈 예측을 결합해 담당자가 확인할 알림과 사건 후보를 만들고, 근거 확인부터
> SOP 대응·실행·보고서까지 끊김 없이 이어지는 구조를 정의한다.**

상위 방향은 `README.md`, 이벤트와 사건의 의미는 `01_이벤트·사건모델.md`, 대표 사건의 내용은
`02_대표데모시나리오.md`, 유형별 트윈의 차이는 `03_유형별디지털트윈.md`를 따른다. 이 문서는 그
결과를 화면과 이동 구조로 바꾸는 역할만 한다.

## 2. IA 엑셀의 역할

`CUVIA_NDMS_기능및정보구조도.xlsx`는 이 MD의 내용을 업무 검토용 표로 옮긴 동기화본이다. `개요`,
`화면`, `정보구조도`, `트윈유형`, `데모동선`, `사건맥락`, `정보객체`, `공통상태`, `Phase1판정`,
`데모범위`의 10개 시트로 구성한다.

- 이 MD가 Phase 2 IA의 정본이며 엑셀과 값이 다르면 MD가 우선한다.
- 방향과 구조를 먼저 MD에서 수정한 뒤 엑셀에 같은 내용을 반영한다.
- `Phase1판정` 시트는 기존 자산의 재사용·재편 여부를 확인하는 표이며 Phase 1 화면 수를 승계하지 않는다.
- 기존 SCR 번호를 보존하기 위해 새 화면 역할을 끼워 맞추지 않는다.
- 엑셀의 행 수와 시트 수를 Phase 2 구현 목표로 사용하지 않는다.

## 3. IA 설계 원칙

1. **사건 중심:** 지구·센서·기능이 아니라 판단하고 대응할 사건이 이동의 기준이다.
2. **질문 중심:** 각 화면은 담당자의 한 가지 핵심 질문에 답한다.
3. **공통 사건 맥락:** 사건 ID, 기준시각, 처리상태, 선택 예측판·영향공간·근거와 검토 중 결정은
   화면을 이동해도 유지한다. 사건 시나리오 방식과 이벤트별 수집·시연 방식은 내부 계약으로 유지한다.
4. **근거와 판단 분리:** 원천 관측, 분석 결과, 시스템 권고와 담당자 결정을 구분한다.
5. **현재와 미래 분리:** 현재 상태, 기준 전망, 대안 전망과 실제 결과를 섞지 않는다.
6. **공통 골격:** 재난유형마다 별도 메뉴와 화면을 복제하지 않는다.
7. **유형별 트윈:** 트윈의 입력·시간축·공간표현·결과만 유형에 맞게 달라진다.
8. **제품에 필요한 근거:** 관측·갱신시각, 품질, 출처기관, 예측 기준시각과 모델처럼 담당자의 판단에
   필요한 정보만 화면에 표시한다. 데모 fixture의 실제·시나리오 구분과 교체 대상은 내부에서 관리한다.
9. **사람 승인:** 사건 확정, 병합·분리, 대응 승인과 종료는 담당자 행위로 남긴다.
10. **수량 비목표:** 화면·패널·재난유형 수를 Phase 2 성과로 사용하지 않는다.

## 4. 전체 구조

```text
CUVIA NDMS
├── 상시 메뉴
│   ├── 01 종합상황 ─ 감시 우선대상·복합 알림·사건 후보·실시간 주요 사건
│   ├── 07 모의훈련 ─ 지난 사건으로 시나리오를 만들어 조건·대응을 바꿔 돌려 보고 개선 항목을 남긴다(README §2.3)
│   ├── 05 이력 ─ [사건] 사건 기록(요약·발생 근거·위험 판단·대응·예측 검증·경과) · [보고서] 사건 보고서
│   ├── 06 통계 ─ 기간 동안의 사건·대응 집계. 이력과 같은 사건 원장에서 센다
│   └── 운영 관리 ─ 대표 데모 밖
├── 02 사건 작업공간 ─ 01의 사건·후보를 열어 진입
│   ├── 사건 개요
│   ├── 관측 근거
│   ├── 영상·현장
│   ├── 상태·관계 이력
│   ├── 03 디지털트윈 ─ 예측 이벤트 선택 시 같은 지도가 예측 모드로 전환
│   │   ├── 현재 상태·기준 전망·대안 전망
│   │   └── 영향·근거·한계
│   └── 04 대응·실행 ─ 사건 안의 집중 팝업
│       ├── 권고·SOP·승인·전파·시설 요청
│       └── 채널·현장 실행 결과
└── 공통 AI 보조 ─ 현재 사건·화면 위에서 근거 탐색과 이동 지원
```

상시 메뉴, 사건 안 화면 모드, 사건 안 팝업을 구분한다. IA-02·03·04는 메뉴를 하나씩 늘리는 구조가
아니며, 한 사건을 검토하는 동안 화면 깊이가 바뀌는 구조다.

### 5.2 Phase 2 라우트 계약

Phase 2는 신규 라우트를 만들지 않고 현재 구현된 `/scr-*` 경로를 유지한다. IA ID는 설계 문서 식별자이며
URL이 아니다. 사건 중심 재편은 URL 교체가 아니라 기존 화면 안의 정보 구조와 패널 역할을 바꾸는 것이다.

| IA | 기준 라우트 | 경로가 나타내는 것 | 선택·전달 값 |
|---|---|---|---|
| IA-01 | `/scr-01` | 종합상황과 사건·후보·감시 우선대상 진입점 | 기존 필터·선택 구조 유지 |
| IA-02 | `/scr-02/:districtId` | 지도 중심 사건 작업공간 | 선택 사건·알림·이벤트는 화면 상태와 기존 query로 전달 |
| IA-03 | `/scr-02/:districtId?panel=twin` | 사건 작업공간 안의 예측 모드 | 선택 사건·Forecast·시각·대안은 query |
| IA-04 | `/scr-02/:districtId` | IA-02 위에 여는 집중 팝업 | 별도 라우트 없이 선택 전망·검토안 맥락 유지 |
| IA-05 | `/scr-07` | 이력. 탭 [사건]이 기본, `?tab=report`가 [보고서] | 사건 기록 창은 `?incident=`, `&view=case`면 ⑤ 예측 검증 절로 연다. 보고서 창은 `?tab=report&report=` |
| IA-06 | `/scr-04` | 통계 | 기간·지역·유형 조건은 화면 상태(공유 불필요) |
| IA-07 | `/scr-05` | 모의훈련. 지난 사건 목록 → 그 사건의 시나리오(`?incident=`) · `?tab=saved` 저장된 분석 | 사건·분석 기준 시점(`basis`)·상황(`situation`)·대응(`response`)·조정값(`preset`)·보는 시각(`validAt`)은 query |
| IA-G01 | `/scr-06` | 기존 AI 화면과 현재 화면의 공통 AI 보조 | 현재 화면·사건·선택 근거 맥락 유지 |
| IA-A01 | 추후 정의 | 운영 관리 | 대표 데모 밖. 실제 개발 시 기존 제품 구조와 함께 정의 |

라우트를 유지하면서 다음 원칙을 적용한다.

- `districtId`는 기존 지도·지구 진입을 유지하는 값이며 사건 범위를 현장 하나로 제한하지 않는다.
- 사건·알림·Forecast 선택은 현재 화면 상태와 기존 query 전달 방식을 우선 사용한다.
- 펼침·hover·임시 입력처럼 공유할 필요가 없는 UI 상태는 URL에 넣지 않는다.
- D0~D8 시나리오 단계와 데모 시계는 공통 상태 엔진이 관리하며 라우트로 만들지 않는다.
- IA-04 대응은 `/scr-02/:districtId` 위의 집중 팝업으로 열고 별도 대응 URL을 만들지 않는다.
- IA-03은 `/scr-02/:districtId`의 query `panel=twin`으로 연다(2026-09-14 구현). `/scr-05/:districtId`는 Phase 1 진입점 호환으로
  남긴다. 그 지구의 사건이 진행 중이면 사건 작업공간 전망 탭(`/scr-02/:districtId?panel=twin`)으로, 지난 사건이면 모의훈련 시나리오
  (`/scr-05?incident=`)로 넘기고, 없으면 지난 사건 목록을 보인다. 신규 라우트를 만들지 않는다.

기존 경로의 역할은 다음처럼 재편한다.

| 기존 경로 | Phase 2 역할 |
|---|---|
| `/scr-01` | 종합상황 유지. 복합 알림과 실시간 주요 사건 목록을 추가 |
| `/scr-02/:districtId` | 재난관제를 지도 중심 사건 작업공간으로 재편 |
| `/scr-03` | 신규 대응 화면으로 확장하지 않고 `/scr-02/:districtId`의 집중 팝업으로 통합 |
| `/scr-04` | 통계(IA-06). 탭 없이 한 화면이고 사건 원장을 모아 센다. 앞서 두었던 사건 이력·예측 검증 탭은 이력(IA-05)으로 옮겼다(2026-09-16) |
| `/scr-05` | 모의훈련(IA-07)으로 재편(2026-09-16 · README §2.3). 상단 탭 둘. `지난 사건`(목록 → `?incident=` 그 사건의 시나리오)과 `?tab=saved` 저장된 분석(목록·정보 창·다시 열기·보고서). 진행 중 사건은 올리지 않는다. 03 §26 |
| `/scr-06` | 기존 진입 경로를 유지하면서 공통 AI 보조와 연결 |
| `/scr-07` | 보고서 메뉴를 이력(IA-05)으로 바꿨다(2026-09-16). 상단 탭 둘 — [사건] 게시판과 [보고서] 게시판. 두 게시판 모두 줄을 누르면 목록 위에 창이 뜬다(platform_web 게시판 문법). 사건 고르개(드롭다운)는 두지 않는다. 없는 사건·보고서는 다른 것으로 바꾸지 않고 게시판으로 돌아가는 길을 준다. `?analysis=…`는 모의훈련 저장된 분석의 보고서 전체 화면으로 같은 렌더러를 쓰며 이력 게시판에 세우지 않는다(03 §26) |

#### 라우트 예외 처리

잘못된 경로를 임의의 사건이나 최신 데이터로 조용히 바꾸지 않는다. 사용자가 무엇이 달라졌는지 알 수 있게
현재 맥락을 보존하고 복귀 경로를 제공한다.

| 예외 | 처리 원칙 | 복귀·다음 행동 |
|---|---|---|
| 선택 사건을 찾을 수 없음 | 빈 사건을 만들지 않고 선택값이 유효하지 않음을 표시 | `/scr-01`의 사건·후보 목록으로 복귀 |
| 병합된 사건 | 원 사건을 새 사건처럼 열지 않고 병합 사실과 대상 사건 표시 | 같은 `/scr-02/:districtId`에서 병합 대상 사건 선택 |
| 오탐·종료 사건 선택 | 편집 가능한 현재 사건으로 되살리지 않고 읽기 전용 기록으로 안내 | `/scr-07?incident=...` 이력의 사건 기록에서 확인 |
| 잘못되거나 만료된 Forecast 선택 | 다른 Forecast를 자동 선택하지 않고 선택값이 유효하지 않음을 표시 | 전망 탭의 예측판 목록에서 다시 선택 |
| 대응에 필요한 Forecast·근거가 없음 | 대응 화면은 열 수 있으나 누락 근거와 긴급 대응 여부를 구분 | 근거 선택 또는 긴급 대응 사유 기록 |
| 지구와 사건 연결 실패 | 지구나 이벤트로 임의 사건을 생성하지 않는다 | `/scr-01`로 복귀하고 연결 실패 안내 |

권한 없음 처리와 역할별 메뉴 노출은 이번 데모 라우트 계약에서 확정하지 않고 추후 제품 개발에서 정의한다.

## 6. IA-01 종합상황

### 역할

도시 전체를 한눈에 보여주는 대시보드가 아니라, 담당자가 **어떤 사건부터 확인할지 결정하는 진입점**이다.

### 필수 정보

| 영역 | 정보 | 원천 객체 |
|---|---|---|
| 감시 우선대상 | 예측·특보·취약성으로 선정한 구역·카메라·시설과 선정 근거 | Event·Forecast·AffectedArea |
| 복합 알림 | 센서·API·VLM·Forecast의 단일 심각 또는 복합 조건, 알림 등급·상태·연결 이유 | AttentionAlert·Event·Forecast |
| 실시간 주요 사건 | 후보·확인중·대응중 사건(안정 국면 표시), 매트릭스 위험등급, 긴급도, 확실성, 경과시간 | Incident |
| 후보 근거 | 최초 징후, 연결 이벤트 수가 아닌 근거 종류, 추가 확인 필요사항 | Event·Incident |
| 공간 개요 | 현재·예상 영향권, 원인·파생 사건, 데이터 장애 위치 | Incident·AffectedArea |
| 광역 맥락 | 특보, 예측 변화, 도시 대응단계 | Event·Forecast·CityOperationalState |
| 데이터 상태 | 지연·결측·의심 원천과 영향받는 사건 | Event·Incident |

### 주요 행동

- 감시 우선대상 또는 사건·사건 후보 열기
- 담당자·상태·유형으로 실시간 주요 사건 거르기
- 데이터 장애가 영향을 주는 사건 확인
- 원인·파생 사건 묶음 펼치기

### 제외할 구성

- 지구 수와 사건 수를 같은 방식으로 집계한 도넛
- 모든 센서값을 동일 우선순위로 나열한 현황판
- 사건과 무관한 기상정보를 큰 카드로 고정 배치
- 전 지구 × 전 지표 신호등 표를 첫 화면의 중심으로 사용

## 7. IA-02 사건 작업공간

### 역할

사건 후보가 왜 만들어졌는지 확인하고, 담당자가 실제 사건 여부와 관계를 결정하는 중심 화면이다.
사건 작업공간은 특정 현장 하나를 뜻하지 않는다. 사건의 `scope`에 따라 지점·시설·구역·지구·도시 전역을
같은 구조로 다루며 지도 범위와 정보 밀도가 함께 바뀐다.

### 기본 화면 구조

| 영역 | 역할 |
|---|---|
| 중심 지도 | 사건의 실제·예상 영향 범위와 센서·CCTV·시설·이벤트 발생 위치를 공간으로 표시 |
| 좌측 관련 이벤트 현황 | 선택한 복합 알림 또는 사건과 연결된 관측·특보·VLM·시설·Forecast·품질 이벤트를 시간순으로 표시 |
| 우측 판단·전망 | 위험도 매트릭스와 현재 판단·전망, 승인 뒤 대응 결과 요약과 실행 진입 |

사건 생성 전에는 선택한 복합 알림을 구성한 이벤트를, 사건 생성 후에는 해당 Incident에 연결된 이벤트·
판단·예측·조치를 보여준다. 같은 지구에서 발생했어도 현재 사건과 연결되지 않은 이벤트는 별도 지구 현황으로
구분한다. 이벤트를 선택하면 지도 위치와 근거 상세가 함께 바뀌고, Forecast 이벤트를 선택하면 같은 지도가
디지털트윈 예측 모드로 전환된다.

### 공통 헤더

| 정보 | 내용 |
|---|---|
| 사건 식별 | 사건 ID, 제목, 재난유형, 공간 범위 |
| 처리 상태 | 후보·확인중·대응중·종료·오탐·병합됨. 대응중 안의 국면 안정 |
| 위험 판단 | 심각도·긴급도·확실성·추세를 독립 표시 |
| 시간 | 최초 관측, 사건 생성, 최신 갱신, 경과시간 |
| 담당 | 담당 조직·담당자·인계 상태 |
| 운영 근거 | 관측·갱신시각, 품질, 출처기관, 예측 기준시각·모델 등 실제 판단에 필요한 정보 |

### 내부 구성

#### 사건 개요

- 현재 상황 한 문장 요약
- 원인·악화·완화 요인
- 위험도 매트릭스의 등급·점수·지표별 기여도와 이를 설명하는 심각도·긴급도·확실성·추세
- 위험·완화·반대 근거와 불확실성·누락정보
- 실제·예상 영향 공간
- 원인·파생·동시 사건 관계
- 다음 확인 또는 결정이 필요한 항목

#### 관측 근거

- 강우·수위·조위·시설 등 시간 정렬
- 원천 관측과 임계치·변화율 파생 결과 분리
- 관측시각과 수신시각
- 결측·지연·의심·보정 상태
- 사건에 연결된 이유
- 침수예측판 갱신(E8)을 관측·영상과 같은 급의 근거로. 유효 시각·침수심·영향 요약 한 줄과 [디지털트윈 보기]

#### 관련 이벤트 현황

- 현재 알림·사건에 연결된 이벤트를 시간순으로 표시
- 이벤트 종류, 발생·갱신시각, 위치, 품질, 연결 이유와 확인 필요 여부 표시
- 수위·강우·특보·VLM·시설·Forecast·품질을 같은 목록에서 구분
- 선택한 이벤트의 센서·CCTV·시설·영향 범위를 지도에서 강조
- 같은 지구의 미연결 이벤트는 기본 목록과 섞지 않고 별도 현황으로 구분

#### 영상·현장

- 사건 주변 CCTV와 선택 영상
- VLM 분석 문장, 신뢰도, 모델·버전·분석시각
- 실제 영상과 분석 결과 병렬 확인
- 현장 보고·사진·통행 가능 여부

#### 상태·관계 이력

- 후보 생성·확인·오탐·병합·분리 기록
- 상태 변경 사유와 담당자
- 외부 기관 사건과의 관계
- 타임라인에 예측 유효 시각의 미래 눈금

### 주요 행동

- `확인`, `추가 확인`, `오탐`
- 기존 사건에 병합 또는 별도 사건으로 분리
- 원인·파생·동시발생 관계 지정
- 이후 트윈·대응에서 유지할 관측·영상·분석 근거 선택
- 예측 이벤트를 눌러 디지털트윈 열기. 같은 화면의 지도가 디지털트윈 화면으로 바뀐다
- 대응 검토 시작

## 8. IA-03 디지털트윈

### 역할

사건 작업공간 안의 디지털트윈 화면이다. 담당자가 근거 목록이나 타임라인의 예측 이벤트를 누르면 같은 지도가 그
시각의 3D 디지털트윈 화면으로 바뀐다. 독립 페이지가 아니다. 현재 상태와 미래 전망을 구분하고 기준 전망("그대로면?")과
대안 비교("지금·더 빨리 대응하면?")를 한 탭에서 보여 준다. 진행 중 사건의 대응 판단은 이 탭이 끝까지 들고 모의훈련으로 넘기지 않는다
(2026-09-16 · README §2.3. 같은 날 앞선 "[디지털트윈에서 비교]로 넘긴다"를 고친다). 두 전망은 같은 트윈의 결과다.

### 구성 요소

| 구성 요소 | 하는 일 | Phase 1 자산 |
|---|---|---|
| 3D 지도 | 지도가 3D로 전환되고 지형·건물 위에 시간대별 침수심과 영향 대상(도로·건물·대상자)이 표시된다 | 트윈 페이지 3D 씬. 수면 하나를 배수권역 단위 침수심으로, 영향 대상 표시 추가 |
| 시간 조절 | 예측 시각을 옮긴다. 눈금은 예측판 유효 시각, 남은 시간 표시 | 시간축 패널 |
| 그대로 두면 | 최대값·도달 예상·영향 대상(도로·중요시설·건물·이용자)과 상태·시각·요약 한 줄. 대상 수는 자료 경로가 확인된 뒤에 붙인다(2026-09-16) | 영향 결과 카드를 기준 한 열로 |
| 대안 비교 | 대응 유형·시작 시점 선택지와 기준 대비 달라지는 지표. 수치는 README §2.3 기준 ③(경로·트윈 결과)을 넘는 것만. 노출 대응은 도달 전 여유 시간 | 2026-09-15 전망 탭 대안 비교표(README §8.2) |
| 근거·한계 | 모델·버전·입력·기준시각·품질·가정 | 근거 카드에 항목 추가 |

시연 시각 이후에 실제로 일어난 일은 눈금에 넣지 않는다. 판단에 쓰는 값은 눈금값이고 눈금 사이 값은 "사용자가
고른 시각"으로 구분한다.

### 공통 다섯 영역

| 영역 | 질문 | 필수 정보 |
|---|---|---|
| 현재 상태 | 지금 실제로 관측된 것은 무엇인가? | 관측값·시설상태·영상·품질·기준시각 |
| 기준 전망 | 현재 조건이 유지되면 어떻게 되는가? | 유효시간별 공간 결과·도달시간·강도 |
| 대안 전망 | 무엇을 바꾸었고 무엇이 달라지는가? | 변경 조건·기준 대비 차이 |
| 영향 결과 | 누가·어디가·언제 영향을 받는가? | 도로·건물·시설·대상·노출·중단 |
| 근거·한계 | 무엇으로 계산했고 어디까지 믿을 수 있는가? | 모델·버전·입력·가정·불확실성·결측 |

### 도시침수 대표 데모

- 배수권역·관로망·센서·CCTV 위치
- 현재 강우·관로·도로수위·조위·펌프·저류시설 가용성
- 시간대별 침수심·범위·도달시간
- 기준 전망과, 데이터가 있을 때의 배수·통제 대안
- 도로·건물·중요시설·대상자 영향
- 외부 모델 수신인지 CUVIA 계산인지 구분

### 주요 행동

- 근거 목록·타임라인의 예측 이벤트 선택
- 시간 조절로 유효 시각 이동
- 대안 비교: 대응 유형·시작 시점을 골라 기준과 견준다. 대안 예측판이 없는 사건은 닫히고 이유가 한 줄로 선다

- [이 전망으로 조치안 갱신]: 선택한 시각의 기준 전망으로 대응 집중 팝업을 연다. 권고 카드에 전망 기준이 표시된다

| F 지반·구조 영향 | 시설·사면·변위 벡터 | 즉시 또는 누적 | 사용 가능성·점검순서 | R0 후보 | 모의훈련의 지난 사건(교방동 급경사지 변위). 사전 작성 예측판. 수치 경로는 03 §15(확인 필요) |

R0 유형은 계산 결과를 주장하지 않는다. 2026-09-16 C~G 를 지난 사건으로 세웠고(03 §5·§16) 모의훈련(IA-07)에서 연다. 값은 사전 작성
예측판이다. 수치는 03 §15 경로 표와 README §2.3 기준 ③을 따르고, 어느 사건을 Phase 2에 보일지는 README §6.1에서 정한다. 실시간 물리 계산처럼 부르지 않고, 모델이 연결되면 같은 계약의 ModelRun 결과로 교체한다.

R0~R3은 `03_유형별디지털트윈.md`의 데이터·모델·업무 준비도다. P0~P2는
`02_대표데모시나리오.md`의 자료 확인 우선순위다. 사건 국면 `안정`과 도로·시설 통제 Action은 서로 다른 값이다.
국면의 옛 이름 `통제`가 Action 과 같은 이름이라 2026-09-16 `안정`으로 바꿨다.

### 데이터가 없을 때

- 기준 전망이 없으면 예측을 가장하지 않고 필요한 모델·데이터를 표시한다.
- 지원하지 않는 대안은 트윈의 대응 선택에 나타나지 않는다. 미지원·미실행·실패는 ModelRun 상태값으로만 기록하고
  화면 라벨로 두지 않는다.
- 실제 관측 비교가 없으면 검증 대기 상태와 필요한 결과를 표시한다.
- 임의 슬라이더로 침수면을 움직인 장면을 예측이라고 부르지 않는다.

## 9. IA-04 대응·실행

### 역할

예측과 영향 근거를 실제 결정, 승인, 전파·시설 요청과 결과로 연결한다.
판단·전망은 사건 지도 위 우측 패널에서 확인하고, SOP·대응 승인·전파·조치 실행은 사건 맥락을 유지한
집중 팝업에서 처리한다. 팝업이 열리면 활성 조작면은 하나이며 닫은 뒤 결과는 우측 요약과 이력에 반영한다.
광역·복합 사건의 지역·기관·시설별 대응은 같은 실행 맥락 안에서 확장한다. 상세 배치는 04 정본을 따른다.

### 내부 구성

| 영역 | 정보 |
|---|---|
| 판단 요약 | IA-02에서 확인한 매트릭스 위험등급·기여 근거와 4축 설명, 영향·불확실성·반대 근거의 대응용 요약 |
| 권고 | 권고 대응수준, 대상, 시점, 생성 근거 |
| SOP 초안 | 단계별 업무, 담당 조직, 자동/승인 구분 |
| 승인 | 선택안, 수정사항, 승인자·시각·사유 |
| 실행 | 전파(CAP 1.2 필드 구조)·도로통제·시설점검·운영 요청 |
| 결과 | 대기·진행중·성공·실패·미응답·확인대기·대체됨·취소 |

### 주요 행동

- 권고 검토·수정·기각
- SOP 항목 선택 및 담당 배정
- 전파 대상·지역·매체·문안 확인
- 시설 운영·점검 요청 승인
- 실패 건 재시도 또는 대체조치 기록
- 사건을 `안정` 국면(상황 안정)으로 전환

### 승인 경계

- 시스템은 권고·SOP·전파문·보고서 초안을 만들 수 있다.
- 사건 확정, 대응수준, 외부 전파와 시설 요청은 담당자가 승인한다.
- 실제 원격제어가 확인되지 않으면 `요청·승인·결과 확인`까지만 표현한다.
- 실행 실패를 성공으로 덮어쓰지 않고 실패와 대체조치를 각각 기록한다.

## 10. IA-05 이력 · IA-06 통계

두 메뉴는 **같은 사건 원장**을 본다. 이력은 사건 한 건을 되짚고, 통계는 여러 사건을 모아 센다. 같은 기간·조건이면 두 화면의
사건 수와 상태가 같다(2026-09-16). 종합상황의 실시간 주요 사건, 모의훈련의 지난 사건 목록도 같은 원장에서 나온다. 목적이 달라
칸은 달라도 사건 수·상태·시각은 갈리지 않는다.

모의훈련의 분석 결과와 분석 보고서는 이력에 쌓지 않는다(2026-09-16). 이력은 "예측 대 실제"를 견주고, 모의훈련은
"실제(재현) 대 바꾼 조건"을 견준다. 분석 결과의 저장·조회·다시 열기·보고서는 모의훈련(IA-07)이 소유한다(03 §26).
**개선 항목만은 한 목록이다.** 예측 검증과 모의훈련이 찾은 고칠 거리를 출처(`검증` · `훈련`)만 달리해 모으고, 승인 뒤 반영한다(README §2.3).

진행 중 사건의 판단·승인·조작은 이력에서 하지 않는다. 그 일은 사건 작업공간(IA-02·04)이 한다. 이력은 읽는 자리다.

### 10.1 IA-05 이력

메뉴 이름은 `이력`이고 상단 탭은 [사건] · [보고서] 둘이다. 모의훈련의 [지난 사건] · [저장된 분석]과 같은 문법으로,
일어난 일(사건)과 만들어진 문서(보고서)를 가른다. 두 게시판 모두 줄을 누르면 목록 위에 창이 뜬다.

| 보는 자리 | 사용자가 보는 목적 | 알아야 할 정보(읽는 순서) | 하는 일 |
|---|---|---|---|
| [사건] 게시판 | 되짚을 사건을 찾는다 | 사건명·범위 → 유형 → 상태(진행 중·종료·오탐·병합) → 발생·종료 시각 → 예측 검증·보고서가 있는지 | 상태·유형으로 거르기, 검색, 줄을 눌러 사건 기록 창 |
| 사건 기록 창 | 이 사건이 무엇이었고, 왜 사건이 됐고, 무엇을 했고, 예측은 맞았는지 한 번에 안다 | 아래 여섯 절을 순서대로 | 절 바로가기, 보고서로 넘어가기 |
| [보고서] 게시판 | 확정·제출할 문서를 찾는다 | 보고서명 → 사건 → 상태(초안·확정본)·판 → 생성 시각 | 줄을 눌러 보고서 창, [보고서 화면]에서 인쇄·상급기관 보고 |

#### 사건 기록 창 — 읽는 순서 (2026-09-16)

사건 기록 창은 탭으로 나누지 않고 한 번에 읽히는 기록이다(SK2 이벤트 상세 · SK 결과보고서와 같은 결). 경과 타임라인 하나로는
"이 사건이 무엇이었고 무엇을 했는지"가 보이지 않는다(2026-09-16 사용자 "이력이 너무 부실하다").

| 절 | 사용자가 알고 싶은 것 | 보이는 정보 |
|---|---|---|
| ① 사건 요약 | 무엇이었나 | 사건 번호 · 유형 · 범위 · 최초 징후 · 사건 생성 · 종료 · 최고 위험 등급 · 담당·승인 · 연관 사건, 결과 한 줄 |
| ② 발생 근거 | 왜 사건이 되었나 | 사건을 만든 알림과 연결 이유 → 근거 관측(수위·강우·조위·특보·영상·시설) → **예측판**(기준시각·모델·도달 시각·최대값·영향 대상)과 그 예측의 실제 결과 |
| ③ 위험 판단 | 어떻게 판단했나 | 위험 등급의 흐름(시각 · 등급 · 한 줄), 가장 높았던 판단의 요약 |
| ④ 대응 | 무엇을 했나 | 결정·승인(누가 · 언제 · 무엇을 · 왜) → 조치(무엇 · 대상 · 담당 · 결과) → 전파(채널 · 결과 · 대체) |
| ⑤ 예측 검증 · 학습 | 근거가 된 예측은 맞았나, 다음에 무엇을 반영하나 | §13.1의 넷: 무엇으로 예측했나 → 얼마나 맞았나 → 실제로 무엇을 했나 → 무엇을 고칠까(개선 항목 · 출처 `검증`·`훈련`) |
| ⑥ 경과 | 전부 어떤 순서였나 | 시간순 타임라인(아래) |

**예측판은 사건을 일으킨 근거의 하나다.** 그래서 예측은 ② 발생 근거 안에 관측과 나란히 서고, 그 카드에 실제 결과와 오차를 바로 붙인다.
⑤ 예측 검증은 그 근거가 실제와 얼마나 맞았는지 되짚고 다음 예측·임계치·SOP에 가져갈 것을 남기는 자리다. 오차는 실패가 아니라
학습 재료다(2026-09-16 사용자). 점수·등급은 매기지 않고, 모델 보정·재학습 자동화는 여전히 향후 활용이다(§13.1).
원장이 없는 지난 사건은 아는 것만 선다 — 발생 근거는 당시 상태 값과 예측판, 대응은 실제 대응 목록. 없는 절은 비었다고 말한다.

⑥ 경과는 타임라인이다(CSMS 통합 타임라인 문법 · KISA 이력 탭과 같은 레일). 한 시간축에 두 갈래를 싣는다.

- **사건 흐름** — 무슨 일이 있었나. 관측·알림·위험 판단·예측판. 둥근 점이고 위험 단계 색을 쓴다.
- **조치** — 무엇을 했나. 확인·결정·승인·조치·전파·결과. 네모 점이고 종류는 짧은 뱃지로 적는다. 실패와 대체조치는 따로 보이게 한다.
- **종료** — 체크 아이콘으로 끝을 닫는다. 오탐·병합도 같은 자리에서 닫는다.

수집 이벤트를 전부 늘어놓지 않는다. 사건을 만들었거나 판단·조치가 참조한 이벤트만 선다. 원장에 없는 시각은 지어내지 않는다.

사건 기록 창의 바닥에는 [보고서]가 있으면 그 사건 보고서로 넘어가는 동작, 진행 중이면 [사건 작업공간] 동작이 선다. 창은 한 번에 하나다.

두지 않는 것: 점수·등급·순위, 사건 편집, 이벤트 원장 전체 목록, 대안 분석 결과와 분석 보고서.

보고서는 독립된 업무가 아니라 사건 기록을 바탕으로 생성되는 결과물이다. [보고서] 탭은 그 결과물을 사건을 가로질러 찾는 자리다.

### 10.2 IA-06 통계

탭 없이 한 화면이다. 사건 한 건의 경과는 보지 않는다. 그것은 이력이 한다.

| 보는 자리 | 사용자가 보는 목적 | 알아야 할 정보 | 하는 일 |
|---|---|---|---|
| 조회 조건 | 볼 범위를 정한다 | 기간(기본 전체) · 지역 · 유형 · 상태 | 칩 한 줄로 고르기, 초기화 |
| 핵심 지표 | 기간 전체를 한 줄로 안다 | 사건 수(진행 중·종료·오탐·병합) → 발생에서 첫 대응까지 → 발생에서 종료까지 → 가장 많이 난 유형·지역 | 없음 |
| 추이·분포 | 언제·무엇이 많았나 | 기간별 발생, 유형별 사건 수 | 없음 |
| 지역별 비교 | 어디서 많았나 | 지역별 사건 수 · 진행 중 · 첫 대응까지 | 줄을 누르면 그 지역으로 좁힌다 |

숫자는 이력과 같은 사건 원장에서 센다. 조건이 같으면 이력 [사건] 게시판의 건수와 같다. 모든 사건이 가진 값(상태·유형·지역·
발생·첫 대응·종료 시각)으로만 세고, 일부 사건에만 있는 값(위험 등급·전파 건수)은 합계를 흐리므로 통계에 세우지 않는다.
계측 곡선·열돔·수온처럼 사건 원장이 아닌 자료로 그리는 판도 두지 않는다. 사건의 계측은 사건 작업공간의 관측 근거와 이력의 사건 기록이 보인다.

## 11. IA-G01 공통 AI 보조

### 역할

현재 사건과 화면의 근거를 요약하고 사용자를 해당 정보로 이동시킨다. 별도의 판단 결과를 만드는
독립 사일로로 두지 않는다.

### 허용 역할

- 현재 사건 요약과 누락 정보 안내
- 특정 판단에 사용된 관측·예측·SOP 근거 찾기
- 유사 사건·과거 결정 탐색
- 전파문·상황보고서 초안 작성
- 답변 근거가 있는 화면·이벤트·문서로 이동

### 제한

- 원천에 없는 사실 생성 금지
- 확실성·한계를 숨긴 단정 금지
- 담당자 승인 대행 금지
- 근거 링크 없는 위험도·대응 결론 금지

관리 화면 수는 대표 데모 성과에 포함하지 않는다.

메뉴를 순서대로 누르는 시연이 아니라, 현재 사건의 `다음 행동`을 통해 이동한다.

### 13.1 D8에서 이력으로 넘기는 예측 케이스 계약

사건이 끝난 뒤 쌓이는 검증 단위는 `예측 케이스`다. 모의훈련(IA-07)은 같은 지난 사건으로 시나리오를 돌려 보는 별도 업무이고 예측 케이스를
다시 계산하지 않는다(2026-09-16 · README §2.3. 2026-09-15 "모의훈련 모드는 두지 않는다"를 고친다). 한 사건에서 예측판이 생길 때마다 케이스 한 건이 되고, 사건 종료(D8)에서 실제 결과가 붙어 확정된다.

| 묶음 | 필수 내용 | 사용 방식 |
|---|---|---|
| 원 사건 | `sourceIncidentId`, 사건 위험유형, 트윈 유형군, 공간범위 | 케이스의 출처와 적용 범위 |
| 예측 기준 | 예측판 기준시각, 입력 상태(최근 강우 이력, 현재 강우, 관로·도로 수위, 조위 예보, 펌프·저류 상태), 입력 이벤트 참조 | "무슨 정보로 예측했나"를 원 이벤트를 수정하지 않고 재구성 |
| 기준 전망 | 핵심 지표(예: 최대 침수심 0.32 m), 도달 시각(17:52), 영향 대상 상태 | 비교의 기준 |
| 대안 전망 | 사전 작성 대안 예측판(배수 대응 시 17:55 · 0.20 m 등) | 대응 선택의 근거 |
| 실제 대응 | Decision, Action, Outcome 참조 | 어떤 대응을 언제 실제로 했는가 |
| 실제 결과 | 실측 도달 시각(17:58), 실측 침수심(0.27 m), 실제 시설 상태(펌프 3/3) — E4·E5·E7·E9 참조 | 예측 대 실제 |
| 오차·개선 | 도달시간 오차(+6분), 침수심 오차(−0.05 m), 영향 대상 적중 여부, 개선 항목 | 예측 정확도와 대응 근거의 축적. 개선 항목은 모의훈련 출처 항목과 한 목록 |

케이스는 원 Incident·Forecast·Decision·Action·Outcome 을 참조만 하고 수정하지 않는다. 화면은 이력(IA-05) 사건 기록 창의
⑤ 예측 검증 절이며(2026-09-16) 디지털트윈 화면에 넣지 않는다. ② 발생 근거의 예측판 카드에서 이어진다 — 예측판은 사건을 일으킨 근거의 하나이고, 검증은 그 근거가 실제와 얼마나 맞았는지와 다음에 반영할 학습을 남긴다(§10.1). 데모에서 실제 모델을 실행하지 않을 때는 임의 계수를 런타임 계산식으로 두지 않는다. 기준·대안 Forecast는
사전에 작성한 시나리오 결과 객체로 준비하고, 실제 모델이 연결되면 입력·모델·버전·계산 주체가 있는 ModelRun 결과로 교체한다.

케이스 화면은 넷을 순서대로 읽힌다. ① 무엇을 무슨 정보로 예측했나(케이스 머리·예측 기준 입력) ② 얼마나 맞았나(예측 대 실제 표 · 예측 범위 대 실제 범위 지도 · 영향 대상 적중)
③ 실제로 무엇을 했나(결정·성공한 조치·같이 만들었던 대안 전망) ④ 다음에 무엇을 고칠까(개선 항목). 차이는 실제에서 예측을 뺀 값이고, 위험을 크게 본 쪽이 과대, 작게 본 쪽이 과소다.
대응으로 노출이 막힌 대상은 예측이 어긋난 것이 아니라 대응이 들어간 것이므로 적중·어긋남 대신 그렇게 적는다. 점수·등급·순위를 매기지 않는다.

확정된 현재 역할은 예측 오차 확인과 사후 개선 항목 도출까지다. 유사 사건 추천, SOP 임계값 개선, 모델 보정·재학습으로 잇는 것은
향후 활용이며 Phase 2 확정 기능이 아니다. 모델 축 개선 항목은 검증 출처에서만 나온다. 모의훈련 결과로 모델을 고치지 않는다(자기 출력 순환).

- D8의 예측 케이스 확정과 예측 대 실제 비교(IA-05 이력 · 사건 기록 창의 ⑤ 예측 검증 절)

### 일정이 허용할 때 선택 확장

- 모의훈련(IA-07): 지난 사건 시나리오 · 비교 · 개선 항목. 어느 사건을 넣을지는 README §7. 인셋·보조뷰·선·노드·벡터·격자 부품

- 사건 AI 보조 오버레이와 운영 관리 보조 구조

C 모의 예측과 G 파생 장면은 제품 방향에는 포함하되 대표 도시침수 D0~D8의 완료 조건에는 넣지 않는다.
항목별 일정과 시연 효과를 확인해 I4에서 선택한다.

### 데이터 확보 시 강화

- CCTV/VLM 결과와 실제 영상 교차확인
- 기준·대안 예측판 비교

- 예측과 실제 관측의 오차 검증

정렬된 과거 자료와 실제 모델 결과가 없으면 A 유형은 R1을 유지한다. 디지털트윈 화면은 사전 작성한 시나리오
Forecast로 목표 제품의 흐름을 보여준다. 데이터 구성과 실제 모델 교체 대상은 내부 계약에서 관리하며 기본
제품 UI에 제작 설명을 노출하지 않는다. 검증되지 않은 모델 성능이나 실제 운영 성과로 대외 주장하지 않는다.

## 19. 화면 정의 완료 조건

각 화면 또는 작업영역은 다음 항목을 가져야 구현 대상으로 확정할 수 있다.

- 답할 사용자 질문
- 사용하는 공통 객체와 필드
- 진입 조건과 다음 행동
- 시스템 생성 정보와 담당자 결정의 구분
- 정상·빈·지연·결측·실패 상태와 내부 시나리오 처리
- 데이터·모델·업무 근거와 준비도
- 대표 데모 포함 여부
- 기존 자산의 재사용·재편·제외 판정

## 20. 결정된 화면 기준과 남은 확인

다음은 현재 기준안에서 결정됐다.

- D0는 IA-01의 감시 우선대상에서 시작하고, D1에 생성된 후보가 실시간 주요 사건에 나타나면 IA-02로 연다.
- AI 보조는 공통 근거 탐색·요약으로 두며 독립 판단 사일로로 만들지 않는다.
- 보고서는 IA-05에서 사건 기록으로 생성하는 산출물로 둔다. 이력의 [보고서] 탭이 사건 보고서를 모으고, 분석 보고서는 모의훈련이 소유한다(2026-09-16).
- 이력(IA-05)과 통계(IA-06)는 별도 메뉴다(2026-09-16). 예측 검증은 사건 한 건의 기록이라 통계에 두지 않고 이력의 사건 기록 창에
  이벤트 이력과 함께 둔다. 종합상황·모의훈련·이력·통계의 사건 목록은 같은 사건 원장에서 나오고 사건 수·상태가 같다.
- P0 자료 확인 전 IA-03은 사전 작성한 시나리오 Forecast로 목표 제품의 흐름을 보여준다. 데이터 구성과
  실제 모델 교체 대상은 내부 계약에서 관리하고, 기본 제품 UI에 제작 설명을 넣지 않는다.
- IA-02는 Phase 1 지구 재난관제와 좌우 패널 골조를 지도 중심 사건 작업공간으로 재편한다. 좌측은 선택한
  알림·사건의 관련 이벤트 현황, 우측은 판단·전망과 대응 결과 요약이며 사건 범위는 지점부터 도시 전역까지 수용한다.
- IA-03 디지털트윈은 독립 페이지가 아니라 사건 작업공간 안에서 예측 이벤트를 눌러 여는 디지털트윈 화면이다.
  IA-04 대응 승인·실행은 사건 위의 집중 팝업으로 분리한다. 화면 배치와 전환은 04 정본을 따른다.
- IA-05 이력은 상시 메뉴로 두되 대표 데모의 주 동선에서는 D8 사건 종료가 그 사건의 기록 창으로 들어온다.
- 디지털트윈의 축은 사건이다(2026-09-16). 유형별 장면은 사건이 가리키는 유형을 따른다. A 는 진행 중 대표 사건(전망 탭), B~G 는 모의훈련의 지난 사건이며(03 §16) 어느 사건을 Phase 2에 보일지는 README §6.1에서 정한다. 표현 부품은 I4 선택 범위다.
- G 파생 관계 표시도 I4 선택 범위다. 대표 데모 필수 범위는 도시침수 D0~D8과 D8의 예측 케이스 확정까지다.
- 사이드바 `/scr-05` 메뉴는 `모의훈련`(IA-07)이다(2026-09-16 · README §2.3. 같은 날 앞선 "디지털트윈 = 사건 기반 대응 What-if"와 09-15 "모의훈련 모드 폐기"를 고친다).
  진행 중 사건의 "지금 대응하면?"은 IA-03 전망 탭이 맡고, 모의훈련은 지난 사건에서 "이런 상황에서 이렇게 대응했다면?"을 본다.
  바꾸는 것은 상황(조건 단계·유형 결합)과 대응(유형·조정값)이고 조합마다 사전 작성 판을 쓴다. 수치는 README §2.3 기준 ③을 넘는 것만 선다.
  예측 대 실제 비교는 IA-05 예측 케이스(§13.1)다. 유형별 장면·광역 인셋은 `03_유형별디지털트윈.md` 제2부가 소유한다. 차별점 기준은 README §2.2 다.

남은 확인은 다음 두 가지다.

1. 모의훈련에서 Phase 2에 보일 사건·유형과 비전 항목의 범위를 README §6.1에서 정한다(B·G·E 자리는 2026-09-16 지난 사건으로 닫혔다).
2. 실제 기관의 메뉴 권한과 운영 절차를 확인해 IA-05 상시 접근 권한과 예측 케이스 관리 책임 조직을 정한다.
   이번 데모에서는 확정하지 않고 추후 제품 개발 시 정의한다.

## 21. IA 완료 기준

- 화면 넷과 모의훈련이 각각 하나의 핵심 질문에 답하고, 사건이 끝나면 예측 케이스가 IA-05 에 쌓인다. 개선 항목은 검증·훈련이 한 목록으로 쓴다.
- 대표 데모 D0~D8이 사건의 다음 행동으로 끊김 없이 연결된다.
- 사건 ID, 기준시각, 처리상태, 선택 예측판·영향공간·근거와 검토 중 결정이 제품 화면의 사건 맥락으로
  유지된다. 사건 시나리오 방식과 이벤트별 dataOrigin·수집·시연 방식은 내부 사건 맥락과 계약으로
  유지하되, 제작 구분을 위한 표시를 기본 제품 UI에 노출하지 않는다.
- 원천 이벤트, 분석 결과, 권고, 결정, 실행과 결과가 구분된다.
- 재난유형별 화면 복제 없이 공통 골격과 트윈 차이를 설명할 수 있다.
- 데이터가 없는 상태에서도 허위 결과 대신 필요한 연계와 한계를 보여준다.
- Phase 1 자산의 유지·재편·통합·제외·보류 판단이 기록돼 있다.
- 대표 데모와 후속 제품 범위가 구분돼 있다.
