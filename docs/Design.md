# 지도 스타일 — 무엇이 문제였고 어떻게 잡았나

> 대상 코드: `designs/src/lib/map-config.ts` · `designs/src/lib/map-style.ts` · `designs/src/lib/useMapLibre.ts`
> 이 문서는 **왜 그 값인지**를 남긴다. 값 자체는 코드가 정본이고, 여기 표는 작성 시점의 사본이다.

## 요약

MapTiler 커스텀 스타일 `202603_map`(ID `019cd585…`)을 그대로 쓰면 어두운 관제 화면에서 지도가 뒤집힌다.
**정보가 없는 면이 제일 밝고, 봐야 할 것이 그 아래 깔린다.** 원본이 밝은 베이스맵을 전제로 만들어졌기 때문이다.

문제는 두 종류였다.

| 종류 | 내용 |
|---|---|
| 색 설계 | 원본 팔레트가 라이트 전제 — 명도 서열이 의미 서열과 반대 |
| 구현 순서 | 덮어쓰기를 지도 생성 **후**에 해서 타일별로 색이 갈림 |

두 번째가 실제로 화면을 깨뜨린 원인이었고, 첫 번째보다 늦게 발견됐다.

---

## 1. 색 설계 문제

### 1-1. 산이 배경으로 뭉갠다

원본 `Wood` 는 `hsl(138, 10%, 40%)`, 배경은 `hsl(249, 3%, 41%)`. **명도가 1%p 차이**다.
물만 `hsl(205, 29%, 30%)` 로 채도가 살아 있어서 "물은 보이는데 산은 안 보이는" 화면이 된다.

처음엔 채도(10%)가 원인이라고 봤는데 **틀린 진단이었다.** 국내 내비 다크맵을 대조해 보니 그쪽 임야도 채도는 10%대다.
차이는 명도였다 — 저쪽은 20% 언저리, 원본은 40%. 어둡게 깔면 채도가 낮아도 산으로 읽힌다.

### 1-2. Wood 가 반투명이라 지정한 색이 안 나온다

원본 `fill-opacity` 가 `z0 0.5 → z14 0.6`. 반투명이라 지정 색이 바닥과 섞인다.
채도 30% 를 줘도 화면에는 **14%** 로 찍혔다. 색만 만져서는 원하는 값이 안 나온다.

→ `opacity: 1` 로 고정하고 색으로 직접 잡는다. 그래야 코드의 값과 화면의 값이 일치한다.

### 1-3. Forest 레이어는 이 앱에서 아예 안 그려진다

`maxzoom: 8` 인 데다 `fill-opacity` 도 `z8` 에서 0 이 된다. 앱 `minZoom` 은 9.
**화면에 보이는 산은 전부 `Wood` 다.** `Forest` 에 값을 줘도 무의미하므로 목록에서 뺐다.

격자 조회로 확인한 실제 렌더 분포(줌 10.7):

| 레이어 | 조회 히트 | 내역 |
|---|---|---|
| `Wood` | 801 | 산 |
| `Water` | 392 | 바다 363 · 하천 21 · 저수지 6 · 호수 2 |
| `Farmland` | 119 | 농지 |
| `Industrial` | 69 | 산업 |
| `Residential` | 28 | 주거 |
| `Grass` | 15 | **골프장 9 · 공원 5 · 초지 1** |

`Grass` 는 산이 아니다. 골프장·공원이다.

### 1-4. 도로가 혼자 하얗게 뜬다

간선 `hsl(56,10%,66%)`, 외곽선 `hsl(40,6%,75%)`, 교량 상판 `hsl(42,49%,93%)`.
어두워진 바닥 위에 얹히면 도로망이 화면에서 제일 밝은 면이 되어 마커·침수 범위보다 먼저 눈에 들어온다.

도로 계열은 `source-layer` 기준 **42개**이고 그중 **17개가 줌·도로등급별 표현식**(`interpolate` / `match` / `case`)이다.
단색으로 갈아끼우면 줌에 따라 색이 변하는 동작이 통째로 죽는다.

→ 표현식 구조는 두고 **그 안의 `hsl()` 명도에만 계수를 곱한다**(`ROAD_DIM = 0.55`).
`"match"` · `"motorway"` 같은 색 아닌 문자열은 정규식에 안 걸려 그대로 통과한다.
계수만 곱하므로 도로 등급 간 밝기 서열(고속 > 간선 > 이면)은 원본대로 남는다.

### 1-5. 서로 같은 색인 레이어들

`Background` · `Industrial` · `Military` 가 원본에서 **모두 `hsl(249,3%,41%)`** 다.
배경만 내리면 산업단지·군사지역이 새로 제일 밝은 면이 된다. 같이 내리되 한 단계 밝게 둬 구분을 남겼다.

### 1-6. 명도가 같으면 축소 화면에서 합쳐진다

작업 중간에 `Wood` 와 `Residential` 을 둘 다 명도 17% 로 뒀더니, 줌아웃해서 도형이 뭉개지는 순간
**시가지가 통째로 사라졌다.** 색상만 다르고(140 vs 225) 명도가 같으면 축소된 화면에서 구분이 안 된다.

→ 4%p 벌렸다(산 20% / 주거 16%).

## 2. 구현 순서 문제 — 타일별로 색이 갈렸다

**이것이 화면을 실제로 깨뜨린 원인이다.**

처음 구현은 이랬다.

```
원본 스타일로 지도 생성 → map.on("load") → setPaintProperty 로 50여 개 레이어 덮어쓰기
```

덮어쓰기 **전에 이미 그려진 타일은 원본 색을 유지**하고, 그 뒤에 도착한 타일만 새 색으로 그려진다.
결과적으로 화면에 사각형 경계가 그대로 드러났다 — 밝은 회색 시가지 옆에 어두운 시가지가 붙고,
손대지 않은 `Sand` 같은 레이어의 원본 모래색이 한쪽 타일에만 남았다.

이 증상을 처음엔 **타일 일반화(줌 레벨마다 폴리곤이 다름)로 잘못 진단했다.**
일반화도 실재하는 현상이지만, 사각형으로 딱 갈리는 경계는 그것으로 설명되지 않는다.
일반화는 경계가 불규칙하고, 이건 타일 경계와 정확히 일치했다.

### 고친 방식

```
스타일 JSON fetch → 객체 상태에서 가공 → 가공된 스타일로 지도 생성
```

지도는 처음부터 고쳐진 스타일 하나만 안다. 원본 색으로 그려지는 타일이 **생길 수 없다.**
덤으로 원본 색이 잠깐 보였다 바뀌는 깜빡임도 사라진다.

가공 함수는 전부 순수 함수로 `map-style.ts` 에 모았다 — 지도 인스턴스가 필요 없고, 스타일 객체만 받아 고쳐서 돌려준다.

> **규칙**: 지도 표현을 바꿀 때는 `setPaintProperty` 가 아니라 `map-style.ts` 의 가공 단계에 넣는다.
> 런타임에 켜고 끄는 것(레이어 토글 등)만 지도 인스턴스를 쓴다.

## 3. 지금 팔레트

바닥을 캔버스로 깔고 **도로를 가장 밝게 남기는** 구조다. 국내 내비 다크맵과 같은 서열이다.

| 요소 | 레이어 | 원본 | 현재 |
|---|---|---|---|
| 건물 2D | `Building` | `hsl(30, 6%, 73%)` | `hsl(225, 6%, 12%)` |
| 배경 | `Background` | `hsl(249, 3%, 41%)` | `hsl(228, 8%, 13%)` |
| 주거지 | `Residential` | `hsl(236, 9%, 32%)` | `hsl(225, 7%, 16%)` |
| 농지 | `Farmland` | `hsl(138, 10%, 38%)` | `hsl(140, 8%, 18%)` |
| 산업·군사 | `Industrial` · `Military` | `hsl(249, 3%, 41%)` | `hsl(228, 6%, 19%)` |
| **산** | `Wood` | `hsl(138, 10%, 40%)` · 반투명 | `hsl(140, 14%, 20%)` · **불투명** |
| 초지 | `Grass` | `hsl(138, 10%, 38%)` | `hsl(140, 10%, 21%)` |
| 물 | `Water` | `hsl(205, 29%, 30%)` | `hsl(206, 20%, 23%)` |
| 건물 3D | `Building 3D` | `hsl(218, 7%, 68%)` | `hsl(222, 6%, 34%)` |
| 도로 | 42개 레이어 | `hsl(56, 10%, 66%)` 등 | 명도 × **0.55** ≈ 36% |

**명도 서열**: 건물 12% < 배경 13% < 주거 16% < 농지 18% < 산업 19% < 산 20% < 초지 21% < 물 23% < 3D건물 34% < 도로 36% < 마커(채도 100%)

### 검증

지도 영역 픽셀 집계에서 **채도 높은 색이 화면의 0.03~0.17%** 뿐이고 그것이 전부 마커다
(경보 `hsl(30,100%,70%)`, 장비 `hsl(220,100%,75%)`). 지도에서 채도가 살아있는 건 마커밖에 없다 — 관제 화면으로선 의도한 구조다.

## 4. 지형 음영 (SCR-05)

스타일이 `terrain-rgb-v2` 를 선언하고 있는데 **hillshade 레이어가 없다.** 그래서 3D 로 눕혀도 능선 음영이 안 잡히고
산이 평평한 색면으로만 보였다.

`ensureHillshade()` 는 이미 `flood-scene.ts` 에 구현돼 있었고 기본값만 꺼져 있었다.
`DEFAULT_LAYERS.hillshade` 를 `true` 로 바꿨다([DigitalTwinPage.tsx](../designs/src/pages/scr-05/DigitalTwinPage.tsx)).

레퍼런스와 우리 화면 차이의 대부분이 색이 아니라 **음영 부재**였다.

**음영은 SCR-05 에만 걸려 있다.** 나머지 화면은 `useMapLibre` 만 쓰고 음영 코드가 없다.
SCR-01 은 평면 조망(pitch 0)이라 효과가 3D 만큼 크지 않아 넣지 않았다.

## 5. 남은 것 · 주의사항

### 줌 단계마다 임야 면적이 변한다 — 색으로 못 고친다

`maptiler_planet_v4` 의 maxzoom 은 15 다. z9~z15 사이 **정수 줌마다 다른 타일**을 받고,
각 타일의 `wood` 폴리곤은 서로 다르게 단순화돼 있다. z9 타일은 작은 임야를 버리고 큰 걸 합치고, z14 타일은 필지 단위로 담는다.

실측하면 육지 중 초록 비율이 줌에 따라 **51% ↔ 59%** 로 움직인다. 어떤 색을 골라도 없어지지 않는다.
없앨 수 있는 건 그 변화가 얼마나 눈에 띄느냐뿐이고, 그것은 **산과 배경의 명도 차**가 곧 크기다.

| 산 명도 | 산 구분 | 줌 시 색 변화 |
|---|---|---|
| 40% (원본, 배경 41%) | 안 보임 | 없음 |
| **20% (현재, 배경 13%)** | 뚜렷 | 눈에 띔 |
| 16% (배경 13%) | 희미 | 거의 없음 |

원본이 산을 배경과 같은 색으로 깔아둔 건 이 트레이드오프를 **산 쪽을 포기하는 방향**으로 푼 결과였다.
현재는 산을 살리는 쪽을 택했다.

`Wood` 에 줌별 opacity 램프를 되살리지 않은 것도 같은 이유다 — 램프를 넣으면 줌에 따라 산 색이 또 변해서
고치려던 문제를 다시 만든다.

### 줌 문턱에서 나타나는 레이어들

원본 스타일에 줌 문턱이 여럿 있다. 줌 전환 시 화면이 바뀌는 정상 동작이다.

| 레이어 | 동작 |
|---|---|
| `Building` | z12~15, opacity `z12 0.2 → z13 0.3` |
| `Building 3D` | z15 부터 |
| `Farmland` | opacity `z8 0 → z13 1` |
| `School`·`Hospital`·`Pitch`·`Cemetery` | z10 부터 |
| `Pedestrian`·`Construction` | z12 부터 |
| `Military` | opacity `z14 0.25 → z18 0.85` |
| `Parking` / `Parking space special` | z15 / z16 부터 |

특히 **z15 에서 2D 건물 → 3D 건물로 교대**한다. 줌 한 단계에 시가지가 확 바뀌는 건 이것이다.
`Farmland` 의 opacity 램프는 원본을 그대로 뒀다 — 줌을 당길수록 농지가 서서히 올라오는 건 의도된 연출이다.

### 손대지 않은 라이트 테마 잔재

다음은 밝은 값이 그대로 남아 있다. 현재 화면에는 거의 안 나오지만, 해당 지물이 있는 지구로 가면 튄다.

`Pedestrian` `hsl(54,80%,98%)` · `Sand` `hsl(52,93%,89%)` · `Ice`·`Heliport` `hsl(0,0%,100%)` ·
`Parking space special` `hsl(218,80%,96%)` · `Swimming pool` `hsl(191,92%,75%)` · `Cemetery` `hsl(90,6%,93%)` · `Zoo` `hsl(66,79%,78%)`

### 도로만 색 계열이 다르다

배경 246 · 주거 225 · 건물 222 · 물 206 은 전부 차가운 쪽인데 도로만 56(따뜻한 쪽)이다.
명도를 낮춰 덜 튀지만 계열은 이질적이다. 우선순위가 낮아 두었다.

### 스타일은 제품군 공용이다

`MAP_STYLE_URL` 의 스타일은 CUVIA 제품군이 공유한다. **MapTiler 쪽에서 고치면 다른 제품에도 번진다.**
이 앱에서만 덮어쓰는 이유가 그것이다.

MapTiler 키도 제품군 공용 값을 그대로 쓰고 있다. 최소 두 제품의 클라이언트 번들에 같은 키가 박혀 나가므로,
배포 전 키 정책 확인이 필요하다. 키 분리보다 **MapTiler 쪽 도메인 제한**이 먼저 실효가 있다.

## 부록 — 검토했다가 접은 것

**다른 제품(`019bdf7d…` / `CUDO1`) 스타일로 교체**: 적용해 봤으나 되돌렸다.
그 스타일은 배경이 `hsl(214,62%,16%)` 짙은 남색인데 **바다가 `hsl(204,92%,75%)`** 로 극단적으로 밝고,
`Wood` 가 `hsl(211,10%,46%)` 청회색이라 초록 산이 아예 없다.
또 `globallandcover` 계열(`Forest`·`Meadow`·`Scrub`·`Crop`)이 명도 76~86% 파스텔로 남아 있어
z8 이하로 줌아웃하면 튀어나온다(그 앱은 `minZoom` 이 없어 도달 가능).
