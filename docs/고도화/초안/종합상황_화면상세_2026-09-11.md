# 종합상황(scr-01) 화면 상세 초안

> 상태: 검토 작업메모. 정본 인용 금지. 디테일을 확정한 뒤 IA §6에 흡수하고 `레거시/작업`으로 옮긴다.
>
> 작성: 2026-09-11. 1차 재편(사건 큐·복합 알림·감시 우선대상·데이터 상태 카드)은 정본 영역명을 카드 제목으로
> 그대로 박아 화면 문구가 되지 못했고, 다른 CUVIA 관제 화면을 보지 않고 만들었다. CSMS 통합관제와
> platform_web 관제 대시보드를 확인한 뒤 그 문법에 맞춰 내용을 다시 잡는다.
>
> 근거: IA §6 · §17, 01 §6.1 · §6.2 · §8.1, 02 §5.2.1 · D0~D1, README §9. 참조 화면은 아래 §1.

## 1. 참조한 화면

| 화면 | 위치 | 골격 |
|---|---|---|
| CSMS 통합관제 (SCR-01) | `012_CUVIA_CSMS/designs/src/pages/scr-01/` | NDMS 데모를 복사해 다듬은 후속 판. 지도 + 좌 2패널 + 우 3패널 + 하단 CCTV 3슬롯 + 상단 캡슐 |
| platform_web 관제 대시보드 (SCR-2100) | `007_CUVIA_PLATFORM_WEB/features/dashboard-kisa/` | 제품 원형. 지도 + 좌 300 · 우 340 레일 + 하단 CCTV. 우측 "이벤트 현황" : "위험도별 현황" = 11 : 9 |
| platform_web 이벤트 도메인 | `kits/event-kit/src/types.ts` | 처리상태 미확인·대응중·종료, 위험도 Lv1~5, 배지 규칙의 단일 출처 |

두 화면이 공유하는 규칙

- 패널 제목은 `h2 text-body font-semibold`, 우측에 `text-caption` 보조(건수·범위). 패널은 전부 GlassPanel
- 목록 행은 상태 점 · 이름 · 보조 라벨 · 두 번째 줄(진행 사건 또는 기본 정보) · 오른쪽 chevron
- 사건 카드는 위험도 배지 · 제목 · (보조 배지) / 위치 · 장비 · 시각 / 진행률 또는 분석 상태
- 두 축을 섞지 않는다. 위험도(HIGH·MEDIUM·LOW / Lv5~1)와 처리(미확인·대응중·종료)는 다른 축이고,
  지구 상태(위험·주의·정상)는 위험도 집계의 파생이다. 범례에 축 이름을 단다
- 값이 없으면 `-`, 수치는 mono · tabular. 카드 시각은 상대(`5분 전`) 또는 대본 시각, 표는 절대 시각
- 지도 이름표는 전부 그리고 층서로만 가른다. 진행 사건이 있는 곳만 점 색, 메인 사건만 펄스
- 하단 CCTV는 평상시 대표 채널 순환, 사건 시 사건 채널로 재구성. 시연 중에는 순환을 멈춘다

## 2. 종합상황 구성안

NDMS 의 "지구" 가 CSMS 의 "사업장" 자리다. 제목은 CSMS·platform_web 문구를 그대로 쓰고 대상만 바꾼다.

| 자리 | 제목 (제안) | 내용 | NDMS 데이터 |
|---|---|---|---|
| 상단 캡슐 | (제목 없음) | 시각 · 위험 지구 n · 주의 지구 n · 대응중 n. 심각 사건이 서면 맨 앞에 `심각 사건 n건 대응 필요` 배지 | 시연 시계 · 지구 상태 집계 · 처리상태 대응중 수 · 매트릭스 심각 사건 수 |
| 좌 1 | **지구 현황** | 전체 지구 12 · 온라인 CCTV n · 위험 지구 n · 주의 지구 n | 지구 원장 · CCTV 채널 · 지구 상태 파생 |
| 좌 2 | **지구** (n곳) | 상태 점 · 지구명 · 지구 유형 / 두 번째 줄: 진행 사건이 있으면 `위험도 사건 제목`, 없으면 관측 대상. 정렬 위험 → 주의 → 정상, 동률은 최근 사건. 푸터 범례 `지구 상태 · 위험 주의 정상` | 사건 파생(지구별 최고 위험도 사건) |
| 우 1 | **위험 현황** | `심각 n` · `경계 n` · `대응중 n` 3셀. 캡션 `진행 중 사건 · 대응은 위험도와 별개` | 매트릭스 등급 집계 · 처리상태 |
| 우 2 | **이벤트 유형 현황** | 도넛 + 유형별 건수. 유형 축 = 관측 임계·변화율 · 시설 상태 · 영상 분석 · 예측 갱신 · 특보 · 품질. 심각 사건이 서면 접힌다 | 이벤트 원장 유형별 집계 |
| 우 3 | **실시간 주요 사건** (n건 진행 중) | 사건 카드. 위험도 배지 · 제목 · `감지`(사건 전 알림) · `확인 필요` / 지구 · 장비 · 시각 / SOP 진행률 또는 분석 상태. 카드 클릭 → 사건 작업공간 | 복합 알림(사건 전) + 사건(후보 이후). 알림 카드가 후보가 되면 같은 자리에서 사건 카드로 바뀐다 |
| 하단 | **지구 대표 CCTV** / **우선 확인 CCTV** | 평상시 지구 대표 채널 순환 3슬롯. 사건이 서면 사건 카메라 · 진입 경로 · 전체 시야 | CCTV 채널 · 사건 카메라 |
| 지도 | 지구 이름표 12 | 전부 그리고 진행 사건 지구만 점 색. 메인 사건 점만 펄스. 감시 우선구역은 이름표 보조 표기 | 지구 원장 · 지구 상태 · 감시 우선대상 |
| 좌측 얇은 스트립 (제안) | **데이터 장애 없음** / 장애 원천 칩 | platform_web "장비 장애 없음" 스트립 문법. 지연·결측 원천이 있으면 칩으로 | 데이터 상태 파생 |

IA §6 의 영역과 대응

| IA §6 | 이 구성안에서 |
|---|---|
| 감시 우선대상 | 지구 이름표 보조 표기 + 지구 목록 두 번째 줄(사건 없을 때 `감시 · 사유`) + 실시간 주요 사건의 `감지` 카드(사전 감시 알림) |
| 복합 알림 | 실시간 주요 사건의 `감지` 카드. 후보가 되면 사건 카드로 전환 |
| 사건 우선 큐 | 실시간 주요 사건 (위험도 순 · 최근 순) |
| 후보 근거 | 카드 세 번째 줄(분석 상태 · 근거 칩) 과 사건 작업공간 |
| 공간 개요 | 지도 이름표 점 색 · 펄스 |
| 광역 맥락 | 상단 캡슐 (특보 배지는 유지) |
| 데이터 상태 | 좌측 얇은 스트립 |

## 3. 축 정리 (NDMS 값과 참조 축의 대응)

| 참조 축 | NDMS 값 | 표기 |
|---|---|---|
| 위험도 HIGH · MEDIUM · LOW | 매트릭스 등급 심각 · 경계 · 주의 · 관심 | 배지 red · orange · yellow · gray. 판단 전(매트릭스 없음)은 배지를 그리지 않는다 |
| 처리 미확인 · 대응중 · 종료 | 처리상태 후보 · 확인중 · 확인됨 · 대응중 · 통제 · 종료 · 오탐 · 병합됨 | 카드 배지는 참조 3단으로 접어 표기: 후보·확인중 = 미확인, 확인됨·대응중·통제 = 대응중, 종료·오탐·병합됨 = 종료. 상세는 작업공간 |
| 지구 상태 위험 · 주의 · 정상 | 지구의 진행 사건 최고 등급: 심각 = 위험, 경계·주의 = 주의, 없음 = 정상 | 점 · 이름표 · 범례 |
| 감지 vs 사건 | 복합 알림(사건 전) vs 사건 후보 이후 | 카드 `감지` 배지 |

## 5. 남은 선택지

- 5.1 위험 현황 셀을 `심각 · 경계 · 대응중`으로 둘지 `심각 · 경계 · 주의`로 둘지. 참조는 위험도 둘 + 처리 하나
- 5.2 처리상태 8종을 카드에서 3단으로 접을지 그대로 쓸지. 참조는 3단
- 5.3 데이터 상태를 좌측 얇은 스트립으로 둘지 우측 패널로 둘지. 참조는 스트립
- 5.4 감시 우선구역을 지구 목록 두 번째 줄로만 둘지 별도 카드로도 둘지
- 5.5 유형 도넛의 축을 이벤트 유형으로 둘지 재난유형(도시침수 등)으로 둘지
- 5.6 지도 이름표 펄스를 메인 사건 점에만 둘지 사건 전부에 둘지. 참조는 메인만

## 6. 확정하지 않는 것

- 레일 폭 · 카드 높이 배분 (참조 300 · 340 유지)
- 카드 애니메이션(정렬 이동 · 페이드) 도입 시점
- AI 질의 바 · 알람 버튼 위치 (IA-G01 재편 때)
