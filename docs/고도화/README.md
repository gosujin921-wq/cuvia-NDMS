# CUVIA NDMS Phase 2 고도화 계획

> 상태: **Phase 2 계획 정본**  
> 기준일: 2026-09-10  
> 현재 `designs/src`는 Phase 1 프로토타입이며, 이 문서가 Phase 2 신규 작업의 방향과 범위를 결정한다.

## 1. 목표

> **CUVIA는 센서·영상·기상·시설·기관 이벤트를 수집해 하나의 재난 사건으로 연결하고, 현재 상황의
> 근거와 미래 영향을 함께 보여줘 담당자가 대응을 결정하도록 지원한다.**

Phase 2는 기존 화면에 기능과 재난유형을 계속 추가하는 작업이 아니다. 앞으로 만들 제품의 전체
방향을 수립하고, 그 방향이 실제로 가능한 구조임을 대표 데모로 보여주는 단계다.

데모가 증명할 것은 세 가지다.

1. 여러 출처의 이벤트를 받아 하나의 사건으로 묶을 수 있다.
2. 사건 유형에 따라 디지털트윈의 조건·시간축·표현·영향 결과가 달라질 수 있다.
3. 예측 결과가 담당자 판단·SOP·상황전파·기록으로 이어질 수 있다.

### 넓이와 깊이

| 구분 | 보여주는 방식 |
|---|---|
| 제품의 넓이 | 이벤트 유형별 대표 사건과 디지털트윈 예상 시나리오 |
| 제품의 깊이 | 대표 사건 한 건을 수집부터 기록까지 상호작용으로 시연 |
| 확장성 | 유형이 늘어도 공통 사건 구조와 화면 역할이 유지됨을 설명 |

유형마다 알람→SOP 전체 흐름을 반복하지 않는다. 전체 흐름은 대표 사건 한 건으로만 증명하고,
나머지 유형은 어떤 이벤트를 받아 디지털트윈에서 무엇을 다르게 보여주는지 설명한다.

## 2. 범위와 원칙

### 이번 계획에 포함

- 이벤트 수집·정규화·연결 구조
- 원천 이벤트와 재난 사건의 구분
- 사건의 지점·구역·전역 범위
- 유형별 대표 사건과 디지털트윈 구성
- 대표 데모 시나리오 한 벌
- 화면 역할과 IA 재편
- 데이터 출처와 준비 상태
- 단계별 구현 순서와 완료 기준

### 대표 데모에서 완성하지 않음

- 모든 재난유형의 동적 시뮬레이션
- 실제 기관 연계의 운영 수준 완성
- 실 전파·실 시설물 제어
- 권한·결재·감사·저장 정책의 제품 수준 구현
- 대규모 실데이터 운영과 SLA

위 항목은 향후 제품 구조에 위치만 표시할 수 있다. 계획 기능을 현재 보유 기능처럼 표현하지 않는다.

### 설계 원칙

- **사건 중심:** 센서나 유형 목록보다 담당자가 판단할 사건이 먼저다.
- **근거와 확정 분리:** 센서·VLM·예측은 근거이고 확인·승인은 담당자 행위다.
- **현재와 미래 분리:** 현재 관측, 기준 전망, 사용자 대안, 실제 결과를 구분한다.
- **공통 골격과 유형별 계약:** 업무 흐름은 공통이고 트윈의 입력·시간·표현·결과는 유형별로 바뀐다.
- **정직한 데모:** 실연계·연계 예정·계산·모의·개념을 구분한다.
- **수량 비목표:** 지구·유형·사건 수를 Phase 2 성과로 삼지 않는다.

### 검토한 자료와 사용 방식

| 자료 | 확인된 내용 | 이 계획에서의 사용 |
|---|---|---|
| CUVIA 요약설명자료 v0.2 | VLM·AI 판단·E-SOP·침수예측·자동기록을 8단계 비전으로 제시 | **목표 비전.** 현재 구현·실증의 증거로 사용하지 않음 |
| 창원시 CUVIA REV 1.0 | 영상 AI, E-SOP, 모의훈련, 침수예측, 보고서 기능안을 제시 | 회사·제안 역량과 Phase 2 제품 범위 후보를 구분 |
| 2024 도시침수 완료보고 | 창원 센서·CCTV·시설·예측 연계 항목과 실증 결과를 기록 | 대표 침수 데모의 현실적인 데이터 기반 |
| 지오멕스 자료 4종 | 센서·GIS·영상·위험도·SOP·전파·보고서 기능을 확인 | 업계 기본기와 비교 기준. 화면을 그대로 복제하지 않음 |
| RINO 소개서 | 이벤트 룰·메시지 라우팅·워크플로우·상황전파의 모듈 구조를 확인 | 공통 사건 처리 구조의 참고 근거 |
| TwinRIS-ON 제안서 | 계측 통합·NDMS 연계·3D 모니터링 중심 | 협력 가능한 수집·표현 경계로 사용 |
| 남해군 자료·시연 | 계측→경보→전파와 수위 슬라이더 기반 3D 시연을 확인 | Phase 1 원형과 차이를 설명하는 근거 |
| 기존 고도화 MD | 유형·트윈·사건·SOP·화면에 대한 과거 검토 | 원본과 재검증한 결론만 이 문서에 흡수 |

자료의 `제안`, `보유`, `연계 가능`, `실제 연결`, `데모 구현`은 서로 다른 상태다. 제안서에 적힌
기능을 현재 CUVIA 데모가 제공한다고 해석하지 않는다.

## 3. 이벤트 수집과 활용 구조

```text
원천 데이터 수집
센서 · CCTV/VLM · 기상 · 시설 · 기관 시스템
        ↓
관측 이벤트 정규화
값 · 단위 · 위치 · 시각 · 출처 · 품질
        ↓
재난 사건 생성·연결
유형 · 범위 · 상태 · 관련 관측 · 원인/파생 관계
        ↓
판단 근거 구성
임계치 · 교차검증 · 신뢰도 · 유사 이력
        ↓
디지털트윈 예측
현재 상태 · 조건 유지 전망 · 대안 조건 · 공간 영향
        ↓
대응 결정·실행
권고 · 담당자 승인 · SOP · 전파 · 조치
        ↓
결과 기록·검증
실행 결과 · 현장 보고 · 예측 대 실제 · 보고서
```

### 공통 객체

| 객체 | 뜻 | 예시 |
|---|---|---|
| 원천 데이터 | 외부 시스템이 제공한 원본 | 수위 3.41m, 강우 54mm/h, 펌프 2대 가동 |
| 관측 이벤트 | 단위·위치·시각·출처를 통일한 변화 | 봉암 강우량계가 경보 기준 초과 |
| 재난 사건 | 함께 판단하고 대응할 이벤트 묶음 | 봉암 배수구역 내수침수 위험 |
| 예측 결과 | 현재 또는 가정 조건에서 계산한 미래 | 60분 뒤 저지대 도로 침수 예상 |
| 판단·권고 | 근거를 종합한 시스템 제안 | 도로 통제와 주민 대피 준비 권고 |
| 대응 실행 | 승인 뒤 수행한 업무 | 문자 발송, 펌프 확인, 도로 통제 요청 |
| 결과 기록 | 실행과 현장의 실제 결과 | 전파 성공, CCTV 실패, 유선 대체 보고 |

`이벤트`라는 단어로 위 객체를 모두 부르지 않는다. 화면과 데이터에서 가능한 한 정확한 객체명을 쓴다.

### 관측 이벤트가 사건이 되는 기준

모든 센서 알림을 재난 사건으로 만들지 않는다. 다음 순서로 사건 후보를 구성한다.

1. 원본값의 단위·시각·위치·품질을 확인한다.
2. 같은 장비의 반복 알림과 특보 갱신을 하나의 변화 흐름으로 묶는다.
3. 시간·공간·원인 관계가 가까운 관측을 기존 사건 후보에 연결한다.
4. 임계치, 변화율, 예측 초과, 영상 근거를 함께 제시한다.
5. 규칙이 충분하면 자동으로 사건 후보를 만들고, 담당자가 확인·병합·오탐 처리한다.

사건 후보가 만들어져도 원천 관측은 그대로 보존한다. 담당자의 확인 전에는 시스템 판단과 확인된
사실을 같은 상태로 표시하지 않는다.

### 연결 관계

```text
Incident
├── observations[]       여러 관측 이벤트
├── relatedIncidents[]   원인 · 파생 · 동시발생
├── affectedAreas[]      실제·예상 영향 범위
├── forecasts[]          생성 시각과 조건별 예측
├── decisions[]          권고 · 확인 · 승인
├── actions[]            SOP · 전파 · 시설 조치
└── outcomes[]           성공 · 실패 · 대체 · 현장 결과
```

- 여러 관측 이벤트가 하나의 재난 사건에 연결될 수 있다.
- 하나의 관측이 여러 지구 또는 사건에 영향을 줄 수 있다.
- 태풍→폭풍해일, 지진→지진해일처럼 사건끼리 원인·파생 관계를 가질 수 있다.
- 하나의 사건에 조건과 생성시각이 다른 예측 결과가 여러 개 쌓일 수 있다.

### 공간 범위

| 범위 | 의미 | 예시 |
|---|---|---|
| 지점 | 특정 센서·시설·좌표 중심 | 수위계 기준 초과, 배수문 장애 |
| 구역 | 하나 이상의 행정·위험·배수 구역 | 봉암 배수구역 내수침수 |
| 전역 | 시 전체 또는 광역 영향 | 태풍, 폭염특보, 지진 |

지도 표시용 `displayAnchor`와 실제 영향 범위 `affectedGeometry`를 분리한다. 전역 사건을 대표 지구의
사건으로 저장하지 않는다. 대표 핀은 화면 배치용 앵커일 뿐이다.

### 수집 데이터가 가져야 할 정보

- 출처와 원본 식별자
- 측정 항목·값·단위
- 관측 시각과 수집 시각
- 지점·구역·전역 공간 범위
- 정상·지연·결측·이상 품질 상태
- 갱신 주기
- 조회·저장·재배포·제어 권한

### 데이터 준비 상태

| 상태 | 뜻 | 데모 원칙 |
|---|---|---|
| 실연계 | 현재 API·센서에서 실제 수신 | 출처와 최신 시각 표시 |
| 연계 가능 | 키·경로는 있으나 미연결 | 목표 연계로 표시 |
| 협의 필요 | 시청·협력사 데이터 필요 | 모의 데이터 여부 표시 |
| 신청 필요 | 기관 승인·활용 신청 필요 | 확보 전제로 단정하지 않음 |
| 계산 | 수집값으로 CUVIA가 산출 | 계산 근거와 가정 표시 |
| 데모 모의 | 시나리오용 표본 | 실데이터처럼 주장하지 않음 |

목표 입력은 넓게 정의하되 “모두 받을 수 있다”고 가정하지 않는다. 데이터가 없을 때의 대체 상태도
함께 설계한다.

### 창원 도시침수 기준 데이터

2024 도시침수 완료보고에서 실제 연계 대상으로 확인되는 항목은 다음과 같다. 이는 **창원 측 기반과
사업 연계 범위의 근거**이며, 현재 데모 코드에 모두 연결됐다는 뜻은 아니다.

| 출처 | 확인된 입력·출력 | 연계 방식·주기 | Phase 2 활용 |
|---|---|---|---|
| 창원 재난상황 시스템 | 강우·하천·도로·관로 수위, 우수받이 거리, 유량·유속 | API/Socket, 기축 10분·신축 1분 | 현재 관측·상승률·교차검증 |
| CCTV | 실시간 영상·스틸컷 | RTSP 실시간, 스틸컷 1분 | 현장 확인·VLM 근거 |
| 창원 시설물 관리 | 우수저류조·배수펌프장·지하차도 및 하천진입 차단시설 | API 이벤트 | 배수 조건·상태 확인·승인 후 제어 요청 |
| 공공·수문 데이터 | AWS·ASOS·레이더·예측강우·하천수위·유량·조위 | Open API·DB·파일, 1~10분 또는 이벤트 | 원인 조건·외수위·예측 입력 |
| 도시침수 예측 | 최적 시나리오·실시간 침수예측·관로 예측 | DB/파일, 10분 또는 이벤트 | 기준 전망·영향 범위 |
| NDMS | 계측기 정보·차량 제어 정보 | API, 10분 | 상급기관 공유·연계 결과 확인 |

보고서 실증에서는 관로 만관 후 도로수위까지 약 30~40분의 예보 선행시간 가능성이 확인됐다. 동시에
지역 특화 모형, 센서와 CCTV의 공간 결합, 침수예측 대 실측 검증이 필요하다고 기록됐다. 따라서
Phase 2는 선행시간을 고정 성능으로 약속하지 않고 대표 사건에서 검증할 가설로 사용한다.

### 서로 섞지 않을 상태축

| 상태축 | 답하는 질문 | 예시 |
|---|---|---|
| 외부 특보 | 기관이 무엇을 발표했는가 | 호우주의보·폭풍해일주의보 |
| 관측 위험단계 | 센서값이 어느 기준을 넘었는가 | 정상·주의·경계·심각 |
| 사건 처리상태 | 담당 업무가 어디까지 갔는가 | 후보·확인중·대응중·종료·오탐 |
| 분석 상태 | 영향 검토가 어디까지 갔는가 | 자동 추정·상세 분석 필요·검토 완료 |
| 대응 결정 | 무엇을 승인했는가 | 모니터링·통제 준비·대피 승인 |
| 실행 결과 | 조치가 실제로 되었는가 | 성공·실패·대체조치·확인 대기 |
| 도시 대응단계 | 시 전체 운영 수준은 무엇인가 | 평시·비상 단계 |

특보 발표나 예측 결과만으로 관측 단계·사건 처리상태·도시 대응단계를 자동으로 같은 값에 맞추지 않는다.

### 사건 판단 원칙

- 단위·시간대·위치를 정규화하고 원본과 변환값을 함께 보존한다.
- 반복 알림과 갱신 특보를 실제 사건 수와 구분한다.
- 가능한 경우 센서·기상·시설·영상으로 교차검증한다.
- VLM과 위험도는 근거이며 담당자 확인 상태와 분리한다.
- 단계 변경의 원인이 된 관측과 규칙을 추적할 수 있어야 한다.

## 4. 이벤트 유형과 대표 사건

### 분류 기준

| 구분 | 정의 | 예시 |
|---|---|---|
| 입력 조건 | 다른 사건의 발생·확대를 설명 | 집중호우, 강풍, 무강우 지속 |
| 위험 상태 | 피해 전 감시·대비가 필요한 상태 | 산불위험, 저수율 저하, 지반변위 |
| 재난 사건 | 독립된 판단·대응·기록이 필요 | 내수침수, 하천범람, 산불, 지진 |
| 파생 사건 | 다른 사건이 원인이 된 별도 사건 | 태풍→폭풍해일, 지진→지진해일 |

관측 알림·위험 상태·재난 사건을 하나의 재난유형 도넛에 동일하게 집계하지 않는다.

### 대표 카탈로그

| 사건/상태 | 역할 | 대표 사건 | 주요 수집 이벤트 | 활용 | 데모 수준 |
|---|---|---|---|---|---|
| 내수침수 | 재난 사건 | 봉암 배수구역 침수 위험 | 강우·내/외수위·배수문·펌프·CCTV | 배수 조건별 침수·대응 예측 | **대표 데모** |
| 폭풍해일 | 재난 사건 | 서항 만조 중첩 위험 | 해안수위·조위·해일특보·강우 | 만조 시점 침수와 대피 대상 | 예상 시나리오 |
| 하천범람 | 재난 사건 | 창원천 월류 위험 | 하천수위·상류강우·유량·제방고 | 최초 월류 지점과 범람구역 | 예상 시나리오 |
| 태풍 | 원인 사건 | 태풍 창원 최근접 | 경로·기압·풍향·풍속·강우 | 해일·침수·강풍 파생 사건 연결 | 예상 시나리오 |
| 산불 | 재난 사건 | 정병산 산불 확산 | 발생좌표·풍향·풍속·습도·산림 | 시간별 확산과 대피구역 | 예상 시나리오 |
| 폭염 | 광역 위험/재난 | 창원 폭염 장기화 | 특보·기온·습도·체감온도·취약계층 | 지역별 노출과 쉼터 대응 | 예상 시나리오 |
| 저수율 저하 | 위험 상태 | 주남저수지 저수율 저하 | 저수율·수위·유입량·무강우일 | 공급 가능 기간과 제한급수 영향 | 예상 시나리오 |
| 지반변위 | 위험 상태 | 저수지 사면 변위 증가 | 변위·누적강우·토양수분·경사 | 붕괴 징후와 감시 강화 | 예상 시나리오 |
| 산사태 | 재난 사건 | 사면 붕괴 위험 | 지반변위·강우·토양수분·지형 | 붕괴 영향권과 대피구역 | 후보 |
| 지진 | 재난 사건 | 창원 영향 지진 | 진앙·규모·PGA·시설물 상태 | 즉시경보·자동조치·피해확인 | 관제 예시 |
| 지진해일 | 파생 사건 | 남해안 해일 도달 위험 | 진앙·규모·해일특보·도달시각 | 해안 도달과 침수·대피 예측 | 예상 시나리오 |

이 목록은 제품 방향 후보군이며 전부 구현한다는 약속이 아니다. 유형별로 독립된 사건인지, 다른
사건의 조건인지, 배경 위험인지 먼저 확정한다.

### 통계 원칙

- 지역별 관측값 여러 건을 재난 사건 여러 건으로 세지 않는다.
- 한 사건이 여러 지구에 영향을 줘도 사건 수는 하나다.
- 원인 사건과 파생 사건은 관계를 보존한다.
- 관측 알림 수, 사건 수, 대응 건수를 구분한다.
- 원장은 화면 밀도를 위한 임의 건수보다 관계 설명에 필요한 최소 표본을 사용한다.

## 5. 유형별 디지털트윈 구성

디지털트윈은 다음 질문을 다룬다.

> 현재 관측과 조건이 지속되거나 달라지면, 언제 어디까지 영향을 받고 누구에게 어떤 대응이 필요한가?

시설물 제어는 가능한 활용 중 하나다. 제어가 없다고 디지털트윈 전체를 부정하지 않으며, 실시간 연결과
예측이 없는 단순 3D 시각화도 디지털트윈이라고 과장하지 않는다.

기존 문서의 `현실 제어가 있어야만 디지털트윈`이라는 정의는 채택하지 않는다. Phase 2에서는
실제 상태 연결, 미래 예측, 조건 비교, 공간 영향, 근거 추적을 핵심으로 하고 현실 제어는 권한과 안전이
확보된 경우에만 추가한다.

### 공통 다섯 영역

| 영역 | 공통 질문 | 유형별 변화 |
|---|---|---|
| 공간 | 무엇이 어디에서 변하는가 | 수면·확산면·영향권·열 노출·시설 상태 |
| 조건 | 무엇을 비교할 수 있는가 | 강우·조위·배수·풍향·강도·지속시간 |
| 시간 | 언제 어떻게 변하는가 | 분·시간·일 또는 시간축 없음 |
| 결과 | 무엇을 얼마나 셀 것인가 | 면적·건물·도로·사람·공급일수·시설 위험 |
| 근거 | 결과를 왜 믿을 수 있는가 | 관측·모델·가정·출처·생성시각·오차 |

여기에 유형별 **의사결정 가능시간(리드타임)**을 함께 본다. 시간축의 단위가 같아도 담당자가 판단하고
실행할 수 있는 시간이 다르면 화면과 자동화 경계가 달라진다.

| 의사결정 가능시간 | 대표 유형 | 기본 처리 방식 |
|---|---|---|
| 주~달 | 저수율 저하 | 장기 전망·수요 조건 비교 |
| 일 | 폭염·태풍 | 지역별 영향과 준비 조치 |
| 수십 분~시간 | 침수·범람·폭풍해일·지진해일 | 담당자 판단·승인·선제 대응 |
| 분 | 산불 확산 | 빠른 확인과 즉시 대응 |
| 초 | 지진 흔들림 | 자동조치 후 결과 확인 |

### 참여 수준

| 수준 | 조건 | 표현 |
|---|---|---|
| A. 예측·대안 비교 | 현재 연결 + 미래 예측 + 조건 비교 | 완전한 트윈 시나리오 |
| B. 예측 시각화 | 현재 연결 + 미래 예측, 사용자 조건 없음 | 전망과 영향 중심 |
| C. 상태 모니터링 | 현재 연결, 신뢰할 예측 모델 없음 | 현재 공간 상태와 추세 |
| D. 즉시 대응 | 사람이 볼 리드타임이 없음 | 사건관제·자동조치 결과 |

### 유형별 차이

| 유형 | 수준 | 공간 표현 | 조건 | 시간축 | 핵심 결과 |
|---|---|---|---|---|---|
| 내수침수 | A | 고임 깊이·배수시설 | 강우·배수문·펌프·외수위 | 분~시간 | 침수구역·도로·건물·대피대상 |
| 폭풍해일 | A | 해안 침수면·침수선 | 조위·해일 편차·강우 | 시각 | 수위·침수면적·대피대상 |
| 하천범람 | A | 하천 수면·월류지점 | 상류강우·유입량·하구조위 | 분~시간 | 범람구역·제방구간·도로 |
| 태풍 | A | 중심경로·영향반경·파생영향 | 경로·강도·도달시각 | 시각 | 해일·침수·강풍 중첩지역 |
| 산불 | A | 풍향에 따른 확산면 | 풍향·풍속·습도 | 분~시간 | 소실면적·건물·대피구역 |
| 폭염 | B | 체감온도·취약계층·쉼터 | 예보 시나리오 | 일 | 노출인구·취약계층·쉼터 여력 |
| 저수율 저하 | B/A | 저수면·공급구역 | 유입량·수요·무강우 | 일~주 | 공급 가능일·제한급수 대상 |
| 지반변위 | C/B | 사면경사·변위 방향 | 강우·토양수분 | 일 | 변위 추세·감시 대상 |
| 산사태 | A | 붕괴 방향·영향권 | 토양수분·강우·붕괴점 | 분~시간 | 영향반경·건물·대피구역 |
| 지진 | D | 진앙·진도·시설 상태 | 없음 | 초 | 자동조치 결과·시설 점검 |
| 지진해일 | A | 파 도달·해안 침수면 | 진앙·규모·해저지형 | 분~시간 | 도달시각·침수범위·대피대상 |

### 예측의 네 상태

| 구분 | 의미 |
|---|---|
| 현재 관측 | 지금 실제로 받은 값 |
| 기준 전망 | 현재 조건이 유지될 때 시스템이 계산한 미래 |
| 대안 시나리오 | 사용자가 시설·기상 조건을 바꾼 비교 |
| 실제 결과 | 시간이 지난 뒤 확인한 관측 |

모든 예측은 생성시각·유효시각·입력 조건·모델 또는 규칙·가정을 함께 가진다.

### 분석 결과를 사건에 반영하는 경계

디지털트윈 결과는 사건의 `forecast/impact snapshot`으로 저장한다. 반영 뒤에는 권고 사유, 대응 대상,
통제 검토 구간, SOP 초안과 전파 문안을 구체화할 수 있다. 그러나 다음 값은 덮어쓰지 않는다.

- 실제 관측값과 관측 위험단계
- 사건 유형·최초 발생시각·원천 데이터
- 담당자가 승인한 대응 수준
- 이미 실행된 전파·통제 결과

트윈 검토는 필수 관문이 아니다. 긴급 시 담당자는 상세 분석 없이 대응을 승인할 수 있어야 한다.
사전 모의분석은 실제 사건·SOP·통계와 저장 영역을 분리한다.

## 6. 대표 데모 시나리오

### 기준안: 봉암 배수구역 내수침수

봉암은 강우·수위·시설·영상을 한 사건으로 연결할 수 있고, 배수문과 펌프 조건에 따라 결과가 달라져
디지털트윈의 대안 비교가 분명하다. 서항 폭풍해일은 대체 후보로 남긴다.

강우·관로·도로수위·CCTV·배수시설·침수예측의 조합은 창원 도시침수 완료보고에서 확인된다. 다만
`봉암`이라는 위치의 실제 장비·배수구역·임계치·모형값은 별도 확인 대상이다. 확인 전 수치와 결과는
데모 예시로만 사용한다.

### 전달 메시지

> 비가 많이 온다는 사실만 보여주는 것이 아니라, 물이 왜 빠지지 않는지 설명하고 조건별 침수 영향을
> 비교해 지금 필요한 대응을 결정한다.

### 입력 이벤트

| 입력 | 역할 | 상태 표기 |
|---|---|---|
| 시간당·누적 강우 | 유입 조건 | 실연계 또는 모의 |
| 배수구역 내수위 | 현재 위험 | 센서 시계열 |
| 하구 외수위·조위 | 자연 배수 가능 여부 | 연계 예정 또는 모의 |
| 배수문 개폐·통신 | 배출 조건 | 협의 또는 모의 |
| 펌프 가동 대수·용량 | 배출 조건 | 협의 또는 모의 |
| CCTV 영상·VLM | 현장 교차검증 | 영상 표본 + 분석 예시 |
| 취약도로·건물·인구 | 영향 산출 | 공간 레이어·계산 |

수치와 임계치는 공식·시 기준이 확정되기 전까지 `데모 예시값`으로 표시한다.

### 시연 흐름

| 단계 | 질문 | 보여줄 내용 | 행위 |
|---:|---|---|---|
| D0 | 어디가 먼저 위험한가 | 예측 강우와 배수 취약성으로 봉암 우선 표시 | 사건 후보 선택 |
| D1 | 무슨 사건이 생겼는가 | 강우·수위·시설 이벤트를 내수침수 사건으로 연결 | 사건 열기 |
| D2 | 현장도 같은가 | 센서·CCTV·VLM 근거와 데이터 품질 | 담당자 영상 확인 |
| D3 | 그대로 가면 어떻게 되는가 | 현재 조건 유지 기준 전망 | 트윈 진입 |
| D4 | 배수 조건을 바꾸면 달라지는가 | 배수문·펌프 조건 A/B 비교 | 대안 선택 |
| D5 | 누가 무엇의 영향을 받는가 | 침수구역·도로·건물·대피대상·예상시각 | 대응안 확인 |
| D6 | 무엇을 실행할 것인가 | 권고·SOP 초안·대상·문안·시설 요청 | 담당자 승인 |
| D7 | 결과는 무엇인가 | 채널별 성공·실패·대체조치·현장보고 | 결과 보완 |
| D8 | 예측은 맞았는가 | 예측 대 실제·판단 근거·이력·보고서 초안 | 검토 후 기록 |

### 시스템과 담당자

| 시스템 | 담당자 |
|---|---|
| 이벤트 수집·정규화 | 이상값·결측 확인 |
| 사건 후보와 관련 근거 구성 | 사건 확인·병합·오탐 판단 |
| VLM 문장과 신뢰도 제시 | 실제 영상 확인 |
| 전망·대안·영향 계산 | 조건과 결과 검토 |
| 권고·SOP·보고서 초안 | 승인·수정·실행·최종 확정 |

“전 과정을 자동 수행”이라고 표현하지 않는다. 되돌릴 수 없는 조치는 담당자가 승인한다.

### 완료 기준

- 모든 화면이 동일한 사건과 시나리오 시각을 공유한다.
- 원천 이벤트와 사건 판단이 구분된다.
- VLM 결과와 담당자 확인이 별도 상태다.
- 현재 관측·기준 전망·대안 전망·실제 결과가 구분된다.
- 영향 결과가 SOP 대상과 전파 문안에 연결된다.
- 실패와 대체조치가 기록된다.
- 마지막에 예측 검증과 보고서 초안이 남는다.

## 7. 화면과 IA 재편

### 목표 역할

| 영역 | 핵심 질문 | 주요 내용 |
|---|---|---|
| 종합상황 | 지금 무엇을 먼저 봐야 하는가 | 사건 우선순위·광역 위험·지도·데이터 상태 |
| 사건관제 | 왜 위험하고 무엇을 확인해야 하는가 | 사건·관측·영상·근거·관련 사건 |
| 디지털트윈 | 앞으로 어떻게 되고 대안은 무엇인가 | 기준 전망·조건 비교·영향·근거 |
| 대응 | 무엇을 결정하고 실행할 것인가 | 권고·승인·SOP·전파·시설 요청·결과 |
| 기록·분석 | 무엇을 예측했고 실제로 어떻게 되었는가 | 타임라인·검증·보고서·유사사례 |
| AI 보조 | 근거를 어떻게 빠르게 찾고 설명할 것인가 | 현재 맥락 질의·근거 링크·화면 이동 |

대응은 사건관제 안의 집중 작업공간으로 두는 기준안을 유지한다. 보고서는 기록·분석의 산출물로,
AI는 독립 사일로가 아닌 전역 보조 기능으로 둔다.

### Phase 1 화면 판정

| 현재 화면 | 판정 | Phase 2 방향 |
|---|---|---|
| SCR-01 종합상황 | 역할 유지·내용 재편 | 지구 나열보다 사건 우선순위와 데이터 상태 중심 |
| SCR-02 재난관제 | 역할 유지·대폭 재편 | 관측→사건→근거→확인의 주 작업공간 |
| SCR-02 대응 팝업 | 역할 유지·구조 재편 | 권고·승인·SOP·전파·결과 연결 |
| SCR-04 통계·분석 | 역할 확장 | 집계보다 예측 검증·보고서·유사사례 중심 |
| SCR-05 디지털트윈 | 역할 유지·대폭 재편 | 수위 고정 UI를 유형별 계약 구조로 변경 |
| SCR-06 AI 검색 | 독립 화면 재검토 | 전역 보조를 기본으로 하고 사후 질의는 기록과 통합 검토 |
| SCR-07 보고서 | 위치 재검토 | 별도 대메뉴보다 사건 기록의 생성·검토 결과 |

SCR 번호는 IA 확정 뒤 정리한다. 현재 번호 보존 자체를 목표로 삼지 않는다.

### 종합상황 원칙

경쟁사식 넓은 지표 표를 그대로 복제하지 않는다. 첫 질문은 “지표가 높은 곳이 어디인가”보다 “지금
무엇을 먼저 판단해야 하는가”다. 사건·사건 후보 우선순위, 광역 위험, 영향 범위, 데이터 장애를 먼저
보여주고 상세 지표표는 근거를 펼칠 때 사용한다.

### 대표 흐름

```text
종합상황
→ 봉암 사건관제
→ 센서·영상 교차확인
→ 디지털트윈 기준/대안 비교
→ 사건관제 대응 작업공간
→ 실행 결과
→ 기록·분석의 예측 검증과 보고서
```

대표 흐름은 사이드바 설명이 아니라 사건을 든 화면 안의 행동으로 이어진다.

## 9. 결정 상태

### 확정

- Phase 2는 기존 구현의 단순 확장이 아니다.
- 이벤트 수집·해석·활용 구조를 먼저 정한다.
- 전체 흐름은 대표 사건 한 건으로 보여준다.
- 나머지 유형은 대표 사건과 디지털트윈 차이로 보여준다.
- 기존 화면 외곽은 재사용할 수 있지만 내부는 재편할 수 있다.
- 현재 코드는 Phase 1 참고 구현이다.
- 기존 파생 문서는 필요한 내용을 흡수한 뒤 제거하고 원본 참고자료만 보존한다.
- 유형 수와 사건 수를 성공 기준으로 사용하지 않는다.

### 기준안

- 대표 데모 사건: 봉암 내수침수
- 공통 흐름: 수집→사건→판단→트윈→대응→기록
- 유형 카탈로그: 유형당 대표 사건 한 건
- 디지털트윈: 상태 연결·예측·조건 비교·영향 산출, 제어는 선택적 활용

### 미정

- 대표 데모를 봉암으로 최종 확정할지
- 폭염과 열돔의 명칭·관계
- 가뭄과 저수율 저하의 관계
- 지반변위와 산사태의 관계
- 산사태를 Phase 2 후보군에 포함할지
- 전역·구역 사건의 지도 표현
- 위험도 화면을 사건 우선 큐로 확정할지
- AI 독립 화면과 보고서 독립 화면을 유지할지

미정 항목은 본문을 임의로 확장하지 않고 사용자 결정 또는 근거 확인 뒤 이 절에서 닫는다.

## 10. 참고자료 사용 원칙

- 경쟁사 자료는 기능 후보와 업계 표현을 확인하는 근거다.
- 한 회사의 여러 자료를 시장 전체의 공통 기능으로 일반화하지 않는다.
- 경쟁사에 있다는 이유만으로 화면을 추가하지 않는다.
- 우리 대외 자료의 `자체 보유`, `파트너 연계`, `고도화 계획`, `개념`을 구분한다.
- VLM·자동 보고서·모의훈련·시설 제어는 실제 수준보다 강하게 주장하지 않는다.

### 대외 설명에서 바로잡을 표현

| 기존 표현 | 검토 결과 | Phase 2 표현 |
|---|---|---|
| 경쟁사는 센서 임계치 기반이고 VLM이 없다 | 지오멕스 자료에도 비전 AI·VLM AI 구조가 있음 | VLM 보유 여부가 아니라 사건 근거·사람 확인과의 연결로 비교 |
| 자동 보고서·기록은 CUVIA만 제공 | 경쟁사에도 보고서·이력·리포트 기능이 있음 | 사건 타임라인에서 초안을 자동 구성하고 근거까지 추적하는 방식으로 차별화 |
| 1~8단계를 전 과정 자동 수행 | 현재 데모와 자료로 입증되지 않으며 승인 경계와도 충돌 | 수집·분석은 자동화하되 되돌리기 어려운 조치는 담당자 승인 |
| 모의훈련·오탐 환류 학습을 자체 보유 | 제안·비전 외 구현 근거가 부족 | Phase 2 이후 후보 또는 개념 검증으로 표시 |
| 디지털트윈·예측을 자체 보유로 단정 | 회사·파트너·현재 데모의 보유 범위가 섞여 있음 | 자체 계산·파트너 연계·데모 모의를 분리 표기 |

현재 PPT는 제품 비전 자료로는 사용할 수 있지만 보유 기능 비교표와 독점 표현은 그대로 재사용하지 않는다.
원본 자료는 `docs/참고자료/`에서 확인한다.
