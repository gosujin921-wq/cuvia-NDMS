# CUVIA NDMS Phase 2 기능 및 정보구조도

> 상태: IA 기준안 - 재검수 잔여항목 반영 완료·엑셀 동기화 필요
>
> 기준일: 2026-09-10
>
> 역할: Phase 2의 업무 공간, 화면 역할, 정보 객체, 대표 데모 동선과 기존 화면 판정을 정의한다.

## 1. IA의 목적

이 문서는 기존 화면과 패널의 수를 다시 세는 목록이 아니다.

> **담당자가 하나의 사건을 발견하고, 근거를 확인하고, 미래 영향을 비교하고, 대응을 실행한 뒤 결과를
> 검증하는 흐름을 끊김 없이 지원하는 구조를 정의한다.**

상위 방향은 `README.md`, 이벤트와 사건의 의미는 `01_이벤트·사건모델.md`, 대표 사건의 내용은
`02_대표데모시나리오.md`, 유형별 트윈의 차이는 `03_유형별디지털트윈.md`를 따른다. 이 문서는 그
결과를 화면과 이동 구조로 바꾸는 역할만 한다.

## 2. IA 엑셀의 역할

`CUVIA_NDMS_기능및정보구조도.xlsx`는 이 MD의 내용을 업무 검토용 표로 옮긴 동기화본이다. `개요`,
`업무공간`, `정보구조도`, `트윈유형`, `데모동선`, `사건맥락`, `정보객체`, `공통상태`, `Phase1판정`,
`데모범위`의 10개 시트로 구성한다.

- 이 MD가 Phase 2 IA의 정본이며 엑셀과 값이 다르면 MD가 우선한다.
- 방향과 구조를 먼저 MD에서 수정한 뒤 엑셀에 같은 내용을 반영한다.
- `Phase1판정` 시트는 기존 자산의 재사용·재편 여부를 확인하는 표이며 Phase 1 화면 수를 승계하지 않는다.
- 기존 SCR 번호를 보존하기 위해 새 화면 역할을 끼워 맞추지 않는다.
- 엑셀의 행 수와 시트 수를 Phase 2 구현 목표로 사용하지 않는다.

## 3. IA 설계 원칙

1. **사건 중심:** 지구·센서·기능이 아니라 판단하고 대응할 사건이 이동의 기준이다.
2. **질문 중심:** 각 업무 공간은 담당자의 한 가지 핵심 질문에 답한다.
3. **공통 사건 맥락:** 사건 ID, 기준시각, 처리상태, 선택 예측판·영향공간·근거, 검토 중 결정,
   사건 시나리오 방식과 이벤트별 수집·시연 방식은 화면을 이동해도 유지한다.
4. **근거와 판단 분리:** 원천 관측, 분석 결과, 시스템 권고와 담당자 결정을 구분한다.
5. **현재와 미래 분리:** 현재 상태, 기준 전망, 대안 전망과 실제 결과를 섞지 않는다.
6. **공통 골격:** 재난유형마다 별도 메뉴와 화면을 복제하지 않는다.
7. **유형별 트윈:** 트윈의 입력·시간축·공간표현·결과만 유형에 맞게 달라진다.
8. **정직한 상태:** 연계 준비도, 시연 방식, 데이터 품질과 계산 주체를 표시한다.
9. **사람 승인:** 사건 확정, 병합·분리, 대응 승인과 종료는 담당자 행위로 남긴다.
10. **수량 비목표:** 화면·패널·재난유형 수를 Phase 2 성과로 사용하지 않는다.

## 6. IA-01 종합상황

### 역할

도시 전체를 한눈에 보여주는 대시보드가 아니라, 담당자가 **어떤 사건부터 확인할지 결정하는 진입점**이다.

### 필수 정보

| 영역 | 정보 | 원천 객체 |
|---|---|---|
| 감시 우선대상 | 예측·특보·취약성으로 선정한 구역·카메라·시설과 선정 근거 | Event·Forecast·AffectedArea |
| 사건 우선 큐 | 후보·확인중·확인됨·대응중·통제 사건, 긴급도, 심각도, 확실성, 경과시간 | Incident |
| 후보 근거 | 최초 징후, 연결 이벤트 수가 아닌 근거 종류, 추가 확인 필요사항 | Event·Incident |
| 공간 개요 | 현재·예상 영향권, 원인·파생 사건, 데이터 장애 위치 | Incident·AffectedArea |
| 광역 맥락 | 특보, 예측 변화, 도시 대응단계 | Event·Forecast·CityOperationalState |
| 데이터 상태 | 지연·결측·의심 원천과 영향받는 사건 | Event·Incident |

### 주요 행동

- 감시 우선대상 또는 사건·사건 후보 열기
- 담당자·상태·유형으로 우선 큐 필터링
- 데이터 장애가 영향을 주는 사건 확인
- 원인·파생 사건 묶음 펼치기

### 제외할 구성

- 지구 수와 사건 수를 같은 방식으로 집계한 도넛
- 모든 센서값을 동일 우선순위로 나열한 현황판
- 사건과 무관한 기상정보를 큰 카드로 고정 배치
- 전 지구 × 전 지표 신호등 표를 첫 화면의 중심으로 사용

## 7. IA-02 사건 작업공간

### 역할

사건 후보가 왜 만들어졌는지 확인하고, 담당자가 실제 사건 여부와 관계를 결정하는 중심 업무 공간이다.

### 공통 헤더

| 정보 | 내용 |
|---|---|
| 사건 식별 | 사건 ID, 제목, 재난유형, 공간 범위 |
| 처리 상태 | 후보·확인중·확인됨·대응중·통제·종료·오탐·병합됨 |
| 위험 판단 | 심각도·긴급도·확실성·추세를 독립 표시 |
| 시간 | 최초 관측, 사건 생성, 최신 갱신, 경과시간 |
| 담당 | 담당 조직·담당자·인계 상태 |
| 데이터 표시 | dataOrigin, 연계 준비도, 시연 방식, 품질, 계산 주체 |

### 내부 구성

#### 사건 개요

- 현재 상황 한 문장 요약
- 원인·악화·완화 요인
- 심각도·긴급도·확실성·추세와 반대 근거·불확실성·누락정보
- 실제·예상 영향 공간
- 원인·파생·동시 사건 관계
- 다음 확인 또는 결정이 필요한 항목

#### 관측 근거

- 강우·수위·조위·시설 등 시간 정렬
- 원천 관측과 임계치·변화율 파생 결과 분리
- 관측시각과 수신시각
- 결측·지연·의심·보정 상태
- 사건에 연결된 이유

#### 영상·현장

- 사건 주변 CCTV와 선택 영상
- VLM 분석 문장, 신뢰도, 모델·버전·분석시각
- 실제 영상과 분석 결과 병렬 확인
- 현장 보고·사진·통행 가능 여부

#### 상태·관계 이력

- 후보 생성·확인·오탐·병합·분리 기록
- 상태 변경 사유와 담당자
- 외부 기관 사건과의 관계

### 주요 행동

- `확인`, `추가 확인`, `오탐`
- 기존 사건에 병합 또는 별도 사건으로 분리
- 원인·파생·동시발생 관계 지정
- 이후 트윈·대응에서 유지할 관측·영상·분석 근거 선택
- 트윈 비교 열기
- 대응 검토 시작

## 8. IA-03 트윈 비교

### 역할

현재 상태와 미래 전망을 구분하고, 조건을 바꿨을 때 영향이 어떻게 달라지는지 비교한다.

### 공통 다섯 영역

| 영역 | 질문 | 필수 정보 |
|---|---|---|
| 현재 상태 | 지금 실제로 관측된 것은 무엇인가? | 관측값·시설상태·영상·품질·기준시각 |
| 기준 전망 | 현재 조건이 유지되면 어떻게 되는가? | 유효시간별 공간 결과·도달시간·강도 |
| 대안 전망 | 무엇을 바꾸었고 무엇이 달라지는가? | 변경 조건·기준 대비 차이 |
| 영향 결과 | 누가·어디가·언제 영향을 받는가? | 도로·건물·시설·대상·노출·중단 |
| 근거·한계 | 무엇으로 계산했고 어디까지 믿을 수 있는가? | 모델·버전·입력·가정·불확실성·결측 |

### 도시침수 대표 데모

- 배수권역·관로망·센서·CCTV 위치
- 현재 강우·관로·도로수위·조위·펌프·저류시설 가용성
- 시간대별 침수심·범위·도달시간
- 기준 전망과, 데이터가 있을 때의 배수·통제 대안
- 도로·건물·중요시설·대상자 영향
- 외부 모델 수신인지 CUVIA 계산인지 구분

### 주요 행동

- 기준 전망 선택과 유효시간별 결과 이동
- 지원되는 대안 조건 선택과 실행 요청, 또는 수신된 대안 예측판 선택
- 영향공간과 그 결과를 만든 근거 선택
- 기준 대비 차이와 불확실성 확인
- 선택한 예측판·영향공간을 유지한 채 대응 검토 시작

### 유형별 교체 영역

| 비교 기준안 | 공간 문법 | 시간축 | 핵심 결과 | 준비도 | Phase 2 표현 |
|---|---|---|---|---|---|
| C 해안 경계·월류 | 해안선·월류구간·저지대 | 만조 전후 | 월류시각·구간·침수 | R1 설계 | 계약과 미확보 조건 |
| D 이동 전선·확산 | 화선·플룸·풍하측 영향면 | 분·시간 이동 | 도달시간·대피방향 | R0 후보 | 정적 개념 예시 |
| F 지반·구조 영향 | 시설·사면·변위 벡터 | 즉시 또는 누적 | 사용 가능성·점검순서 | R0 후보 | 정적 개념 예시 |

R0 유형은 계산 결과 화면처럼 만들지 않는다. 필요한 입력·모델과 예상 출력의 차이를 설명하는 정적
개념 예시로만 표현한다.

R0~R3은 `03_유형별디지털트윈.md`의 데이터·모델·업무 준비도다. P0~P2는
`02_대표데모시나리오.md`의 자료 확인 우선순위다. 사건 처리상태 `통제`와 도로·시설 통제 Action은
이름이 같아도 서로 다른 값이다.

### 데이터가 없을 때

- 기준 전망이 없으면 예측을 가장하지 않고 필요한 모델·데이터를 표시한다.
- 제품 범위상 지원하지 않거나 실행하지 않은 대안은 `계산 미지원·미실행`, 필요한 입력이 없어 산출할 수
  없으면 `대안 계산 불가`, 실행 중 오류가 난 경우는 `계산 실패`로 구분한다.
- 실제 관측 비교가 없으면 검증 대기 상태와 필요한 결과를 표시한다.
- 임의 슬라이더로 침수면을 움직인 장면을 예측이라고 부르지 않는다.

## 9. IA-04 대응·실행

### 역할

예측과 영향 근거를 실제 결정, 승인, 전파·시설 요청과 결과로 연결한다.

### 내부 구성

| 영역 | 정보 |
|---|---|
| 판단 요약 | IA-02에서 확정한 위험판단과 영향, 불확실성·반대 근거의 대응용 요약 |
| 권고 | 권고 대응수준, 대상, 시점, 생성 근거 |
| SOP 초안 | 단계별 업무, 담당 조직, 자동/승인 구분 |
| 승인 | 선택안, 수정사항, 승인자·시각·사유 |
| 실행 | 전파(CAP 1.2 필드 구조)·도로통제·시설점검·운영 요청 |
| 결과 | 대기·진행중·성공·실패·미응답·확인대기·대체됨·취소 |

### 주요 행동

- 권고 검토·수정·기각
- SOP 항목 선택 및 담당 배정
- 전파 대상·지역·매체·문안 확인
- 시설 운영·점검 요청 승인
- 실패 건 재시도 또는 대체조치 기록
- 사건을 `대응중` 또는 `통제`로 전환

### 승인 경계

- 시스템은 권고·SOP·전파문·보고서 초안을 만들 수 있다.
- 사건 확정, 대응수준, 외부 전파와 시설 요청은 담당자가 승인한다.
- 실제 원격제어가 확인되지 않으면 `요청·승인·결과 확인`까지만 표현한다.
- 실행 실패를 성공으로 덮어쓰지 않고 실패와 대체조치를 각각 기록한다.

## 10. IA-05 기록·검증

### 역할

사건 진행과 판단 근거를 재구성하고 예측·대응의 실제 결과를 검토한다.

### 내부 구성

| 영역 | 정보 |
|---|---|
| 사건 타임라인 | 원천 이벤트, 사건 상태, 예측판, 결정, 실행과 현장 결과 |
| 주요 시간 | 최초 감지·후보 생성·확인·전파·조치·통제·종료 |
| 예측 검증 | 예측 대 실제, 과대·과소, 비교 불가 사유 |
| 대응 검토 | 대기·진행중·성공·실패·미응답·확인대기·대체됨·취소와 소요시간 |
| 보고서 | 상황보고서 초안, 근거 링크, 담당자 수정·확정 |
| 개선 항목 | 임계치·모델·데이터·SOP 검토 과제 |

### 주요 행동

- 사건 종료 또는 재개
- 예측판과 실제 관측 비교
- 누락 근거·결과 보완 요청
- 상황보고서 생성·수정·확정·내보내기
- 후속 개선 항목 등록
- 이 사건의 대응 이력으로 `대응 모의훈련` 시나리오 후보 생성 요청. 편집·실행은 IA-A01 범위

보고서는 독립된 대메뉴에서 새로 시작하는 업무가 아니라 사건 기록을 바탕으로 생성되는 결과물이다.

## 11. IA-G01 공통 AI 보조

### 역할

현재 사건과 화면의 근거를 요약하고 사용자를 해당 정보로 이동시킨다. 별도의 판단 결과를 만드는
독립 사일로로 두지 않는다.

### 허용 역할

- 현재 사건 요약과 누락 정보 안내
- 특정 판단에 사용된 관측·예측·SOP 근거 찾기
- 유사 사건·과거 결정 탐색
- 전파문·상황보고서 초안 작성
- 답변 근거가 있는 화면·이벤트·문서로 이동

### 제한

- 원천에 없는 사실 생성 금지
- 확실성·한계를 숨긴 단정 금지
- 담당자 승인 대행 금지
- 근거 링크 없는 위험도·대응 결론 금지

## 18. Phase 2 데모 범위

### 데모 구현 시 반드시 포함할 핵심

- 사건 우선 큐에서 대표 후보 진입
- 서로 다른 이벤트의 시간·공간·의미 연결 근거
- 담당자 사건 확인과 상태 전환
- 현재 상태와 기준 전망 분리
- 영향 근거를 대응안·전파·조치에 연결
- 승인과 시스템 권고 분리
- 실패·미응답·대체조치 기록
- 사건 타임라인과 결과 기록
- 실시간·재생·모의·수동 및 품질 표시
- 특보 헤더와 전파문의 CAP 1.2 필드 구조
- IA-05의 대응 모의훈련 시나리오 후보 진입점. 훈련 편집·실행 화면은 만들지 않음

### 데이터 확보 시 강화

- CCTV/VLM 결과와 실제 영상 교차확인
- 기준·대안 예측판 비교
- 영향 대상과 실제 SOP·전파문 연결
- 예측과 실제 관측의 오차 검증

정렬된 과거 자료와 실제 모델 결과가 없으면 A 유형은 R1을 유지한다. 이때 IA-03은 비활성 빈 화면으로
숨기지 않고 미확보 조건을 표시하며 모델 성능이나 대안 효과를 주장하지 않는다. 합성 결과임은 화면 배지가
아니라 사건 헤더의 데이터 상태 칩과 시연 대본이 든다.

### 대표 데모 밖

- 모든 유형의 동적 모델
- 실제 재난문자·시설 원격제어
- 임계치·SOP·사용자·권한 관리 전체 화면
- 대응 모의훈련 시나리오 편집·실행·예약 화면
- 대규모 운영 통계와 SLA
- R0 유형을 실제 계산하는 것처럼 보이는 화면

## 19. 화면 정의 완료 조건

각 화면 또는 작업영역은 다음 항목을 가져야 구현 대상으로 확정할 수 있다.

- 답할 사용자 질문
- 사용하는 공통 객체와 필드
- 진입 조건과 다음 행동
- 시스템 생성 정보와 담당자 결정의 구분
- 정상·빈·지연·결측·모의·실패 상태
- 데이터·모델·업무 근거와 준비도
- 대표 데모 포함 여부
- 기존 자산의 재사용·재편·제외 판정

## 20. 결정된 화면 기준과 남은 확인

다음은 현재 기준안에서 결정됐다.

- D0는 IA-01의 감시 우선대상에서 시작하고, D1에 생성된 후보가 사건 우선 큐에 나타나면 IA-02로 연다.
- AI 보조는 공통 근거 탐색·요약으로 두며 독립 판단 사일로로 만들지 않는다.
- 보고서는 IA-05에서 사건 기록으로 생성하는 산출물로 둔다.
- P0 자료 확인 전 IA-03은 합성 예측면으로 흐름을 보여주고, 실제 모델 결과가 아님은 시연 대본이 밝힌다.
- IA-02는 Phase 1 지구 재난관제 팝업의 개요 고정·탭 골조를 유지하고 내용을 사건 개요·근거·영상·관계
  이력 중심으로 재편한다.
- IA-03은 사건 맥락을 유지하는 독립 페이지로 열고, IA-04 대응은 사건 화면 안 팝업으로 둔다.
- IA-05는 상시 접근 가능한 독립 페이지로 두되 대표 데모의 주 동선에서는 D8에 진입한다.
- C·D·F 비교는 IA-03 유형 전환으로 제시하고 R0인 D·F는 정적 개념 예시와 필요한 근거만 보여준다.
- IA-05의 대응 이력은 후속 `대응 모의훈련` 시나리오의 입력이 될 수 있다. 훈련 편집·실행은 운영 관리
  범위이자 대표 데모 밖이며, 훈련 조건을 트윈의 `사전 조건분석` 진입점으로 연결할 수 있다.

남은 확인은 다음 두 가지다.

1. Phase 1 경로를 재사용할 때 IA-03 독립 페이지의 최종 URL과 사건 ID 전달 방식을 구현 설계에서 확정한다.
2. 실제 기관의 메뉴 권한과 운영 절차를 확인해 IA-05 상시 접근 권한과 훈련 관리 책임 조직을 정한다.

## 21. IA 완료 기준

- 다섯 업무 공간이 각각 하나의 핵심 질문에 답한다.
- 대표 데모 D0~D8이 사건의 다음 행동으로 끊김 없이 연결된다.
- 사건 ID, 기준시각, 처리상태, 선택 예측판·영향공간·근거, 검토 중 결정, 사건 시나리오 방식과
  이벤트별 dataOrigin·수집·시연 방식이 화면 이동 중 유지된다.
- 원천 이벤트, 분석 결과, 권고, 결정, 실행과 결과가 구분된다.
- 재난유형별 화면 복제 없이 공통 골격과 트윈 차이를 설명할 수 있다.
- 데이터가 없는 상태에서도 허위 결과 대신 필요한 연계와 한계를 보여준다.
- Phase 1 자산의 유지·재편·통합·제외·보류 판단이 기록돼 있다.
- 대표 데모와 후속 제품 범위가 구분돼 있다.
