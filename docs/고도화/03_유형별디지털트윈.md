# CUVIA Phase 2 유형별 디지털트윈 설계

> 상태: 기준안 - 재검수 잔여항목 반영 완료·계산 제공 주체 확인 필요
>
> 기준일: 2026-09-10
>
> 적용 원칙: 재난명별 화면을 늘리지 않고, 계산·시간·공간·의사결정 방식이 달라지는 유형군으로 설계한다.

## 1. 이 문서가 답하는 질문

이 문서는 모든 재난의 전체 대응 시나리오를 반복해서 작성하지 않는다. 공통 사건 흐름은
`01_이벤트·사건모델.md`, 전체 시연 흐름은 `02_대표데모시나리오.md`에서 정의한다.

여기서는 다음 질문에 답한다.

> **사건 유형이 달라질 때 디지털트윈이 무엇을 입력받고, 어떤 시간·공간 변화를 계산하거나 받아서,
> 담당자의 어떤 결정을 도와야 하는가?**

따라서 `호우`, `태풍`, `침수`처럼 행정적 재난명을 메뉴로 나열하는 대신, 실제 트윈의 동작이 달라지는
유형군을 먼저 정의하고 개별 재난을 연결한다.

## 2. 디지털트윈의 제품 정의

CUVIA의 디지털트윈은 3D 지도를 뜻하지 않는다.

> **사건 시점의 관측 상태와 기준 데이터를 공간에 정렬하고, 조건을 유지하거나 바꿨을 때의 미래 상태와
> 영향을 비교해 대응 결정을 지원하는 사건별 작업 공간이다.**

모든 유형의 트윈은 다음 다섯 질문에 답해야 한다.

1. 지금 무엇이 관측됐는가?
2. 현재 조건이 유지되면 언제, 어디까지, 어느 정도 변하는가?
3. 어떤 조건이나 대응을 바꾸어 비교할 수 있는가?
4. 사람·시설·도로·지역에 어떤 영향이 예상되는가?
5. 이 결과는 어떤 데이터·모델·가정으로 만들었고 한계는 무엇인가?

외부 기관이나 협력사 모델이 계산한 결과를 받는 경우에도 CUVIA는 입력 근거, 결과 버전, 사건 연결,
영향 해석과 대응 기록을 관리한다. 자체 계산과 외부 결과 수신을 같은 기능으로 표현하지 않는다.

제품 경험의 방향은 CUVIA 안에서 기준·대안 계산을 요청하고 결과를 비교하는 것이다. 다만 계산 엔진의
기술 소유·운영 주체가 자사인지 협력사인지 현재 자료가 엇갈리므로, 확인 전에는 `자사 보유 기술` 또는
`협력사 제공 기능`으로 단정하지 않는다. 실제 결과가 없을 때 사용하는 시나리오 Forecast의 계산 주체와
교체 대상은 내부 계약에서 관리하며, 기본 제품 UI에는 제작 구분이나 면책 문구를 노출하지 않는다.

## 3. 유형군 분류 기준

유형군은 다음 항목 중 하나 이상이 실질적으로 달라질 때 분리한다.

- **상태 변수:** 수심, 유량, 농도, 온도, 화선, 변위, 서비스 가용성 등
- **전파 방식:** 지형을 따른 흐름, 바람을 따른 확산, 면 단위 노출, 지반·구조 반응, 네트워크 파급
- **시간축:** 분 단위 급변, 시간 단위 확산, 일 단위 누적과 회복
- **공간 단위:** 배수권역, 하천 구간, 해안대, 확산면, 행정·격자 구역, 시설·네트워크
- **대안 조건:** 펌프·수문 운영, 통제 시점, 대피권역, 자원 배치, 우회·복구 순서
- **핵심 결과:** 도달시간·침수심, 범람 범위, 농도·노출, 손상·사용 가능성, 서비스 중단과 파급

같은 재난명도 사건의 원인과 필요한 판단에 따라 둘 이상의 유형군을 결합할 수 있다. 예를 들어 태풍은
기본적으로 하나의 트윈 유형이나 자동 생성 사건이 아니라 도시침수, 해안 월류, 시설·구조 영향과
기반시설 장애를 촉발하는 상위 기상 조건이다. 다만 시 전체 태풍 대응처럼 별도 담당 조직·조치·처리상태가
필요한 경우에만 상위 Incident로 만들고 개별 영향 사건과 관계를 연결한다.

## 4. 공통 트윈 계약

유형별 계산은 달라도 화면과 기록은 다음 계약을 공유한다.

| 구분 | 필수 내용 |
|---|---|
| 사건 연결 | 사건 ID, 유형, 공간 범위, 상태, 담당 조직 |
| 기준시각 | 원천 관측·수신시각, 예측 기준·생성·유효시각 |
| 현재 상태 | 원천 관측, 품질·결측·지연, 기준 데이터 |
| 기준 전망 | 조건을 바꾸지 않았을 때의 시간별 결과 |
| 대안 전망 | 변경한 조건과 기준 전망 대비 차이 |
| 영향 결과 | 영향 객체, 도달시간, 강도·노출·중단 정도 |
| 근거 | 데이터 출처, 모델명·버전, 파라미터와 가정 |
| 불확실성 | 신뢰구간 또는 등급, 민감 조건, 사용할 수 없는 구간 |
| 결정 연결 | 권고, 담당자 선택, 승인, 실행 요청과 결과 |
| 검증 | 예측판과 실제 관측 비교, 오차와 사후 개선 항목 |
| 구현 추적성 | 연계 준비도, 수집·시연 방식, 데이터 품질, 계산 주체와 실개발 교체 대상 |

이는 공간·시간에 따라 환경 데이터를 조회하는 [OGC API EDR](https://docs.ogc.org/is/19-086r6/19-086r6.html),
현실 객체의 속성과 관계를 표현하는 [ETSI NGSI-LD](https://cim.etsi.org/NGSI-LD/official/introduction.html),
위험지식·관측/예측·전파·대응을 잇는 [WMO Early Warnings for All](https://wmo.int/all-activities/build-resilience/early-warnings-all)의
구조를 CUVIA 사건 업무에 맞게 적용한 기준이다. 특정 표준의 전체 구현을 의미하지는 않는다.

이 공통 계약은 A~G 모든 유형에 그대로 적용한다. 아래 유형별 표의 `적용 사건`은 사건 연결,
`시간축`은 기준시각, `대응 활용`은 결정 연결, `근거·한계`와 `검증`은 같은 이름의 공통 항목을
유형에 맞게 구체화한다. 유형 표에서 반복하지 않은 담당 조직·승인·실행 결과와 구현 추적성도 생략되는
것이 아니라 공통 계약을 상속한다.

## 5. Phase 2 트윈 유형군

| 유형군 | 상태 변수·전파 방식 | 시간·공간 문법 | 핵심 결과·대응 활용 | Phase 2 문서 역할 |
|---|---|---|---|---|
| A. 도시 배수·침수 | 지표·관로 수위·침수심이 지형·배수망을 따라 흐름 | 분 단위, 배수권역·관로망·침수면 | 통제·배수·전파 시점 | **대표 데모** |
| B. 하천 흐름·범람 | 수위·유량·범람이 상류에서 하류로 전파 | 분·시간, 하천 종단·구간·범람면 | 하천 접근통제·대피권역 | 확장 설계 |
| C. 해안 경계·월류 | 조위·파랑이 해안 경계를 넘어 저지대로 월류 | 만조 전후, 해안선·저지대·방호시설 | 해안통제·대피·시설 보호 | 비교 설계 |
| D. 이동 전선·확산 | 화선·농도가 바람과 지형을 따라 방향성 있게 이동 | 분·시간, 전선·플룸·풍하측 영향면 | 대피방향·차단선·자원배치 | 비교 개념 |
| E. 대기·면 노출 | 기상·대기 강도가 면에 누적되고 취약성과 결합 | 시간·일, 격자·행정구역·취약대상 | 보호시설·순회·행동권고 | 장기 후보 |
| F. 지반·구조 영향 | 진동·변위·경사가 시설·사면의 사용 가능성으로 반응 | 즉시·누적, 시설·사면·영향권 | 출입통제·점검·대피 | 비교 개념 |
| G. 기반시설·네트워크 장애 | 시설 중단이 의존 연결을 따라 서비스로 파급 | 장애~복구, 시설 노드·연결망·서비스권역 | 우회·복구 우선순위 | 공통 파생 설계 |

Phase 2에서 일곱 유형군 모두의 모델과 화면을 구현한다는 뜻이 아니다. A 유형을 대표 데모로 깊게
설계하고 C·D·F는 서로 다른 트윈 문법을 보여주는 비교 기준안으로 둔다. B는 확장 설계, E는 장기 후보로 남기고,
G는 다른 사건에서 발생하는 파생 장애로 공통 적용한다. 데이터·모델이 없는 유형은 예상 시나리오를
설명할 뿐 계산이 가능한 기능으로 표현하지 않는다.

`Phase 2 역할`은 문서와 데모에서 어디까지 다룰지를 뜻하며 R0~R3 준비도가 아니다.

- `대표 데모`: 사건의 시작부터 결과 기록까지 한 흐름으로 구현한다.
- `비교 설계`: 유형 차이와 필요한 계약·화면 구조를 비교하되 계산 결과를 주장하지 않는다.
- `비교 개념`: 입력·시간·공간·예상 출력 구조만 정적으로 설명한다.
- `확장 설계`: 가치와 계약은 정의하지만 Phase 2 비교 장면에는 넣지 않는다.
- `장기 후보`: 추가 근거를 확보하기 전에는 상세 화면을 설계하지 않는다.
- `공통 파생 설계`: 독립 비교 화면보다 다른 사건과의 관계·의존 구조로 적용한다.

## 6. A. 도시 배수·침수 트윈

### 적용 사건

- 내수침수, 지하차도 침수, 저지대 도로·건물 침수
- 높은 조위나 하천수위로 배수가 제약되는 복합침수

### 트윈 계약

| 항목 | 내용 |
|---|---|
| 상태 변수·전파 | 강우·관로·도로수위, 침수심과 배수 여유가 지형·관로망을 따라 변화 |
| 주요 입력 | 강우 관측·예측, 관로·도로수위, 조위, 지형, 배수구역, 관로망, 펌프·저류시설 상태, CCTV |
| 시간축 | 현재, 10·30·60분 등 단기 예측, 종료 후 실제 비교 |
| 공간 표현 | 배수권역, 관로 흐름, 도로·건물별 침수심, 시간대별 침수면. 3D 지형·건물 위에 표시 |
| 기준 전망 | 현재 강우·조위·시설 가용성이 유지되는 경우 |
| 대안 조건 | 펌프 가용성, 배수·저류 조건, 통제 시점 |
| 핵심 결과 | 최초 침수 예상시각, 최대 침수심, 지속시간, 영향 도로·건물·시설·대상자 |
| 대응 활용 | 선제 통제, 배수시설 요청, 지역 전파, 현장 점검 |
| 근거·한계 | 센서·CCTV·예측판의 공간·시각 정렬, 강우·조위·시설 입력의 품질과 모델 적용 범위 |
| 검증 | 시간대별 예측 침수심·도달시간을 도로수위·영상·현장 결과와 비교 |

`24년도시침수 완료보고_20250325_v1.0.pdf`는 창원의 강우·하천수위·우수받이 기축 API·신축 Socket,
도로·관로수위와 유량·유속 신축 Socket, CCTV와 배수시설 연계 대상(p.18-19)을 확인할 수 있는 가장 강한
원본 근거다. 조위는 p.18 창원 연계 항목이 아니라 침수 모형의 관측·예측 입력으로 확인된다(p.39).
다만 센서와 CCTV의 공간 결합, 지역 특화와 예측 대 실측 검증은 보완 과제로 남아 있다(p.60-62).

### 확인 조건

- 동일 배수권역의 센서·CCTV·펌프·저류시설과 예측판 식별자
- 기준·대안 예측판의 모델·버전·기준시각·유효시간·공간 결과
- 도로·건물·인구·취약대상 기준 데이터의 기준일·공간 단위·사용 권한
- 실제 통제·배수시설 요청 기준과 승인 절차
- 예측과 비교할 도로수위·영상·현장 결과

### 표현하지 말아야 할 것

- 임의 수위 슬라이더만 움직이고 이를 예측 결과라고 부르는 화면
- 관측 수위, 예측 침수심과 담당자 입력을 같은 레이어로 표시하는 화면
- 실제 펌프 제어 연계가 확인되지 않았는데 원격제어가 완료된 것처럼 보이는 시연

## 7. B. 하천 흐름·범람 트윈

### 적용 사건

- 하천수위 상승, 제방 월류·붕괴 위험, 하천변 도로·친수공간 침수

### 트윈 계약

| 항목 | 내용 |
|---|---|
| 상태 변수·전파 | 수위·유량·제방 여유와 범람이 상류에서 하류 구간으로 이동 |
| 주요 입력 | 상·하류 강우, 하천수위·유량, 댐·보 방류, 단면·제방, 지형, 예측강우 |
| 시간축 | 상류 변화부터 하류 도달까지 분·시간 단위 |
| 공간 표현 | 하천 종단도, 관측소 간 구간, 좌·우안 범람면과 도달시간 |

## 14. 복합재난을 다루는 방식

복합재난을 한 화면에 모든 레이어를 올리는 방식으로 정의하지 않는다.

```text
상위 조건: 태풍·집중호우
├─ 악화 사건 또는 조건: 독립 고장 기준을 충족한 펌프 장애·가용성 저하
├─ 주 대응 사건: 창원 검증 배수권역 복합침수 위험
└─ 파생 사건: 침수로 발생한 도로 단절·펌프 중단·통신 장애
```

- 태풍·집중호우는 기본적으로 기상·특보 이벤트와 사건 조건으로 연결한다. 시 전체 대응처럼 독립 담당·조치·
  처리상태가 필요할 때만 상위 사건으로 만들며 자동으로 Incident를 생성하지 않는다.
- 사건마다 주 유형군, 공간 범위, 담당 조직과 상태를 가진다.
- 동일 이벤트를 여러 사건이 참조할 수 있지만 원천 이벤트를 복제하지 않는다.
- 원인·동시·파생 관계를 표시하고, 사건을 병합해 책임과 상태를 잃지 않는다.
- 종합상황에서는 사건 간 영향과 공통 대응만 요약한다.
- 세부 트윈에서는 해당 사건의 계산·근거·대안에 집중한다.

## 15. 데이터·모델 준비도 관리

재난유형을 지원한다고 표현하려면 화면이 아니라 데이터와 계산 근거가 있어야 한다.

## 16. 대표 데모와 나머지 유형의 표현 범위

### 대표 데모: A 도시 배수·침수

- 이벤트 수집부터 사건 생성, 교차확인, 기준 전망, 대응과 결과 기록까지 핵심 데모 흐름을 구현한다.
- 정렬된 자료와 실제 모델이 없으면 R1을 유지한다. 예측면의 계산 주체·시연 방식과 교체 대상은 내부 계약이
  들고 기본 제품 UI에는 제작 면책을 두지 않는다.
- 대안 전망과 실제 대비 검증은 필요한 데이터를 확보했을 때 강화한다.
- dataOrigin, 연계 준비도, 수집·시연 방식, 데이터 품질과 계산 주체를 구분한다.
- `02_대표데모시나리오.md`의 창원 도시침수 기준안을 사용하고 서항은 적용 후보로 둔다.

### 나머지 유형군

- 전체 업무 흐름을 복제하지 않는다.
- 유형별로 `주요 입력`, `시간·공간 표현`, `핵심 결과`, `대안 조건`이 어떻게 다른지만 비교 가능하게 한다.
- 데이터나 모델이 없으면 결과를 생성하지 않고 필요한 연계와 준비도만 표시한다.
- 향후 실제 사업 대상과 데이터가 정해질 때 독립 사건 시나리오로 확장한다.

### Phase 2 비교 기준안

대표 데모 외에는 다음 세 유형을 IA-03의 유형 전환으로 비교하되, 준비도에 따라 표현 깊이를 달리한다.

| 비교 기준안 | 선정 이유 | 보여줄 차이 | 표현 수준 |
|---|---|---|---|
| C 해안 경계·월류 | 대표 사건의 조위를 `도시침수 경계조건`과 `별도 해안 예측`으로 구분해 제품·외부 모델의 경계를 설명 | 배수권역이 아닌 해안선·월류구간·만조 시간축 | `R1 설계`. Phase 1 서항 자산과 시나리오 Forecast로 시간 조절·대안 선택이 동작하는 예측 화면을 보여준다. 계산 주체·교체 대상은 내부 관리 |
| D 이동 전선·확산 | 물과 전혀 다른 방향성·이동 경계를 보여 제품 확장성을 설명. 대표 사례 산불 | 화선·연기·풍하측 도달시간·대피방향 | `R0 후보`, 정적 개념 예시만 표현 |
| F 지반·구조 영향 | 연속 면보다 시설 사용 가능성·점검 우선순위가 중심인 유형 | 시설·사면별 상태, 변위, 출입통제와 점검 | `R0 후보`, 정적 개념 예시만 표현 |

- B 하천 흐름·범람은 A와 전파·공간 문법이 다르지만 대상 하천·모델·SOP가 모두 미확정이다. Phase 2의
  비교 수를 제한하고 C에서 대표 사건과 외부 모델의 경계를 먼저 설명하기 위해 확장 설계에 남긴다.
  C의 조위·전용 모델 자료를 확보하지 못하면 B를 자동 대체하지 않고 두 유형의 근거를 다시 비교한다.
- E 대기·면 노출은 취약대상 데이터의 권한과 공식 지표가 확인될 때 비교 후보로 올린다.
- G 기반시설·네트워크 장애는 독립 비교 장면보다 A·C·D·F 사건에서 발생하는 파생 사건과 복구
  구조로 공통 적용한다. R1에서는 의존관계와 필요한 복구 판단만 보여주며 계산된 복구 우선순위 값은
  제시하지 않는다.

대안은 세 수준을 구분한다. `물리 재계산`은 모델 입력 조건을 바꿔 위험 결과를 다시 계산하고,
`영향 재계산`은 같은 위험 결과에 통제 시점·노출 대상을 바꿔 영향을 다시 산출한다. `운영 비교`는
위험·영향을 재계산하지 않고 조치 순서·담당·자원안의 차이를 비교한다.

불확실성은 도달시간·침수심 등의 `구간`을 기본으로 하고, 담당자 화면에는 이를 요약한 등급을 함께
표시한다. 확률값은 앙상블 계산과 산출 근거가 있을 때만 사용한다.

이 구성은 `대표 사건 1건 + 서로 다른 트윈 문법 3건`을 보여주기 위한 기준안이지 구현 수량 목표가
아니다. 자료 확인 결과에 따라 비교 기준안을 줄이는 것은 가능하지만 근거 없이 늘리지 않는다.

## 17. IA에 반영할 공통 구조

유형별 트윈은 별도 메뉴를 만들지 않고 IA의 화면 안에서 역할을 나눈다. 대응 모의훈련만 메뉴다.

| IA-02 사건 작업공간 | 사건 개요, 상태·담당 조직, 관측 근거, 품질과 원인·악화·파생 관계 |

| IA-T01 대응 모의훈련 | D8에서 후속 진입. 일정이 허용하면 A 시나리오를 선택 에필로그에서 실행 |

유형군에 따라 IA-03의 상태 변수·전파·시각화와 판단 항목만 교체한다. C·D·F는 IA-03의 유형 전환으로
보여주며, R0인 D·F는 계산 화면 대신 정적 개념 예시가 뜬다. 사건 ID, 기준시각, 처리상태,
선택 예측판, 영향공간, 선택 근거와 검토 중 결정은 제품 화면의 사건 맥락으로 유지한다. 사건 시나리오 방식과
이벤트별 dataOrigin·수집·시연 방식은 화면 이동 중 내부 사건 맥락과 계약으로 유지하되, 제작 구분을 위한
표시를 기본 제품 UI에 노출하지 않는다.

`README.md` §8.3의 `사전 조건분석`은 이 문서의 대안 전망 계약을 그대로 사용한다. 사건에서 열든 A 대응
모의훈련의 조건으로 열든 계산 계약과 근거·불확실성 구조는 같다. D8 진입점은 대표 데모에 포함하고 목록·실행은
일정이 허용할 때 선택 에필로그로 구현한다. 편집·예약과 C 유형 훈련은 후속 범위다.

2. 도시침수 계산 기술과 결과의 제공 주체를 자사 보유·협력사 제공 중 무엇으로 대외 표기하며, CUVIA가
   직접 실행할 범위와 외부 모델을 수신할 범위는 어디까지인가?
3. 실제 대상 기관의 재난분류와 이 유형군을 어떤 매핑 테이블로 연결할 것인가?

## 19. 완료 기준

- 행정적 재난명과 트윈 계산 유형이 구분된다.
- 각 유형군의 입력, 상태 변수, 시간축, 공간 표현, 결과와 대응 활용이 정의된다.
- 준비도, Phase 2 역할, 수집·시연 방식과 계산 주체가 구분된다.
- 한 사건이 여러 유형군과 결합될 때 원인·파생 관계가 유지된다.
- 대표 데모와 장기 후보의 구현 범위가 구분된다.
- 데이터·모델이 없는 유형을 구현된 기능처럼 표현하지 않는다.
- IA가 재난유형별 화면 복제가 아니라 공통 사건 구조와 유형별 트윈 차이를 반영할 수 있다.
