# CUVIA Phase 2 유형별 디지털트윈 설계

> 상태: 기준안 - 2026-09-15 제2부(유형별 표현) 통합·사용자 검토 반영. 2026-09-16 §2·§15·§16·§17·§18·§25·§26 을 모의훈련 기준(README §2.3)으로 고침. 계산 제공 주체 확인 필요
>
> 기준일: 2026-09-15 (계약 표 §6~§12 · 준비도 §15 는 2026-09-10 판)
>
> 적용 원칙: 재난명별 화면을 늘리지 않고, 계산·시간·공간·의사결정 방식이 달라지는 유형군으로 설계한다.

## 1. 이 문서가 답하는 질문

이 문서는 두 부로 나뉜다. 제1부(§1~§19)는 유형별 계약, 제2부(§20~§30, 부록 A·B)는 그 계약이 화면에서 어떻게 보이는가다.
이 문서는 모든 재난의 전체 대응 시나리오를 반복해서 작성하지 않는다. 공통 사건 흐름은
`01_이벤트·사건모델.md`, 전체 시연 흐름은 `02_대표데모시나리오.md`에서 정의한다.

여기서는 다음 질문에 답한다.

> **사건 유형이 달라질 때 디지털트윈이 무엇을 입력받고, 어떤 시간·공간 변화를 계산하거나 받아서,
> 담당자의 어떤 결정을 도와야 하는가?**

따라서 `호우`, `태풍`, `침수`처럼 행정적 재난명을 메뉴로 나열하는 대신, 실제 트윈의 동작이 달라지는
유형군을 먼저 정의하고 개별 재난을 연결한다.

## 2. 디지털트윈의 제품 정의

CUVIA의 디지털트윈은 3D 지도를 뜻하지 않는다.

> **관측 상태와 기준 데이터를 공간에 정렬하고, 조건을 유지하거나 바꿨을 때의 미래 상태와 영향을 비교해
> 대응 결정을 지원하는 지도의 상태다.** 사건 작업공간 안에서는 그 사건의 예측판(전망 탭)으로 열리고, 모의훈련에서는
> 지난 사건에서 출발한 시나리오 위에서 열린다. 두 자리가 같은 부품을 쓴다(제2부 · §25).

모든 유형의 트윈은 다음 다섯 질문에 답해야 한다.

1. 지금 무엇이 관측됐는가?
2. 현재 조건이 유지되면 언제, 어디까지, 어느 정도 변하는가?
3. 어떤 조건이나 대응을 바꾸어 비교할 수 있는가?
4. 사람·시설·도로·지역에 어떤 영향이 예상되는가?
5. 이 결과는 어떤 데이터·모델·가정으로 만들었고 한계는 무엇인가?

외부 기관이나 협력사 모델이 계산한 결과를 받는 경우에도 CUVIA는 입력 근거, 결과 버전, 사건 연결,
영향 해석과 대응 기록을 관리한다. 자체 계산과 외부 결과 수신을 같은 기능으로 표현하지 않는다.

제품 경험의 방향은 CUVIA 안에서 기준·대안 계산을 요청하고 결과를 비교하는 것이다. 다만 계산 엔진의
기술 소유·운영 주체가 자사인지 협력사인지 현재 자료가 엇갈리므로, 확인 전에는 `자사 보유 기술` 또는
`협력사 제공 기능`으로 단정하지 않는다. 실제 결과가 없을 때 사용하는 시나리오 Forecast의 계산 주체와
교체 대상은 내부 계약에서 관리하며, 기본 제품 UI에는 제작 구분이나 면책 문구를 노출하지 않는다.

## 3. 유형군 분류 기준

유형군은 다음 항목 중 하나 이상이 실질적으로 달라질 때 분리한다.

- **상태 변수:** 수심, 유량, 농도, 온도, 화선, 변위, 서비스 가용성 등
- **전파 방식:** 지형을 따른 흐름, 바람을 따른 확산, 면 단위 노출, 지반·구조 반응, 네트워크 파급
- **시간축:** 분 단위 급변, 시간 단위 확산, 일 단위 누적과 회복
- **공간 단위:** 배수권역, 하천 구간, 해안대, 확산면, 행정·격자 구역, 시설·네트워크
- **대안 조건:** 펌프·수문 운영, 통제 시점, 대피권역, 자원 배치, 우회·복구 순서
- **핵심 결과:** 도달시간·침수심, 범람 범위, 농도·노출, 손상·사용 가능성, 서비스 중단과 파급

같은 재난명도 사건의 원인과 필요한 판단에 따라 둘 이상의 유형군을 결합할 수 있다. 예를 들어 태풍은
기본적으로 하나의 트윈 유형이나 자동 생성 사건이 아니라 도시침수, 해안 월류, 시설·구조 영향과
기반시설 장애를 촉발하는 상위 기상 조건이다. 다만 시 전체 태풍 대응처럼 별도 담당 조직·조치·처리상태가
필요한 경우에만 상위 Incident로 만들고 개별 영향 사건과 관계를 연결한다.

## 4. 공통 트윈 계약

유형별 계산은 달라도 화면과 기록은 다음 계약을 공유한다.

| 구분 | 필수 내용 |
|---|---|
| 사건 연결 | 사건 ID, 유형, 공간 범위, 상태, 담당 조직 |
| 기준시각 | 원천 관측·수신시각, 예측 기준·생성·유효시각 |
| 현재 상태 | 원천 관측, 품질·결측·지연, 기준 데이터 |
| 기준 전망 | 조건을 바꾸지 않았을 때의 시간별 결과 |
| 대안 전망 | 변경한 조건과 기준 전망 대비 차이 |
| 영향 결과 | 영향 객체, 도달시간, 강도·노출·중단 정도 |
| 근거 | 데이터 출처, 모델명·버전, 파라미터와 가정 |
| 불확실성 | 신뢰구간 또는 등급, 민감 조건, 사용할 수 없는 구간 |
| 결정 연결 | 권고, 담당자 선택, 승인, 실행 요청과 결과 |
| 검증 | 예측판과 실제 관측 비교, 오차와 사후 개선 항목 |
| 구현 추적성 | 연계 준비도, 수집·시연 방식, 데이터 품질, 계산 주체와 실개발 교체 대상 |

이는 공간·시간에 따라 환경 데이터를 조회하는 [OGC API EDR](https://docs.ogc.org/is/19-086r6/19-086r6.html),
현실 객체의 속성과 관계를 표현하는 [ETSI NGSI-LD](https://cim.etsi.org/NGSI-LD/official/introduction.html),
위험지식·관측/예측·전파·대응을 잇는 [WMO Early Warnings for All](https://wmo.int/all-activities/build-resilience/early-warnings-all)의
구조를 CUVIA 사건 업무에 맞게 적용한 기준이다. 특정 표준의 전체 구현을 의미하지는 않는다.

이 공통 계약은 A~G 모든 유형에 그대로 적용한다. 아래 유형별 표의 `적용 사건`은 사건 연결,
`시간축`은 기준시각, `대응 활용`은 결정 연결, `근거·한계`와 `검증`은 같은 이름의 공통 항목을
유형에 맞게 구체화한다. 유형 표에서 반복하지 않은 담당 조직·승인·실행 결과와 구현 추적성도 생략되는
것이 아니라 공통 계약을 상속한다.

## 5. Phase 2 트윈 유형군

| 유형군 | 재난명(화면) | 상태 변수·전파 방식 | 시간·공간 문법 | 핵심 결과·대응 활용 | 화면에서 보여줄 차이 | Phase 2 역할 |
|---|---|---|---|---|---|---|
| A. 도시 배수·침수 | 도시침수 | 지표·관로 수위·침수심이 지형·배수망을 따라 흐름 | 분 단위, 배수권역·관로망·침수면 | 통제·배수·전파 시점 | 배수권역 안의 침수면·침수심 | **대표 데모** · 진행 중 사건 |
| B. 하천 흐름·범람 | 하천범람 | 수위·유량·범람이 상류에서 하류로 전파 | 분·시간, 하천 종단·구간·범람면 | 하천 접근통제·대피권역 | 관측소 순서, 상류 → 하류 도달시간, 종단도, 고립 구역 | 지난 사건 |

| E. 대기·면 노출 | 폭염 | 기상·대기 강도가 면에 누적되고 취약성과 결합 | 시간·일, 격자·행정구역·취약대상 | 보호시설·순회·행동권고 | 격자 노출·취약성·쉼터 공백, 광역 열돔 인셋 | 지난 사건 |
| F. 지반·구조 영향 | 급경사지 | 진동·변위·경사가 시설·사면의 사용 가능성으로 반응 | 즉시·누적, 시설·사면·영향권 | 출입통제·점검·대피 | 변위 벡터, 시설 상태, 통제 경계 | 지난 사건 |
| G. 기반시설·네트워크 장애 | 기반시설 장애 | 시설 중단이 의존 연결을 따라 서비스로 파급 | 장애~복구, 시설 노드·연결망·서비스권역 | 우회·복구 우선순위 | 계통도, 노드 꺼짐·켜짐, 중단 권역, 복구 순서 | 지난 사건 (파생 성격) |

Phase 2에서 일곱 유형군 모두의 모델을 구현한다는 뜻이 아니다. A 유형만 사건의 시작부터 결과 기록까지 한 흐름으로
구현하고(대표 데모), 나머지는 디지털트윈의 **지난 사건**으로 세워 서로 다른 트윈 문법이 지도에서 다르게 보이고 대응을 바꾼 결과가
비교되는 것까지 만든다(2026-09-16 사용자 "C~G 장면 … 지난 사건으로 넣으면 되잖아"). 데이터·모델이 없는 유형의 장면은 계산이 아니라
사전 작성 시나리오이며, 계산이 가능한 기능으로 표현하지 않는다.

`Phase 2 역할`은 데모에서 어디까지 다루는지를 뜻하며 R0~R3 준비도가 아니다.

- `대표 데모`: 사건의 시작부터 결과 기록까지 한 흐름으로 구현한다. 디지털트윈에서는 진행 중 사건으로 선다.
- `지난 사건`: 과거 종료 사건 하나를 세운다. 원장의 주요 시점 셋 · 실제 대응 · 실제 대응 기준 예측판 · 대응을 일찍 한 대안 예측판을 두고,
  분석 시점·시간 조절·대응 비교·분석 결과 저장이 동작한다(§26). 날짜·시각·대상 수는 시나리오 편집값이며 실제 사건 기록이 아니다.
- `파생 성격`: 다른 사건의 악화·파생으로 이어질 수 있는 유형이다(G). 2026-09-16 에 독립 지난 사건으로 세웠다.
- 2026-09-15 의 `조건 세트`·`비교 설계`·`개념 장면`·`개념 예시` 역할은 사건 없는 시뮬레이션과 함께 걷었다(2026-09-16).

앞서 `확인 대기`로 둔 세 자리(B 메뉴 유형 유지 · E 격자 노출 장면 · G 독립 대 A 파생)는 2026-09-16 C~G 를 지난 사건으로 세우며 닫았다.
B 는 창원천, E 는 도심 생활권 격자, G 는 서항 펌프장 정전 파급이 각자 지난 사건으로 선다.

## 6. A. 도시 배수·침수 트윈

### 적용 사건

- 내수침수, 지하차도 침수, 저지대 도로·건물 침수
- 높은 조위나 하천수위로 배수가 제약되는 복합침수

### 트윈 계약

| 항목 | 내용 |
|---|---|
| 상태 변수·전파 | 강우·관로·도로수위, 침수심과 배수 여유가 지형·관로망을 따라 변화 |
| 주요 입력 | 강우 관측·예측, 관로·도로수위, 조위, 지형, 배수구역, 관로망, 펌프·저류시설 상태, CCTV |
| 시간축 | 현재, 10·30·60분 등 단기 예측, 종료 후 실제 비교 |
| 공간 표현 | 배수권역, 관로 흐름, 도로·건물별 침수심, 시간대별 침수면. 3D 지형·건물 위에 표시 |
| 기준 전망 | 현재 강우·조위·시설 가용성이 유지되는 경우 |
| 대안 조건 | 펌프 가용성, 배수·저류 조건, 통제 시점 |
| 핵심 결과 | 최초 침수 예상시각, 최대 침수심, 지속시간, 영향 도로·건물·시설·대상자 |
| 대응 활용 | 선제 통제, 배수시설 요청, 지역 전파, 현장 점검 |
| 근거·한계 | 센서·CCTV·예측판의 공간·시각 정렬, 강우·조위·시설 입력의 품질과 모델 적용 범위 |

| 검증 | 예상 파급·복구시간을 실제 중단 권역·복구 순서·정상화 시각과 비교 |

이 유형은 독립 재난으로도 쓰이지만 다른 사건의 **악화 또는 파생 사건**으로 연결하는 것이 중요하다.
펌프 가용성 저하는 우선 복합침수 사건의 입력·악화 조건이다. 펌프 고장이 별도 담당 조직·조치·처리상태를
가져야 할 때만 G 사건으로 분리해 복합침수 사건과 `악화` 관계를 맺는다. 반대로 침수 때문에 펌프·도로·통신이
중단된 경우도 같은 조건을 충족할 때만 G 사건을 분리하고 `파생` 관계를 맺는다. 그 전까지는 주 사건의
영향·결과로 기록한다.

### 확인 조건

- 시설·서비스 간 의존관계와 서비스권역
- 장애·복구 상태의 제공 주체와 갱신 규칙
- 복구 예상시간 산정 주체와 대체자원 가용성
- 독립 사건으로 분리할 담당 조직·조치·처리상태 기준

## 14. 복합재난을 다루는 방식

복합재난을 한 화면에 모든 레이어를 올리는 방식으로 정의하지 않는다.

```text
상위 조건: 태풍·집중호우
├─ 악화 사건 또는 조건: 독립 고장 기준을 충족한 펌프 장애·가용성 저하
├─ 주 대응 사건: 창원 검증 배수권역 복합침수 위험
└─ 파생 사건: 침수로 발생한 도로 단절·펌프 중단·통신 장애
```

- 태풍·집중호우는 기본적으로 기상·특보 이벤트와 사건 조건으로 연결한다. 시 전체 대응처럼 독립 담당·조치·
  처리상태가 필요할 때만 상위 사건으로 만들며 자동으로 Incident를 생성하지 않는다.
- 사건마다 주 유형군, 공간 범위, 담당 조직과 상태를 가진다.
- 동일 이벤트를 여러 사건이 참조할 수 있지만 원천 이벤트를 복제하지 않는다.
- 원인·동시·파생 관계를 표시하고, 사건을 병합해 책임과 상태를 잃지 않는다.
- 종합상황에서는 사건 간 영향과 공통 대응만 요약한다.
- 세부 트윈에서는 해당 사건의 계산·근거·대안에 집중한다.

## 15. 데이터·모델 준비도 관리

재난유형을 지원한다고 표현하려면 화면이 아니라 데이터와 계산 근거가 있어야 한다.

| 등급 | 의미 | 기획·대외 설명 기준 |
|---|---|---|
| R3 검증 | 실제 연계·모델·관측 비교와 운영 절차가 확인됨 | 검증 결과와 한계를 포함한 운영 표현 |
| R2 시연 | 실제 원본 자료와 실제 모델로 전체 흐름을 시연 가능 | 확인된 계산 주체와 모델 근거에 맞춰 설명 |
| R1 설계 | 필요한 입력·출력·연계 주체는 정의됐으나 계산·연계가 미완료 | 목표 제품 경험으로 시연하되 검증된 모델 성능이나 운영 실적으로 주장하지 않음 |
| R0 후보 | 활용 가치만 있고 데이터·모델·업무 근거가 부족함 | 정적 개념 예시와 필요한 근거만 표현 |

R0~R3은 데이터·모델·업무 근거의 준비도다. `대표 데모·비교 설계·비교 개념·확장 설계·장기 후보·
공통 파생 설계`는 Phase 2에서의 문서 역할이며 별도 축이다. 또한 이벤트의 `실시간·재생·모의·수동`은
수집·시연 방식, `CUVIA 계산·외부 모델 수신·해당 없음`은 계산 주체이므로 준비도에 섞지 않는다.
R0~R3, 수집·시연 방식과 계산 주체는 기획·데이터 계약·대외 메시지의 정확성을 관리하는 기준이며,
기본 제품 UI에 준비도 배지나 제작 면책으로 노출하는 값이 아니다.

현재 판단은 다음과 같다.

타사 자료는 가능한 표현과 업계 기본 수준을 파악하는 참고 자료다. 타사 화면에 존재한다는 이유만으로
CUVIA의 준비도를 올리지 않는다.

데모에서 유형별로 어떤 값을 실제 공개데이터로 붙이고 어떤 장면을 시나리오로 만드는지는 제2부 §22의
"데이터와 표현 역할" 표가 유형마다 든다. 원칙은 하나다. 실데이터는 현재 조건의 근거로, 시나리오는 미래 장면으로 쓰고,
실제 모델 결과가 아닌 장면을 예측 모델 결과처럼 표현하지 않는다. 실데이터 후보의 현행 명세 확인은 README §10에 둔다.

## 16. 대표 데모와 나머지 유형의 표현 범위

### 대표 데모: A 도시 배수·침수

- 이벤트 수집부터 사건 생성, 교차확인, 기준 전망, 대응과 결과 기록까지 핵심 데모 흐름을 구현한다.
- 정렬된 자료와 실제 모델이 없으면 R1을 유지한다. 예측면의 계산 주체·시연 방식과 교체 대상은 내부 계약이
  들고 기본 제품 UI에는 제작 면책을 두지 않는다.
- 대안 전망과 실제 대비 검증은 필요한 데이터를 확보했을 때 강화한다.
- dataOrigin, 연계 준비도, 수집·시연 방식, 데이터 품질과 계산 주체를 구분한다.
- `02_대표데모시나리오.md`의 창원 도시침수 기준안을 사용하고 서항은 적용 후보로 둔다.

### 나머지 유형군

- 전체 업무 흐름을 복제하지 않는다.
- 유형별로 `주요 입력`, `시간·공간 표현`, `핵심 결과`, `대안 조건`이 어떻게 다른지만 비교 가능하게 한다.
- 데이터나 모델이 없으면 계산 결과를 만들지 않는다. 사전 작성 예측판으로 세운 지난 사건으로 보이며, 준비도는 화면이 아니라 §15가 든다(§20).
- 향후 실제 사업 대상과 데이터가 정해질 때 독립 사건 시나리오로 확장한다.

### 표현 범위와 대안 수준 (2026-09-15 갱신)

앞선 "C·D·F 세 유형을 IA-03 유형 전환으로 비교한다"는 기준안을 대체한다. 유형은 사건 트윈 안에서 갈아타는 것이 아니라
모의훈련의 지난 사건 목록에서 사건을 고르면 정해진다(2026-09-16). 어느 유형을 Phase 2에 보일지는 README §6.1에서 다시 정한다. 유형별 역할과 화면에서 보여줄 차이는 §5 표 한 곳이 든다.

- C 는 대표 사건의 조위를 `도시침수 경계조건`과 `별도 해안 예측`으로 구분해 제품·외부 모델의 경계를 설명하는 비교 설계다. R1 설계이며
  계산 주체·교체 대상은 내부 관리한다. B 는 대상 하천·모델·SOP 미확정이라 R1 을 유지한다. D·F 는 R0 이고 변위·화선은 시나리오다.
  G 는 R1 이되 의존관계가 미확정이다.
- 유형별 장면이 지도·보조뷰·우측 레일에서 어떻게 서는지, 대안의 성격(현상 감소 / 노출 감소), 데모에서 무엇을 실데이터로 쓰고
  무엇을 시나리오로 만드는지는 제2부 §22가 든다.
- G 는 §12대로 파생 성격이지만 2026-09-16 독립 지난 사건(서항 펌프장 정전 파급)으로 세웠다. 대응은 비상전원 투입(현상 감소)과
  순회 자원(노출 감소)이고, 복구 순서는 계산된 우선순위 값을 제시하지 않으므로 대응 선택지로 두지 않았다.

대안은 세 수준을 구분한다. `물리 재계산`은 모델 입력 조건을 바꿔 위험 결과를 다시 계산하고,
`영향 재계산`은 같은 위험 결과에 통제 시점·노출 대상을 바꿔 영향을 다시 산출한다. `운영 비교`는
위험·영향을 재계산하지 않고 조치 순서·담당·자원안의 차이를 비교한다. 화면에서는 이것이 "현상을 줄이는 대안"(물리 재계산)과
"노출을 줄이는 대안"(영향 재계산·운영 비교)으로 보인다(§20).

불확실성은 도달시간·침수심 등의 `구간`을 기본으로 하고, 담당자 화면에는 이를 요약한 등급을 함께
표시한다. 확률값은 앙상블 계산과 산출 근거가 있을 때만 사용한다.

이 구성은 `대표 사건 1건 + 서로 다른 트윈 문법`을 보여주기 위한 기준안이지 구현 수량 목표가 아니다. 자료 확인 결과에 따라
줄이는 것은 가능하지만 근거 없이 늘리지 않는다.

  상류가 먼저 기준을 넘고 하류가 뒤따르는 모양이 그대로 선다. 하구가 마산만 만조(18:24, 서항과 같은 날 같은 만)와 겹치면 합류부로 되밀리는 것도 A·C 와 이어진다.

## 17. IA에 반영할 공통 구조

유형마다 메뉴를 만들지 않는다. 트윈이 쓰이는 메뉴는 사건 작업공간(전망 탭)과 `모의훈련` 둘이고 유형은 사건이 정한다(2026-09-16 · README §2.3).
진행 중 사건의 기준 전망과 대안 비교는 전망 탭이, 지난 사건에서 조건·대응·유형 결합을 바꿔 돌려 보는 일은 모의훈련이 맡는다(§25·§26).
2026-09-15의 "별도 모의훈련 모드는 없다"와 같은 날 앞선 "디지털트윈 = 사건 기반 대응 What-if"를 고친다. 사건 안에서는 IA 화면이 역할을 나눈다.

| IA 화면 | 유형별 트윈에서의 역할 |
|---|---|
| IA-01 종합상황 | 도시 전체 감시 우선순위와 서로 관련된 사건·파생 장애 요약 |
| IA-02 사건 작업공간 | 사건 개요, 상태·담당 조직, 관측 근거, 품질과 원인·악화·파생 관계 |
| IA-03 디지털트윈 | 사건 작업공간 안에서 예측 이벤트를 눌러 여는 전망 화면. 기준 전망(그대로 두면)과 대안 비교(대응 유형·시작 시점), 영향 대상, 시간 조절과 근거·한계. [이 전망으로 조치안 갱신]으로 대응 팝업에 넘긴다 |
| IA-04 대응·실행 | 영향 근거에서 권고·SOP·승인·전파·조치와 채널·현장 결과로 연결 |
| IA-05 기록·검증 | 예측판·결정·실행의 감사 기록. 사건이 끝나면 예측 케이스(예측판 + 실제 관측 + 실제 대응 + 실제 결과)로 오차와 개선 항목을 쌓는다 |
| 모의훈련 메뉴 | 지난 사건에서 시나리오를 만들고 조건·대응·유형 결합을 바꿔 돌려 본 뒤 개선 항목을 남긴다. 분석 결과를 저장·다시 열기·보고서로 뽑는다(§25·§26). 대응 실행(IA-04)과 예측 검증(IA-05)은 하지 않는다 |

유형군에 따라 트윈의 상태 변수·전파·시각화와 판단 항목만 교체한다. 트윈의 유형은 사건이 정한다(§16). 사건 ID, 기준시각, 처리상태,
선택 예측판, 영향공간, 선택 근거와 검토 중 결정은 제품 화면의 사건 맥락으로 유지한다. 사건 시나리오 방식과
이벤트별 dataOrigin·수집·시연 방식은 화면 이동 중 내부 사건 맥락과 계약으로 유지하되, 제작 구분을 위한
표시를 기본 제품 UI에 노출하지 않는다.

`README.md` §8.3의 대안 분석은 이 문서의 대안 전망 계약을 그대로 사용한다. 진행 중 사건에서 열든 지난 사건에서 열든
계산 계약과 근거·불확실성 구조는 같다. D8 은 기록·검증의 예측 케이스 확정 자리다(IA §13.1). 종료된 사건은 모의훈련의 지난 사건 목록에 선다.
지난 사건을 모의훈련 시나리오로 넘기는 진입점의 Phase 2 포함 여부는 README §6.1에서 정한다.

- 한 사건이 여러 유형군과 결합될 때 원인·파생 관계가 유지된다.
- 대표 데모와 장기 후보의 구현 범위가 구분된다.
- 데이터·모델이 없는 유형을 구현된 기능처럼 표현하지 않는다.
- IA가 재난유형별 화면 복제가 아니라 공통 사건 구조와 유형별 트윈 차이를 반영할 수 있다.

## 20. 공통 표현 원칙

모든 유형은 같은 화면 골격을 쓰되 **영향을 표현하는 방식은 유형마다 달라야 한다.** 화면에서 반드시 보여야 하는 것은 넷이다.

1. 현재 조건: 어떤 상황을 보고 있는가
2. 현재 시각의 영향: 지금 지도에서 어디가 어떻게 변하는가
3. 시간 변화: 시간이 지나면 영향이 어디로 이동·확대·누적되는가
4. 대안 비교: 대응했을 때 현상 자체 또는 노출 대상이 어떻게 달라지는가

원칙

- 모든 유형을 색 면(폴리곤) 확대 하나로 표현하지 않는다. 재난의 성격에 따라 면 · 선 · 방향 · 격자 · 노드·연결 · 보조 분석뷰를 조합한다.
- 대안은 두 성격이다. **현상을 줄이는 대응**(배수·방류·차수·진압)은 영향 면·강도 자체가 달라진다. **노출을 줄이는 대응**(통제·대피·쉼터·출입통제)은
  현상은 그대로이고 도로·시설·사람의 상태만 달라진다. 모든 대안에서 영향 면을 억지로 줄이지 않는다.
- 시간을 옮기면 지도와 우측 영향 결과는 같은 시각을 보여준다. 한 프레임에 함께 바뀐다.
- 광역 원인이 장면 이해에 도움이 되는 유형은 광역 인셋을 쓴다(§23).
- 화면에는 재난명(도시침수·하천범람·해안월류·산불·폭염·급경사지·기반시설 장애)을 쓴다. A~G 표현 유형명은 문서에서 차이를 설명할 때만 쓴다.
- 값은 사전 작성 예측판이다. 입력값에서 계산하지 않는다. 대안 예측판이 없는 분석 시점은 목록에 `대안 없음`으로 서고, 대응 버튼 대신 그 이유를 적는다.
- 눈금값만 판단에 쓴다. 눈금 사이 값은 만들지 않는다(IA §8).
- 준비도(R0~R3)와 문서 역할은 화면에 배지로 올리지 않는다(§15).

### 데모 데이터의 역할 구분

**실데이터는 현재 조건의 근거로 쓰고, 시나리오는 미래 장면을 설명하는 데 쓴다.** 실제 모델 결과가 아닌 장면을 `예측 모델 결과`처럼 표현하지 않는다.

| 구분 | 역할 | 예 |
|---|---|---|
| 실제 관측·공개데이터 | 현재 상황과 조건의 근거 | 강우, 수위, 풍향, 기온, 파고, 산사태 예측정보 |
| 데모 시나리오 | 미래 영향 장면 | 침수면, 범람면, 화선, 변위, 장애 전파 |
| 화면 동적 생성 | 실제 값과 시나리오를 보기 쉽게 연결 | 풍향 화살표, 연기 플룸, 상태 변화, 경로, 강조 |
| 정적 공간정보 | 변하지 않는 배경·취약성 | 위험지도, 시설 위치, 쉼터, 하천·해안선 |

화면에서는 출처보다 관계가 먼저 보여야 한다. 원인/조건 → 영향의 방향 또는 범위 → 영향받는 대상 → 시간 → 대응 효과.
실제 값 때문에 데모 구조를 끌려가지 않는다. 실제 데이터는 장면의 근거를 강화하는 데 쓴다.

공통 인터랙션

- **시간 칩**: 지도의 영향 표현이 그 시각으로 바뀌고, 우측 결론 한 줄과 달라지는 것도 같은 시각으로 바뀐다.
- **대응**: 현상을 줄이는 대응이면 영향 범위·강도가 변한다. 노출을 줄이는 대응이면 범위는 유지되고 도로·시설·대상 상태가 바뀐다. 누른 대응을 다시 누르면 기준으로 돌아간다.
- **분석 시점 변경**(종료 사건): 그 시점의 상태·기준 전망·대응 선택지로 바뀌고 고르던 대응은 풀린다.
- **준비되지 않은 조합**: 대안 예측판이 없는 시점은 대응 버튼 대신 이유를 적는다. 대안 예측판이 없는 사건은 전망 탭의 대안 비교가 닫히고 그 이유가 한 줄로 선다.


## 22. 유형별 표현

각 유형은 같은 틀로 적는다. 재난명과 표현 성격, 핵심 메커니즘, 데이터와 표현 역할, 지도(와 보조뷰), 시간을 이동하면, 대안을 선택하면,
우측 핵심 지표, 광역 인셋, 데모에서 만들 것과 문구, 표현 핵심. 유형 계약의 출처는 §6~§12다.

### A. 도시 배수·침수 (§6)

**재난명** 도시침수 · **표현 성격** 물이 배수권역 안에서 차오르고 빠지는 유형

**핵심 메커니즘.** 비가 많이 오는 장면이 아니라, 배수 능력을 넘어선 물이 저지대에 차오르고 도로·지하차도·건물로 퍼지는 과정. 지도에서 가장 중요한 것은 침수면 + 침수심 + 영향 대상이다.

| 요소 | 사용 방식 | 화면 표현 |
|---|---|---|
| 현재/예보 강우 | 실제 기상 데이터 | 강우 수치·강우 레이어 |
| 레이더 강수영역 | 실제 데이터 | 광역 인셋 또는 지도 상단 레이어 |
| 수위계·강우계 | 실제 또는 데모 지점 | 센서 핀·값 |
| 조위 | 현행 해양데이터 연계 또는 시나리오 | 조위 곡선·만조 시각 |
| 배수권역 | 정적 공간정보 | 점선 경계 |
| 미래 침수면·침수심 | 데모 시나리오 | 시간별 반투명 물 면, 면의 농도·수면 높이 |
| 펌프장·저류시설 | 시설정보 또는 데모 | 시설 핀·가동 상태 |
| 대피소 | 시설정보 | 대피소 핀 |
| 도로 통제 | 데모 시나리오 | 도로 상태 변경 |

**지도.** 3D 지형·건물 위에 배수권역 외곽선. 그 안에 침수면(침수심이 깊을수록 진함). 수위계·강우계·CCTV 핀, 펌프장·저류시설 핀, 대피소.
얕은 침수는 투명도가 높고 옅게, 깊은 침수는 진하게. 3D면 수면 높이도 조금씩 올려 깊이 차이를 느끼게 한다. 도로 위 침수는 도로 세그먼트 상태도
같이 바꾸고, 건물은 전체를 칠하기보다 저층부·바닥 접점을 강조한다. 침수심 범례는 화면에 유지한다.

**시간을 이동하면.** 침수면이 저지대 → 도로 → 지하차도 진입부 → 저지대 건물로 넓어진다. 강우가 약해지고 조위가 내려가는 시나리오에서는 침수면이 줄어드는 장면까지 보여줄 수 있다. 강우가 이어지거나 배수가 나쁘면 만조가 지나도 빠지지 않는다.
침수면 · 침수심 · 영향 도로 · 영향 시설 넷이 같이 움직인다.

**대안을 선택하면.** 배수 대응(펌프·저류): 침수면이 작아지고 침수심 표현이 옅어지며 일부 도로 영향이 풀린다. 도로 통제: 침수면은 그대로, 해당 도로와 이용 대상만 `통제됨`.
배수는 현상을 바꾸고 통제는 노출을 바꾼다. 통제는 점선 하나로 끝내지 않는다 — 구간 양 끝 차단 지점, 우회로, 통제 완료 시각 대 도달 시각의 여유("통제 완료 17:50 · 도달 2분 전")가 같이 서야 "언제 통제하나"가 읽힌다. 통제 완료 전 눈금에서는 도로가 아직 열려 있다.

**우측 핵심 지표.** 최대 침수심 m. 보조: 주요 지점 도달 예상 시각, 영향 도로·건물 수.
도달 시각의 뜻은 대상 종류가 정한다 — 도로는 통행 지장 시작(차로 침수), 시설·건물은 침수 도달, 대상자는 노출 시작. 물고임은 도달이 아니다. 예측 범위 안에 도달이 없는 대안(사전 방류 등)은 "통행 지장 없음 · 예측 범위 안"으로 말하고 대상 상태는 `영향 없음`이다(통제됨과 다르다).

**광역 인셋.** 강우 레이더, 예측강우 격자, 해안 지역이면 조위 곡선. 메인은 배수권역 안의 침수 결과만.

**데모에서 만들 것.** 시간별 침수 폴리곤 4~5장, 시간별 최대 침수심, 도로·지하차도 영향 상태, 펌프 가동 후 대안 폴리곤, 도로 통제 상태.
실제 강우값을 붙여도 침수면이 실제 수리·수문 모델 결과가 아니면 `실시간 침수 예측`으로 표현하지 않는다. 문구는 `침수 전망 · 시나리오 영향 · 예상 영향 범위`.

**데모 한 문장.** 강우가 강하고 만조가 겹치면 40분 뒤 해안도로가 잠기고, 펌프를 가동하면 최대 침수심이 0.41 m에서 0.22 m로 준다.

**표현 핵심.** A는 물이 어느 구역에 얼마나 깊게 차오르는지가 주인공이다.

### B. 하천 흐름·범람 (§7)

**재난명** 하천범람 · **표현 성격** 물이 상류에서 하류로 이동하고 특정 구간에서 범람하는 유형

**핵심 메커니즘.** 물이 넓어지는 장면보다 상류의 수위 변화가 하류로 전달되고 특정 구간이 기준 수위를 넘는 과정. 도시침수와 구분하려면 반드시 상류 → 하류 흐름이 보여야 한다.

| 요소 | 사용 방식 | 화면 표현 |
|---|---|---|
| 관측소 수위·유량 | 실제 공개데이터 | 관측소 핀·수위, 종단도 |
| 강우 | 실제 기상·수문 데이터 | 유역 인셋 |
| 댐·보 방류량 | 제공 지점은 실제 공개데이터 | 상류 조건 |
| 하천 구간 | 정적 공간정보 | 하천 선·구간 |
| 미래 수위 | 데모 시나리오 | 종단도 시간 변화 |
| 미래 범람면 | 데모 시나리오 | 구간별 범람면 |
| 고립 구역 | 데모 시나리오 | 면·상태 표시 |
| 대피 상태 | 데모 시나리오 | 마을·도로 상태 |

현재 상태의 근거를 실제 데이터로 보여주기 좋은 유형이다.

**지도.** 하천 구간과 흐름 방향, 관측소 순서, 좌·우안 범람면, 제방·여수로, 고립 가능 구역, 하류 마을·도로. 범람면만 보이지 않게 하천 방향과 관측소 순서가 읽혀야 한다.

```text
상류                           하류
● 관측소 A
~~~~~~~→~~~~~~~→~~~~~~~→~~~~~~~ ● 관측소 B
                     ▒▒▒▒▒
                    ▒ 범람 ▒
                     ▒▒▒▒▒       🏘 마을
```

**보조 분석뷰: 종단도.** B의 핵심 보조뷰. 상류 → 하류 방향의 수위 흐름과 기준수위선. 관측소와 주요 구간을 종단도 위에 연결한다. 지도에서 구간을 고르면 종단도에서도
같은 지점이 강조된다. 종단도는 지도 위 선 레이어가 아니라 지도와 함께 보는 보조뷰다.

```text
수위
│        ● A
│       / \
│      /   \      ● B
│_____/_____\_____/________ 하류 방향
──────── 기준수위
```

**시간을 이동하면.** 상류 관측소 수위가 먼저 오르고, 일정 시간 뒤 하류 구간의 수위와 범람면이 변한다. 하류의 영향 시점이 순차적으로 드러난다. 지도와 종단도를 같이 움직인다.
시간축은 +30·+60·+120·+180분처럼 A보다 성기다.

**대안을 선택하면.** 사전 방류: 강우 전에 방류해 저류 여유를 확보하고, 그래서 이후 첨두수위가 낮아지며 범람면이 준다. 방류 직후 하류 수위가 잠깐 오르는 것은 종단도가 보인다. 대피 개시: 수위와 범람면은 그대로, 하류 마을·도로가 `대피/통제`로 바뀐다.

**우측 핵심 지표.** 기준 수위 도달까지 남은 시간. 보조: 주요 구간 범람 예상 시각, 고립 가능 구역.

**광역 인셋.** 유역 전체: 유역 강우, 상류 관측소, 댐·보, 방류 상태. 메인은 실제 문제 구간을 확대한다.

**데모에서 만들 것.** 시간별 하천 수위 시나리오, 시간별 범람 폴리곤, 종단도, 기준 수위선, 고립 구역, 대피 전/후 상태. 문구는 `하천 범람 전망 · 시나리오 도달시간`.

**데모 한 문장.** 예측강우가 매우 강하면 50분 뒤 여수로가 넘치고 2시간 뒤 하류 마을이 고립된다. 대피는 그 전에 시작해야 한다.

**표현 핵심.** B는 면이 커지는 것보다 상류의 변화가 하류로 전달되는 흐름이 주인공이다.

### C. 해안 경계·월류 (§8)

**재난명** 해안월류 · **표현 성격** 바다가 해안 경계를 넘어 저지대로 들어오는 유형

**핵심 메커니즘.** 물이 차는 것보다 바다가 어느 지점에서 경계를 넘고 그 물이 육지로 들어오는 과정. 반드시 월류 지점이 먼저 읽혀야 한다.

| 요소 | 사용 방식 | 화면 표현 |
|---|---|---|
| 조위 | 현행 해양 공개데이터 또는 데모 조건 | 조위 곡선·만조 시각 |
| 파고·파주기·파향 | 해양기상 관측자료 | 해상 조건 |
| 풍향·풍속 | 기상자료 | 방향 표시 |
| 해안선 | 정적 공간정보 | 기준 경계 |
| 방파제·수문·물양장 | 정적/데모 시설정보 | 방호시설 선 |
| 월류 지점 | 데모 시나리오 | 경계 위 강조점 |
| 미래 침수면 | 데모 시나리오 | 육지 방향 물 면 |
| 해안 통제 | 데모 | 도로·선박·물양장 상태 |

조위 API는 제공처 개편이 있었으므로 구현 단계에서 현행 데이터의 명세를 다시 확인한다(README §10). 빠른 데모라면 조위는 시나리오 값으로 두고 파고·풍향 등 받기 쉬운 관측값만 붙여도 된다.

**지도.** 해안선과 방파제·수문·물양장의 방호시설 선, 월류 지점, 월류 이후 육지로 퍼지는 침수면, 조위계·파고 관측 핀, 계류 선박, 해안도로·상가.
물은 월류 지점에서 시작해 육지로 들어와야 한다. 처음부터 육지 안쪽에 침수 폴리곤이 생기면 도시침수와 구분되지 않는다.

```text
바다 ~~~~~~~~~~~~~~
══════════════ 방파제/해안 경계
          ↑ 월류 지점
        ░░░
       ░░░░░   육지
```

**시간을 이동하면.** 조위 상승 → 방호시설 근접 → 물양장 월류 시작 → 만조 → 해안도로 → 상가. 조위 하강과 배수 조건을 반영한 시나리오에서는 침수면이 다시 준다. 배수구 역류가 지속되면 조위가 내려가도 빠지지 않는다. 시간축은 실제 시각형(17:50 · 18:10 · 18:24 만조 · 18:40 · 18:50)이 맞고 만조를 기준점으로 강조한다.

**대안을 선택하면.** 수문·차수: 월류 지점 일부가 막혀 이후 육지 침수면이 준다. 해안 통제: 월류와 침수면은 그대로, 해안도로·물양장·선박이 `통제됨`.
배수구 역류가 내수침수 사건으로 이어지는 연결이 보여야 한다(§8 "내수침수 사건 연결").

**우측 핵심 지표.** 월류 시작 시각·구간. 보조: 최대 침수심, 영향 도로·상가.

**광역 인셋.** 조위 곡선, 풍향, 파고, 태풍이 조건이면 태풍 경로. 메인은 월류 지점과 육지 영향.

**데모에서 만들 것.** 시간별 조위 조건, 월류 시작 시각, 월류 지점 1~3개, 시간별 침수면, 방호시설 선, 차수 대안, 해안도로·시설 통제 상태. 문구는 `월류 전망 · 예상 월류 구간 · 해안 영향 시나리오`.

**데모 한 문장.** 조위 +30 cm에 파고 2 m가 겹치면 만조 전에 물양장에서 월류가 시작되고, 수문을 미리 닫으면 상가까지 침수가 이어지지 않는다.

**표현 핵심.** C는 바다가 어디에서 경계를 넘는지가 먼저 보여야 한다.

### D. 이동 전선·확산 (§9) · 개념 장면

**재난명** 산불 · **표현 성격** 영향 전선이 방향성을 가지고 이동하는 유형

**핵심 메커니즘.** 어디에서 시작됐는가 → 어느 방향으로 번지는가 → 무엇에 언제 영향을 주는가가 한눈에 보여야 한다. 상세는 부록 B.

| 요소 | 사용 방식 | 화면 표현 |
|---|---|---|
| 위성 활성화재 관측점 | 실제 관측 데이터(NASA FIRMS 등). 관측 뒤 수 시간 지연이 있고 열이상 탐지라 실제 산불 면적을 뜻하지 않는다 | 최근 위성 관측 화재점(●). 발화점(🔥)은 시나리오이며 아이콘을 구분한다 |
| 풍향·풍속 | 실제 기상 데이터 | 화살표·수치 |
| 미래 화선 | 데모 시나리오 | 시간별 방향성 화선 |
| 연기 영향 | 풍향 기반 화면 생성 | 반투명 플룸 |
| 방화선 | 데모 시나리오 | 선 |
| 대피경로 | 데모 시나리오 | 경로 |
| 시설 도달시간 | 데모 시나리오 | 시설 상태·도달시각 |
| 광역 연기·대기 | 필요 시 광역 대기자료 | 인셋 |

**지도.** 산지 지형, 시나리오 발화점 핀(🔥)과 최근 위성 관측 화재점(●), 시각별 화선(앞쪽 경계를 더 선명하게), 연기 플룸(화선보다 넓고 옅게), 풍향·풍속 표시, 임도·등산로, 대피경로, 요양시설·주택, 진압자원 핀.
화선과 플룸은 겹쳐서 보이되 시각 성격이 달라야 한다. 원형 버퍼로 만들지 않는다.

**시간을 이동하면.** 화선이 풍하측으로 길어지고 플룸이 화선보다 앞쪽·넓게 퍼진다. 요양시설·주택이 순차적으로 영향권에 든다. 반대 방향은 거의 안 움직인다.
시설 상태도 같이 움직인다(정상 → 영향 예상 → 영향 임박 → 영향권). 필요 시 대피경로가 바뀐다.

**대안을 선택하면.** 차단선·진압: 임도 등에 방화선이 표시되고 이후 시각부터 화선 진행이 그 구간에서 멈추거나 약해진다. 대피방향 설정: 화선은 그대로, 연기와 진행 방향을 피해 대피경로가 표시된다.
진압은 재난 자체를 바꾸고 대피는 노출을 바꾼다.

**우측 핵심 지표.** 화선 확산 거리 km. 보조: 주요 시설 도달 예상 시각, 영향 시설 수.

**광역 인셋.** 광역 풍향장, 건조도, 주변 활성 화재, 필요 시 광역 연기. 메인은 지역 화선·시설 영향.

**데모에서 만들 것.** 시간별 화선 폴리곤(현재 · +30 · +60 · +120 · +180분), 풍향 기반 플룸, 방화선, 대피경로, 시설별 도달시각. 문구는 `확산 전망 · 시나리오 전망 · 예상 영향`, 연기는
`풍향 기반 연기 영향 · 연기 영향 예상 범위`. `AI 산불 확산 예측`, `연기 확산 예측 결과`처럼 물리 모델 결과로 오해할 표현은 피한다.

**데모 한 문장.** 남서풍 8 m/s 조건에서는 화선이 풍하측인 북동쪽으로 확산되고 2시간 뒤 요양시설 인근까지 접근한다. 임도에 차단선을 설정하면 이후 확산이 해당 구간에서 멈춘다.
풍향은 불어오는 방향이다. 북동풍이면 남서쪽으로 번진다(부록 B).

**표현 핵심.** D는 방향성이 가장 중요하다.

### E. 대기·면 노출 (§10) · 개념 예시

**재난명** 폭염 · **표현 성격** 넓은 영역에 강도가 누적되고 취약한 지역이 드러나는 유형

**핵심 메커니즘.** 폭염은 움직이는 전선이 아니다. 지역 전체에 열 노출이 누적되고 취약한 대상과 서비스 공백이 드러나는 과정. 어디가 더 심한가 · 얼마나 오래 지속되는가 · 보호받지 못하는 곳이 어디인가.

| 요소 | 사용 방식 | 화면 표현 |
|---|---|---|
| 현재·예보 기온·습도 | 실제 기상데이터 | 격자 강도, 체감 조건 |
| 폭염특보 | 실제 공개데이터 | 지역 상태 |
| 무더위쉼터 | 실제 공개데이터 | 쉼터 핀 |
| 인구 | 집계 공개데이터 | 격자/행정동 노출 규모 |
| 취약대상 | 데모 집계값 또는 권한 있는 데이터 | 격자 해칭·수치 |
| 서비스 공백 | 화면에서 계산/데모 | 쉼터 접근권 밖 격자 |
| 열돔 | 광역 개념 장면 | 인셋 |

**지도.** 생활권 또는 격자 단위 노출 강도(면 색), 취약대상 밀도(해칭), 쉼터·보호시설 핀, 서비스 공백(쉼터 접근권 밖 격자 외곽선 강조).
시각 채널을 분리한다. 면 색 = 그 시각의 열위험 강도, 해칭 = 취약성, 외곽선·패턴 = 서비스 공백과 지속·누적. 기온 색과 취약성 색을 같은 색으로 섞지 않는다. 쉼터 접근권은 단순 원형 반경이
실제 이동시간과 다르므로 `쉼터 접근권` 정도로 표현하고, 가능하면 도로 접근시간 기반으로 만든다.

**시간을 이동하면.** 면 색은 그 시각의 열위험 강도다. 지속·누적은 색이 아니라 격자 외곽선·패턴과 우측 첫 줄 위험 지속시간으로 보인다. 색이 짙어지는 것을 "기온이 더 올랐다"로 읽지 않게 두 채널을 가른다.
쉼터 운영 종료 시점에 서비스 공백이 넓어진다. 축은 D1 14:00 · 18:00 · 22:00 · D2 14:00 같은 시각형 또는 +0h·+6h·+12h·+24h.

**대안을 선택하면.** 쉼터 운영시간 연장: 폭염 강도는 그대로, 서비스 공백 격자가 준다. 순회 자원 배치: 공백지역 일부가 지원 범위로 바뀐다. 폭염 강도가 줄어드는 애니메이션을 넣지 않는다.

**우측 핵심 지표.** 위험 지속시간. 보조: 노출 인구, 취약대상 수, 서비스 공백 격자 수.

**광역 인셋.** 한반도 열돔 또는 광역 기온 분포. 열돔 지구본이 메인을 먹지 않게 인셋으로 내리고, 메인은 지역 노출·취약성·쉼터 공백을 보인다.

**데모에서 만들 것.** 실제 활용: 기온·습도·폭염특보·무더위쉼터. 데모: 취약대상 집계, 서비스 공백, 시간별 누적 노출, 쉼터 운영 연장 효과. 문구는 `폭염 노출 전망 · 지속 영향 · 쉼터 서비스 공백`.
개인 정보를 다루므로 취약대상 집계 단위·권한이 선결이다(§10 확인 조건).

**데모 한 문장.** 폭염이 이틀 이어지면 쉼터 밖 격자에 취약대상이 남고, 쉼터 운영시간을 연장하면 서비스 공백 지역이 줄어든다.

**표현 핵심.** E는 무언가가 이동하는 그림이 아니라 강도가 누적되고 서비스 공백이 드러나는 그림이어야 한다.

### F. 지반·구조 영향 (§11) · 개념 장면

**재난명** 급경사지 · **표현 성격** 사면의 움직임과 그로 인해 사용할 수 없게 되는 시설을 보여주는 유형

**핵심 메커니즘.** 위험 폴리곤이 아니다. 어느 사면이 위험하고 → 실제 움직임이 어느 방향으로 커지며 → 아래 도로·주택을 언제 통제해야 하는가.

| 요소 | 사용 방식 | 화면 표현 |
|---|---|---|
| 강우 | 실제 기상데이터 | 조건·광역 인셋 |
| 산사태 예측정보 | 실제 공개정보 | 행정구역 상태 |
| 산사태 위험지도 | 실제 공간정보 | 사면 배경 위험도 |
| 사면·경사 | 지형·공간정보 | 3D 지형 |
| 변위센서 | 내부 연계가 있으면 실제, 없으면 데모 | 벡터·수치 |
| 미래 변위 | 데모 시나리오 | 벡터 길이 변화 |
| 낙석·붕괴 영향구역 | 데모 | 영향 면 |
| 시설 상태 | 데모 | 사용 가능/점검/통제 |

특정 사면의 mm 단위 변위값은 공개 API에서 바로 얻는 값으로 가정하지 않는다. 현장 센서 연계가 없으면 변위는 데모 시나리오다.

**지도.** 사면 범위, 변위 벡터(화살표 길이로 변위 정도), 옹벽·배수로·하부 도로·주택, 시설별 상태(사용 가능 / 점검 필요 / 통제), 출입 가능 구역과 통제 구역 경계.
산사태 위험지도(원래 위험한 곳)와 변위 벡터(지금 실제로 움직이는 것)는 다른 정보이므로 구분해 그린다. 벡터는 주의 → 경계 → 심각으로 길어지고 숫자(누적 변위 mm)를 같이 보인다.

**시간을 이동하면.** 변위 화살표가 길어지고 상태가 주의 → 경계 → 심각으로 바뀐다. 위험 구간이 하부 도로에서 주택 방향으로 넓어지고 통제 경계가 나타난다. 시간축은 +2·+6·+12·+24시간.

**대안을 선택하면.** 출입통제·대피: 사면 변위는 그대로, 통제 구역 경계가 표시되고 도로·주택이 `통제됨`. 점검·보강 우선순위: 대상 시설에 순번을 표시한다.

**우측 핵심 지표.** 누적 변위 mm와 기준 단계. 보조: 통제 시설, 점검 우선순위.

**광역 인셋.** 누적 강우, 산사태 예측정보, 주변 위험지역. 메인은 선택 사면의 변위·시설 영향.

**데모에서 만들 것.** 실제 활용: 강우, 산사태 예측 상태, 위험지도. 데모: 변위 mm, 벡터, 시간별 위험구간, 시설 상태, 통제·대피. 문구는 `사면 영향 전망 · 변위 시나리오 · 통제 검토`.
실제 계측센서가 없으면 `실시간 사면변위`라고 쓰지 않는다.

**데모 한 문장.** 강우가 이어지면 12시간 뒤 변위가 경계 기준을 넘어 하부 도로가 위험 구간에 들어오고, 사전 통제 시 해당 구역의 노출을 막을 수 있다.

**표현 핵심.** F는 위험 면 확대보다 실제 사면이 어느 방향으로 얼마나 움직였는지가 먼저 보여야 한다.

### G. 기반시설·네트워크 장애 (§12) · 개념 장면 · 파생 성격

**재난명** 기반시설 장애 / 정전 파급 · **표현 성격** 한 시설의 장애가 연결된 다른 시설로 순차적으로 전달되는 유형

**핵심 메커니즘.** 공간을 따라 재난이 퍼지는 것이 아니라 연결 관계를 따라 장애가 퍼진다. 지도 폴리곤보다 노드·연결 상태가 먼저다.

| 요소 | 사용 방식 | 화면 표현 |
|---|---|---|
| 광역 전력수급 | 공개데이터 | 광역 맥락 |
| 지역 정전·설비 상태 | 내부 연계가 있으면 실제 | 시설 상태 |
| 시설 위치 | 내부/정적 데이터 | 노드 핀 |
| 시설 의존관계 | 내부 데이터 또는 데모 | 연결선 |
| 장애 순서 | 데모 시나리오 | 시간별 노드 상태 |
| 중단 권역 | 데모 시나리오 | 지도 면 |
| 비상전원·복구 순서 | 데모 | 노드 복구·번호 |

지역의 변전 → 펌프 → 기지국 → 마을방송 같은 실제 의존관계는 공개 API만으로 구성하기 어렵다. 내부 시설정보가 없으면 데모 시나리오 비중이 가장 크다.

**보조 분석뷰 또는 인셋: 계통도.** G는 광역 지도보다 계통도가 원인을 설명한다. 정상 노드는 활성, 장애 노드는 꺼짐, 영향 대기는 경고, 끊긴 연결은 점선, 복구는 다시 활성.

```text
[변전소] ─→ [펌프장] ─→ [배수]
               ├─→ [기지국]
               └─→ [마을방송]
정상  ● ─── ● ─── ●      장애  × ┄┄┄ × ┄┄┄ ○
```

**지도.** 계통도의 결과를 공간으로. 시설 노드 핀, 서비스 중단 권역 면, 우회·대체 경로, 영향 세대·시설 위치. 계통도 = 원인과 파급, 지도 = 실제 지역 영향.

**시간을 이동하면.** 변전 장애 → 펌프장 정지 → 통신 영향 → 마을방송 중단 → 중단 권역 확대. 노드 상태·연결선·중단 서비스·영향 권역·복구 예상시간이 같이 바뀐다. 복구가 시작되면 복구 순서에 따라 순차적으로 활성화된다. 장애 역순일 이유는 없다.

**대안을 선택하면.** 비상전원 투입: 펌프장 노드가 다시 켜지고 하위 서비스가 복구되며 지도의 중단 권역이 준다. 복구 순서: 노드에 ①②③ 순번을 표시하고 순서에 따라 복구 장면이 달라진다.

**우측 핵심 지표.** 서비스 중단 상태 · 복구 예상시간. 보조: 영향 세대·시설, 중단 서비스 종류.

**다른 재난과 연결.** 변전 장애 → 펌프장 정지 → 배수 능력 저하 → 도시침수 악화. G는 독립 장면이기도 하지만 A의 악화 조건으로 붙이기에 적합하다. 어느 쪽으로 둘지는 §28.

**데모에서 만들 것.** 계통도, 시간별 노드 상태, 중단 권역 폴리곤, 비상전원 대안, 복구 순번. 문구는 `장애 파급 전망 · 복구 시나리오`.

**데모 한 문장.** 변전 장애가 발생하면 펌프장과 연결 서비스가 순차적으로 중단되고, 비상전원을 투입하면 펌프장과 하위 서비스가 다시 활성화된다.

**표현 핵심.** G는 면이 퍼지는 재난이 아니라 연결을 따라 장애가 전달되는 과정이 주인공이다.


## 23. 광역 맥락 인셋

인셋은 "왜 지금 이런 조건인가", 메인은 "그래서 선택한 지역에 어떤 일이 생기는가"다. 공통 부품이지만 **항상 표시하지 않는다.** 광역 원인이 장면 이해에 도움이 되는 유형에서만 노출한다.

- 자리: 메인 지도 우하단, 우측 레일 바로 왼쪽. 조건 요약 카드와 충돌하지 않는 크기. 누르면 확대 또는 메인과 전환.
- 인셋에는 선택 지역의 위치를 항상 표시한다.
- 시간을 옮기면 인셋도 같은 시점 또는 가장 가까운 시점으로 바뀐다.
- 인셋은 원인·배경 맥락을 보여주는 용도다. 지역 영향 결과는 메인이 보인다. 값을 새로 계산하지 않는다.

| 유형 | 인셋/보조뷰 | 메인 지도 |
|---|---|---|
| A 도시침수 | 광역 강우 분포·조위 | 배수권역 침수 |
| B 하천범람 | 인셋: 유역 강우·상류 수위·방류 / 보조뷰: 종단도 | 하천 범람면 |
| C 해안월류 | 조위·풍향·파고·태풍 경로 | 해안 월류·침수 |
| D 산불 | 광역 풍향·건조도·주변 활성 화재 | 화선·연기·대피경로 |
| E 폭염 | 열돔·광역 기온 | 지역 노출 격자·서비스 공백 |
| F 급경사지 | 누적 강우·산사태 예측 | 사면 변위·통제 구역 |
| G 기반시설 | 계통도 | 서비스 중단 권역 |


## 24. 표현 부품과 우선순위

| 표현 부품 | 주요 유형 | 표현 대상 |
|---|---|---|
| 면 층 | A B C D | 침수면 · 범람면 · 월류면 · 화선 |
| 선 층 | C D F | 방호시설 · 방화선 · 대피경로 · 통제 경계 |
| 방향·벡터 | D F | 풍향 · 변위 |
| 격자 면 | E | 노출 강도 · 취약성 · 서비스 공백 |
| 노드·연결 | G | 시설 장애 · 의존 관계 · 복구 |
| 광역 인셋 | A B C D E F | 광역 원인·조건 (G 는 계통도가 그 자리) |
| 보조 분석뷰 | B G | 종단도 · 계통도 |

데모 우선순위

1. 화면 차별성을 만드는 표현: A 침수심, B 종단도, C 월류 지점, D 방향성 화선·플룸, E 격자·서비스 공백, F 변위 벡터, G 노드·연결
2. 실제 데이터로 신뢰감을 주는 조건: 강우, 수위, 풍향·풍속, 기온, 파고, 산사태 예측상태
3. 실제 연계가 어려운 부분은 사전 시나리오로 고정: 미래 침수면·범람면·월류 이후 침수·미래 화선·사면 변위·시설 장애 전파·대응 효과

부품 순서는 광역 인셋 → 선 표현 → 노드·연결 → 방향·벡터 → 격자 → 보조 분석뷰 고도화. 대표 데모 유형에 따라 바꿀 수 있다.
시각 강도(면의 진하기, 벡터 길이, 노드 상태 색)는 유형별 표현 방식에 맞춘다. 유형이 다른 지표를 하나의 강도값으로 정규화하지 않는다.


## 25. 사건 생애주기에서 디지털트윈의 자리

디지털트윈은 독립 기능이 아니라 사건의 지도가 미래·과거 상태로 바뀌는 방식이다. 쓰이는 자리는 셋이고 역할이 겹치지 않는다
(2026-09-16 · README §2.3). 같은 날 앞선 "디지털트윈 메뉴 = 사건 기반 대응 What-if" 결정을 고친다.

| 시점 | 화면 | 답하는 질문 | 다음 |
|---|---|---|---|
| 예측 이벤트 발생 · 피해 전 | 사건 작업공간의 **판단 기준 전망**(IA-02) | 지금 상태가 이어지면 무슨 일이 일어나는가 | [전망] |
| 〃 · 진행 중 | 사건 작업공간의 **전망 탭**(IA-03 · `?panel=twin`) | 언제·어디가·얼마나 위험해지는가(기준 전망). 대응을 지금·더 빨리 하면 무엇이 달라지는가(대안 비교) | [이 전망으로 조치안 갱신] → IA-04 |
| 사건 종료 후 | 기록·검증의 **예측 케이스**(IA-05) | 당시 예측이 실제로 얼마나 맞았나 | 개선 항목(출처 `검증`) |
| 〃 | **모의훈련**(`/scr-05`) | 이런 상황에서 이렇게 대응했다면 어땠을까 | 개선 항목(출처 `훈련`) · 분석 결과 저장 · 보고서 |

- **진행 중 판단은 전망 탭이 끝까지 든다.** 기준 전망과 대안 비교를 한 탭에서 보고, 고른 전망으로 조치안을 갱신한다. 모의훈련으로 넘기지 않는다.
  2026-09-15 전망 탭의 대안 비교표(README §8.2)를 되살린다. 화면 상세는 04가 든다.
- **지난 사건은 모의훈련이 든다.** 트윈의 `기준`은 그 사건의 재현이고 실제 대응이 들어 있다.
- **예측 대 실제는 예측 케이스가 든다.** 모의훈련에서 다시 계산하지 않는다.
- **개선 항목은 한 목록이다.** 출처(`검증` · `훈련`)만 다르다(README §8.3).

## 26. 모의훈련 (2026-09-16 · README §2.3 · v2 재작성)

메뉴 이름은 `모의훈련`이다. 원본은 창원 제안서 p.15·16 "모의훈련 E-SOP 관리"이고, 자사 경쟁 비교표에서 CUVIA만 ◎인 항목이다(요약설명자료 슬3).

**목적은 규정 검증이다** · "이 조건에서 우리 규정이 통하는지 확인하고, 안 통하는 지점을 고칠 거리로 남긴다"(README §2.3).
역량 숙지는 훈련 운영의 몫이고 화면이 대신하지 않는다. 그래서 점수를 매기지 않고, 대응 실행(IA-04)과 예측 검증(IA-05)도 하지 않는다.

> **v1(2026-09-16 오전)을 폐기하고 다시 썼다.** v1은 Phase 1에 있던 "예측판 두 벌 비교"에 잠금과 질문 하나를 얹은 것이었다.
> 벤치마킹 아홉 항목 중 셋만 화면에 있었고, 없는 여섯이 전부 훈련을 훈련이게 만드는 것이었다(검수 문서 참고).
> 기존 구현에서 출발한 것이 원인이다. v2는 **훈련이 무엇인가**에서 출발한다.

### 26.1 뼈대: 시나리오가 전개되고, 내가 조치하고, 결과를 본다

```text
시나리오가 시간에 따라 전개된다        ②-4 트윈 위 전개 · 지도가 움직인다
  └ 단계마다 규정이 뜬다               ①-1 SOP 시나리오·템플릿 (RINO p.4·5)
      └ 조치를 실행한다                ①-2 단계별 응대 지침·조치 결과 (XEUS p.22)
          └ 시간이 흐르고 결과가 나온다  ②-4
              └ 강평 · 개선 항목 · 보고서 ①-3 ②-5
```

번호는 README §2.3 기준 ①(업계 기본)·②(CUVIA 장점)의 항목이다. 화면의 각 자리가 어느 항목에서 왔는지 추적한다.

### 26.2 화면 다섯

| 화면 | 무엇을 하나 | 지도 |
|---|---|---|
| **목록** | 어느 사건으로 훈련할지 고른다. 훈련 가능·불가를 이유와 함께 밝힌다 | **없다.** 전체 폭 게시판. 사건을 고르기 전에는 지도 위 패널이 설명할 것이 없다 |
| **준비** | 고른 사건을 확인하고 **조건(강우 단계)** 을 정한다 | 사건 범위 |
| **판단 국면** | 규정이 뜨면 **[실행]** 하거나 넘긴다. 정지점 둘 | 물이 오기 전이라 거의 안 바뀐다 |
| **결과 국면** | 조치 창이 닫히고 물이 온다. 정지점 둘 | **바뀐다.** 범람면이 번진다 |
| **강평** | 내 조치가 만든 차이 · 발동에서 조치까지 · 고칠 거리 | 최종 범람 범위. 시각을 눌러 복기 |

지도 위 패널(광역 인셋 · 범례 · 유틸 스트립)은 **지금 구현에 있는 것을 그대로 쓰고**, 훈련 요소(시계 · 조치 표식)만 얹는다.
조치를 실행하면 지도에 표식이 서고 **범례에도 `조치` 줄이 함께 선다**(지도에 새 표식이 서면 범례에 선다).

목록을 지도에 핀으로 올리지 않는다 · 같은 지구에서 사건이 반복되면 겹친다(서항: 복합침수 · 펌프장 정전).

### 26.3 유형별 핵심 판단: 훈련이 묻는 것은 현상 대응이다

사건마다 대응이 둘이고 성격이 갈린다. `WhatIfResponse.kind` 가 이를 든다.

| 유형 | 현상 대응 (핵심 판단) | 노출 대응 |
|---|---|---|
| A 도시침수 | 배수 대응 | 도로 통제 |
| B 하천범람 | **저류지 방류** ← 창원천 | 천변도로 통제 |
| C 해안월류 | 수문·차수 | 해안 통제 |
| D 산불 | 방화선·진압 | 대피 개시 |
| E 폭염 | **없음**(기온은 못 낮춘다) | 쉼터 연장 · 순회 |
| F 급경사지 | **없음**(fixture 확인 2026-09-16) | 도로 통제 · 대피 범위 |
| G 기반시설 | 비상전원 투입 | 순회 자원 |

- **현상 대응**은 재난 자체를 바꾼다. 수위·도달·범위가 달라진다
- **노출 대응**은 사람·차량이 덜 닿게 한다. 대상 상태와 도달 전 여유만 달라진다
**훈련의 질문은 유형마다 다르다(2026-09-17 확정 · 앞선 "현상 대응이 없으면 훈련 불가"를 고친다).**

| 현상 대응 | 훈련이 묻는 것 | 예 |
|---|---|---|
| 있다 | **언제 조치할까** — 시각을 고르면 재난 자체가 달라진다 | B 창원천 방류 |
| 없다 | **우리 체계로 어디까지 버티나** — 조건을 올려 가며 대응 체계가 어디서 비는지 본다 | E 폭염 쉼터·순회 |

앞서 "현상 대응이 없는 유형은 훈련 시나리오를 만들 수 없다"고 닫았던 것은 **과한 단정**이었다.
창원천에서 도로 통제가 안 읽힌 진짜 이유는 노출 대응이라서가 아니라 **결과가 `여유 0분 → 10분` 한 줄로 끝나서**다.
폭염은 노출 대응인데도 쉼터를 일찍 열면 **공백 격자(면)가 줄고 공백 지속(시간)이 준다** — 기준 ③의 `범위`·`지속`이다.
단, **인원 수는 결과로 쓰지 않는다.** 칸당 몇 명은 편집값이라 "일찍 할수록 그만큼 줄어드는 산수"가 된다.
사람은 노출·통제됨 상태로만 선다. 이 구분이 폭염을 다시 실은 근거다(2026-09-16 에 뺐던 판단을 고친다).

- F 급경사지는 여전히 훈련을 만들지 않는다. 대응이 도로 통제·대피 범위뿐인데 **그 둘이 바꾸는 면이 없다** —
  사면은 대응과 무관하게 움직이고 통제 범위는 입력이지 결과가 아니다. 넣으려면 그 대응의 예측판부터 만들어야 한다
- 창원천의 질문이 방류인 이유가 여기서 나온다. 처음에 도로 통제로 물었더니 결과가 `여유 0분 → 10분` 하나뿐이라
  "그래서 무엇이 달라졌나"가 안 읽혔다 · **통제는 물이 오는 시각을 바꾸지 못한다**

**관제 화면의 첫 지표와 훈련의 첫 지표는 다를 수 있다(2026-09-17 검수에서 확인).**

§27.5 가 정한 유형별 첫 지표는 **"지금 무슨 일이 일어나는가"** 를 답한다. 훈련이 물어야 하는 것은
**"내 조치가 무엇을 바꿨는가"** 라 같지 않을 때가 있다.

| 유형 | 관제의 첫 지표(§27.5) | 훈련에서 실제로 갈리는 값 |
|---|---|---|
| B 하천범람 | 기준 수위 도달시간 | 같다 — 방류가 수위와 도달을 함께 바꾼다 |
| C 해안월류 | 월류 시작 시각 | **다르다** — 시작 시각은 조위가 정한다. 수문이 바꾸는 것은 월류 깊이·상가 유입이고, 통제가 바꾸는 것은 막히기 전 노출 시간이다 |
| D 산불 | 화선 확산 거리 | 같다(+ 이송은 연기 노출 시간) |
| E 폭염 | 위험 지속시간 | **다르다** — 지속시간은 조건이 정한다. 쉼터가 바꾸는 것은 공백 격자와 공백 지속이다 |
| G 기반시설 | 중단 상태·복구 시간 | 같다 — 비상전원이 파급을 멈춘다 |

그래서 **강평 표는 달라진 행을 먼저 놓는다.** 안 바뀐 행도 버리지 않고(그대로임을 아는 것도 정보다)
아래로 내린다. 그러지 않으면 폭염 강평의 첫 줄이 `경보 28시간째 → 경보 28시간째` 가 되어
훈련의 답이 "효과 없음"으로 읽힌다.

**조치가 결과를 가르려면 눈금보다 촘촘한 값이 필요하다.** 예측판 눈금은 넷뿐이라 상태 글자만으로는
"30분 일찍 한 것"과 "실제대로 한 것"이 같은 칸에 들어간다. 그때 세우는 것이 **시간 값**이다 —
폭염 `공백 지속`, 산불 `요양시설 연기 노출`, 해안월류 `막히기 전 노출`. 셋 다 곱해서 만든 수가
아니라 그 상태가 이어진 시간이라 기준 ③의 `지속`에 선다. 인원을 곱하면 그때부터 산수다.

### 26.4 정지점: 새로 결정할 일이 생기는 시각

시계는 정지점에서만 선다. 정지점은 **정보가 갱신되거나 기한이 닥치는 시각**이다.

| 정지점 | 국면 | 왜 여기서 멈추나 |
|---|---|---|
| 14:35 | 판단 | 범람 예측이 발생해 규정 3건이 떴다. 첫 결정 |
| 14:55 | 판단 | **방류가 효과를 낼 수 있는 마지막 시각.** 이후엔 해도 늦다 |
| 15:30 | 결과 | 조치 창이 닫히고 물이 온다 |
| 16:00 | 결과 | 최고 수위 → 종료·강평 |

- **조치 가능 시각은 정지점과 겹치는 것만 뜬다.** 시각 목록을 두 곳에 적지 않는다 · 대응의 선택지(`presets`)가 정본이다
- 앞서 정지점을 예측판 눈금(15:00·15:30·16:00·16:30)에만 두려 했으나 **그 시각에는 방류 판이 없어** 훈련이 성립하지 않았다.
  그래서 국면을 나눈다. 판단할 때 지도가 거의 안 바뀌는 것은 정직한 표현이다 · 실제로도 판단은 물이 오기 전에 한다
- **시간은 [다음 단계]로만 간다.** 훈련 중 시계 바는 진행 표시이고 누르는 자리가 아니다(앞으로 갈 길은 점선).
  강평에서는 누를 수 있다 · 복기라서 시각을 오가며 지도를 본다. 조치는 바꿀 수 없다

### 26.5 조치: 실행과 되돌리기

- 한 정지점에서 **여러 건을 실행할 수 있다.** 실행해도 시계는 가지 않는다
- **안 한 것 중 첫 번째는 늘 펴져 있다.** 실행하면 그다음이 그 자리로 올라온다. 두 번 눌러야 하면 흐름이 끊긴다
- 발동 규정이 여럿이면 **핵심(현상 대응)을 펴고 나머지는 접는다.** 세 장을 한꺼번에 던지면 시험지가 된다
- **[다음 단계]를 누르기 전까지 되돌릴 수 있다.** 시간이 안 갔으면 아직 확정이 아니다. 시계가 가면 확정된다
- **"안 함"은 선택지가 아니다.** 안 한 조치는 **실제와 같은 시각에 한 것**으로 본다.
  훈련의 질문은 "할까 말까"가 아니라 "언제 할까"다. 아무 조치도 안 한 판은 만들지 않는다
- 조치마다 **효과가 언제 보이는지** 적는다. 방류는 "결과는 15:30부터 보입니다", 통제는 "지도에 바로 섭니다".
  현상 대응의 효과가 지연된다는 것이 훈련에서 배울 점이라 숨기지 않는다
- 지침은 대응의 `target`·`level` 에서 옮겨 적고 **없으면 비운다**(지어내지 않는다)

### 26.6 조건: 더 나쁘게 해 보기

**훈련 시작 전에** 정한다. 훈련 중에는 바꾸지 않는다.

- 강우는 **판이 있는 값에만 멈추는 슬라이더**(당시 · +20% · +50%). 만조 중첩·펌프 정전은 확장
- 계산 경로가 없는 값(풍속 자유 조작)은 만들지 않는다(README §2.3 기준 ③)
- **조건을 바꿔도 관측값(상태 줄)은 당시 기록 그대로** 두고 조건 배지만 단다. 조건별 관측값을 만드는 것은 관측을 지어내는 일이다
- 같은 사건을 조건만 바꿔 여러 회차로 훈련한다. 목록에 쌓이면 "어디까지 버티나"가 읽힌다

### 26.7 강평: 비교 기준과 결론

**주 비교는 같은 조건 안에서 한다.**

| | 실제와 같게 | 내 훈련 |
|---|---|---|
| 조건 | 강우 +20% | 강우 +20% |
| 조치 | 실제와 같은 시각(방류 15:05 · 통제 15:22) | 내가 정한 시각 |

- 조건과 조치를 동시에 바꾼 비교로 원인을 말하지 않는다. **칸마다 한 가지씩만 달라진다**
- 당시 조건의 실제 대응은 **참고 줄**로 따로 적는다
- 결론은 **"나아졌다"와 "막았다"를 구분한다.** 기준 수위를 안 넘었을 때만 성공으로 말한다.
  넘었으면 "0.4 m 낮아지고 2분 늦어졌지만 여전히 기준을 넘었습니다. 이 조건에서는 방류만으로 막지 못합니다"
- **규정 준수는 양호·지연으로 판정하지 않는다.** 목표 시간의 근거가 없다(재난안전법 시행령·현장조치 행동매뉴얼 확인 대상).
  발동에서 조치까지 걸린 시간과 **실제와의 차이**만 적는다("0분 · 실제 30분")
- 조치를 하나도 안 하면 두 열이 같아진다. 그때는 "실제와 똑같은 훈련이 되었습니다"라고 먼저 말한다

### 26.8 개선 항목

- 사람이 적는다. 축은 임계치 · 데이터 · SOP 이고 모델 축은 쓰지 않는다(시뮬레이션 결과로 모델을 고치면 자기 출력을 되먹는다)
- 사건 · 조건 · 내 조치가 근거로 자동으로 붙는다. 시스템이 개선안 문장을 짓지 않는다
- 예측 검증(IA-05)의 개선 항목과 **한 목록**이고 출처만 `훈련`·`검증`으로 갈린다. 승인 뒤에만 반영한다

### 26.9 저장과 지난 훈련

- 저장 단위는 **훈련 한 회**(`TrainingRun`)다. 사건 · 조건 · 조치 목록 · 결과 판 · 개선 항목을 담는다
- **판 id와 보고서용 표시값을 둘 다 저장한다.** 판 id만 저장하면 판을 고치거나 모델을 교체할 때 과거 훈련 결과가
  소급해서 바뀌어 "그때 이렇게 나왔다"는 기록이 아니게 된다. 다시 열기는 판 id로, 보고서는 저장된 값으로 읽는다
- 사건 작업공간 전망 탭의 `AnalysisResult`(대안 분석 한 건)와 **다른 물건**이다. 섞지 않는다
- 탭은 `[훈련하기][지난 훈련]` 둘이다
- **회차를 나열만 하지 않고 사건별로 묶어 대비한다**(2026-09-16 확정). 같은 사건을 조건만 바꿔 두 번 이상 하면
  목록 위에 조건 순으로 늘어놓고 한 줄로 맺는다: `강우 당시까지는 막았고 강우 +20%부터 넘었습니다. 그 사이가 우리 규정의 한계입니다`.
  회차가 줄로만 쌓이면 "어디까지 버티나"가 안 읽혀 반복 훈련의 고리가 끊긴다(§26.6)
- 결론 문장은 강평과 목록이 **한 벌**이다(`debriefHeadline`). 두 벌로 적으면 한쪽만 고쳐진다
- **줄을 누르면 목록 위에 상세 창이 열린다.** 게시판에서 페이지로 나가지 않는다(platform_web 방식).
  줄이 요약이면 창은 그 회를 다시 읽는 자리다 — 지도 · 결과 비교 · 내 조치 · 고칠 거리
- **저장할 때 지도 한 장을 함께 뜬다**(`TrainingRun.mapImage` · 2026-09-17 확정). 숫자만 남기면
  "그때 어땠는지"가 안 돌아온다. 그림은 저장 시점 화면이고 시나리오를 고쳐도 다시 그리지 않는다.
  캔버스를 폭 760으로 줄여 JPEG 로 굽는다(지도를 만들 때 `capture: true` 가 있어야 빈 그림이 안 나온다)
- 저장 기록은 **안 한 규정도 담는다**(`sopRows`). "안 함"도 훈련의 결과이고, 목록·상세·보고서가
  같은 줄을 읽어야 조치 건수가 갈리지 않는다

**훈련 보고서**(`trainingReportOf` · 2026-09-17). 종이는 사건 보고서·분석 보고서와 같은 한 벌이고 절만 훈련 순서다.

| 절 | 내용 |
|---|---|
| 1 훈련 개요 | 사건 · 훈련 조건 · 훈련자 · **훈련 일시**와 **사건 구간**을 가른다(두 시간축을 한 줄에 섞으면 `02:18 ~ 02:18` 이 된다) |
| 2 훈련 구조 | 정지점마다 그 자리에서 결정할 것 |
| 3 내 조치 | 규정 · 발동 · 내 조치 · 발동에서 조치까지(실제와 견줌). 양호·지연으로 판정하지 않는다 |
| 4 결과 | 같은 조건에서 실제와 같게 했을 때 ↔ 내 훈련 |
| 5 마친 시점 상태 | 마지막 정지점의 관측·시설 상태 |
| 6 지도 결과 | 저장 시점 화면 |
| 7 개선 항목 | 훈련이 남긴 것. 승인 뒤에만 반영 |

v1 분석 보고서의 `분석 기준`·`바꾼 조건과 설정값`·`분석 의견`은 **가져오지 않는다.** 대안 분석의 개념이라
훈련에 자리가 없다. 훈련이 답하는 것은 "내가 한 조치가 무엇을 바꿨나" 하나다.

### 26.10 결과 값의 두 시험과 조합 판

결과 값은 두 시험을 통과해야 선다(README §2.3 기준 ③).

- **경로:** 그 값을 실제로 낼 경로가 있다. 모델 입력(실증 모델 또는 외부 모델 수신), 공식 기준·규칙, 사건 원장 중 하나다
- **트윈 결과:** 트윈이 계산하는 도달·범위·강도·파급이다. 입력에 비례해 줄어드는 산수는 데이터가 붙어도 결과가 아니다

| 예 | 판정 |
|---|---|
| 방류 시각 → 합류부 수위 · 기준 초과 시각 | 선다. 저수지 유입·방류량이 모델 입력(24년 보고서 p.39) |
| 강우·조위·펌프 가동률 조건 → 침수심 · 범위 · 도달 | 선다(p.39·40) |
| 도로 통제 시각 → 통제 완료와 도달 사이의 여유 | 선다. 도달은 모델, 통제 시각은 조치 |
| 도로 통제 → 진입 차량 · 노출 인원 | 서지 않는다. 산수 |
| SOP 단계별 목표 시간 | **서지 않는다. 근거를 못 찾았다**(§26.7) |

**조합 판은 빌드 때 미리 만든다**(조건 3 × 방류 3 × 통제 3). 훈련 중에 계산하면 화면이 값을 만드는 셈이 된다.
생성 규칙은 이미 있다 · `roadOn(판, 통제시각)` 이 임의의 판 위에 통제 시각만 얹는다(범람면·수위는 판이 정하고 통제는 대상 상태만 바꾼다).
규칙으로 만든 판은 근거 카드에 **"규칙 계산"** 이라고 그대로 적는다.

### 26.13 사건을 모의훈련에 올리는 최소 계약

1. 원장의 판단 시점
2. 바꿀 수 있는 조건. 실증 조건 축 또는 유형 결합
3. 대응과 그 결과의 경로. 모델 입력 · 외부 모델 · 규칙 · 원장 중 무엇인가(§15 경로 표)
4. 트윈 결과 지표. 도달 · 범위 · 강도 · 파급
5. 두 시험을 못 넘는 결과는 상황 부여로 둔다

```text
도시침수
  바꿀 조건    총 강우량 · 지속 · 분포 · 조위 · 펌프 가동률(실증 조건 축)
  대응         배수(펌프 가동률 · 현상) · 도로 통제(시각 · 노출)
  결과 지표    침수심 · 침수 범위 · 도달 시각 / 도로 통제: 침수는 그대로, 도달 전 여유
  상황 부여    결과 경로가 없는 전개
```

## 27. 데모 검수 항목

1. **모든 유형이 같은 폴리곤 애니메이션처럼 보이지 않는가.** A 물이 찬다 · B 상류에서 하류로 전달된다 · C 해안 경계를 넘는다 · D 한 방향으로 확산된다 · E 강도가 면에, 지속이 외곽선·지속시간에 드러난다 · F 사면이 움직인다 · G 연결된 시설이 순차적으로 꺼진다. 이 차이가 한눈에 보여야 한다.
2. **대안의 성격이 화면에서 구분되는가.** 현상 감소(배수·방류·차수·진압)와 노출 감소(도로 통제·대피·쉼터 운영·출입 통제). 모든 대안에서 영향 면을 억지로 줄이지 않는다.
3. **메인과 광역 인셋의 역할이 뒤집히지 않았는가.** 광역 = 원인, 지역 = 결과. 광역 상황이 화면을 먹지 않는다.
4. **시간 이동이 숫자 변경으로 끝나지 않는가.** 면의 범위·강도, 선의 위치, 방향, 벡터 길이, 노드 상태, 대상 상태 중 최소 하나는 시각적으로 변해야 한다.
5. **우측 첫 지표가 유형의 핵심 질문과 맞는가.**

| 유형 | 사용자가 화면에서 답할 질문 | 첫 지표 |
|---|---|---|
| A 도시침수 | 어디가 얼마나 잠기는가 | 최대 침수심 |
| B 하천범람 | 상류 변화가 언제 하류에 도달하는가 | 기준 수위 도달시간 |
| C 해안월류 | 언제 어디서 바다가 경계를 넘는가 | 월류 시작 시각·구간 |
| D 산불 | 불과 연기가 어느 방향으로 얼마나 가는가 | 화선 확산 거리 |
| E 폭염 | 어디가 오래 덥고 보호받지 못하는가 | 위험 지속시간 |
| F 급경사지 | 어느 사면이 얼마나 움직이고 무엇을 막아야 하는가 | 누적 변위 |
| G 기반시설 | 무엇이 고장나서 어떤 서비스까지 멈췄는가 | 중단 상태·복구 예상시간 |

장면 층과 침수면은 사건 작업공간의 전망 탭(`/scr-02?panel=twin`)에도 붙었고, 조건 요약 카드·광역 인셋·보조 분석뷰는 아직 디지털트윈 메뉴(`/scr-05`)에만 있다. 모의훈련 모드(훈련 시작·결정·이력·요약)는 2026-09-15 저녁에, 사건 없이 여는 조건 세트 화면(유형·지역·조건 셀렉트 · 사전 분석)은 2026-09-16 에 걷어냈다. C~G 개념 장면은 같은 날 지난 사건으로 옮겼고(`fixtures/past/`) 조건 세트 형식(`model/simulation.ts`)과 준비물은 지웠다.
그 자리를 예측 케이스가 받는다 — 사건이 끝나면 예측판 하나가 케이스 한 건으로 확정되고 이력(`/scr-07` 사건 기록 창의 ⑤ 예측 검증 절 · 2026-09-16 통계에서 옮김)에 쌓인다(IA §10.1 · §13.1 · §25). 화면은 예측 대 실제 표, 예측 범위 대 실제 범위 지도, 영향 대상 적중, 실제 대응, 개선 항목이며 점수를 매기지 않는다.
실측 침수 범위는 같은 굽기 스크립트가 `GEO-FLOOD-ACT`(수위 4.35 m · 6.5 ha)로 함께 굽는다. 잠긴 지역 후보명(창원천·서항 해안·팔용산·마산 원도심·장복산·봉암 펌프장)은 데모 표시용이며 확정 대상지가 아니다.

- 선 층·노드·벡터·격자 부품의 시각 스타일

사용자 결정 대기

- §18 마지막 항목의 다섯 건. 여기서 다시 적지 않는다.

## 30. 완료 기준 (제2부)

- 일곱 유형이 같은 폴리곤 애니메이션처럼 보이지 않는다. 면·흐름·경계·방향·격자·벡터·노드로 갈린다(§27 1).
- 대안의 성격이 화면에서 구분된다. 현상 감소는 면·강도가, 노출 감소는 대상 상태가 바뀐다(§27 2).
- 광역 인셋이 메인을 먹지 않는다. 광역은 원인, 지역은 결과(§26 3).
- 시간을 옮기면 숫자만이 아니라 지도의 무언가가 변한다(§26 4).
- 우측 첫 지표가 유형의 핵심 질문과 맞는다(§26 5).
- 실데이터는 현재 조건의 근거로만 쓰고, 시나리오 장면을 예측 모델 결과처럼 부르지 않는다(§20).

## 부록 A. 유형별 시각 문법 요약

| 유형 | 시각 문법 | 한 줄 | 시간 변화 | 대안 변화 |
|---|---|---|---|---|
| A 도시침수 | 면 + 깊이 | 물이 차오른다 | 저지대부터 침수 확대·감소 | 배수 시 면 감소 / 통제 시 상태만 변경 |
| B 하천범람 | 흐름 + 종단도 + 면 | 상류의 변화가 하류로 전달된다 | 상류 → 하류 전달 | 방류 시 수위·면 감소 / 대피 시 상태 변경 |
| C 해안월류 | 경계 + 월류 지점 + 면 | 바다가 경계를 넘는다 | 만조 전후 월류·침수 | 차수 시 월류 감소 / 통제 시 상태 변경 |
| D 산불 | 방향 + 화선 + 플룸 | 불이 바람을 따라 이동한다 | 한 방향으로 전선 이동 | 차단선에서 확산 억제 / 대피경로 변경 |
| E 폭염 | 격자 + 누적 + 서비스 공백 | 열 노출이 쌓이고 취약한 곳이 남는다 | 노출 강도 누적 | 쉼터 확대로 공백 감소 |
| F 급경사지 | 지형 + 벡터 + 상태 | 사면이 움직이고 아래 시설이 위험해진다 | 변위 증가·위험 단계 상승 | 사면은 그대로 / 통제·점검 상태 변경 |
| G 기반시설 | 노드 + 연결 + 중단 권역 | 한 시설의 장애가 연결을 따라 번진다 | 연결을 따라 장애 전파·복구 | 비상전원으로 일부 노드 복구 |

이 차이가 유지되면 모든 유형이 같은 디지털트윈 골격 안에 있으면서도 서로 다른 장면으로 인식된다.


## 부록 B. 산불 표현 상세

산불은 모든 요소를 실제 예측 API에서 받기보다 **현재 상황과 기상 조건은 외부 데이터를, 미래 확산 장면은 사전 작성 시나리오를** 쓴다. 화면에서 바로 읽혀야 하는 것은
어디에서 시작됐는가 → 어느 방향으로 번지는가 → 무엇에 언제 영향을 주는가다.

**위성 활성화재 관측점.** 위성 활성화재 탐지(NASA FIRMS 등)를 쓸 수 있다. 전 세계 준실시간 자료는 관측 뒤 보통 수 시간 안에 제공되고, hotspot 은 열이상 탐지라
실제 산불 면적을 뜻하지 않는다(NASA 도 이 한계를 명시한다). 그래서 "현재 화재 위치"가 아니라 **최근 위성 관측 화재점**으로 부른다. 개별 관측점을 많이 찍기보다
데모 목적에 따라 묶어 보이고, 시나리오 발화점(🔥)과 관측점(●)은 아이콘을 구분한다. 관측점은 미래 확산을 뜻하지 않는다.

**풍향·풍속.** 실제 기상 데이터를 받아 숫자와 함께 방향을 공간적으로 보인다. 기상 API의 풍향은 불어오는 방향이므로 연기·확산 방향을 만들 때 이동 방향으로 바꿔 쓴다.
풍속값으로 실제 확산 속도를 계산한다고 표현하지 않는다.

**방향성 있는 화선.** 원형 버퍼로 만들지 않는다. 풍하측 전면부가 앞으로 이동하고 반대쪽은 적게 움직인다. 시간별 사전 제작 폴리곤이다.

| 시각 | 장면 |
|---|---|
| 현재 | 발화점 주변 |
| +30분 | 풍하측 확산 시작 |
| +60분 | 임도·시설 방향 접근 |
| +120분 | 주요 시설 인근 도달 |
| +180분 | 대응이 없을 때 최대 장면 |

**연기 플룸.** 화선과 같은 형태로 움직이지 않는다. 더 넓고 옅은 영역으로, 발화 위치 + 화선 위치 + 풍향 + 풍속 + 시간으로 화면에서 만들 수 있다. 풍향이 일정하면 길게 뻗고,
시간에 따라 풍향이 달라지면 중심축이 휜다. 실제 대기확산 모델 결과가 아니므로 `풍향 기반 연기 영향 · 연기 영향 예상 범위`로 부른다.

**화선과 플룸은 겹쳐 보인다.** 화선은 실제 불이 진행하는 전면이라 경계가 명확하고 시설 도달 판단에 쓴다. 플룸은 화선보다 앞쪽·넓은 영역이고 경계를 부드럽게, 대피방향과 영향권 이해에 쓴다.

**시간 이동.** 화선 전진, 연기 확대·이동, 필요 시 풍향 변화, 시설 상태(정상 → 영향 예상 → 영향 임박 → 영향권), 대피경로 변경이 함께 움직인다. 시설 핀은 정보를 늘어놓기보다 상태 중심으로 보이고, 선택 시 거리와 예상 도달시각을 보인다.

**대안.** 차단선·진압은 방화선 또는 진압 구간을 표시하고 이후 시각의 화선 진행을 그 구간에서 멈추거나 작게 보인다. 대피방향 변경은 화선과 연기를 그대로 두고 대피경로만 풍향·진행 방향을 피해 바꾼다.

**광역 인셋.** 광역 풍향장, 건조도, 광역 연기·에어로졸(CAMS 같은 광역 대기자료), 주변 활성 화재 위치. 광역 모델은 산 하나·임도 단위 플룸을 정밀하게 그리는 용도가 아니므로 인셋에만 쓴다.

**첫 화면에서 보여야 하는 관계.**

```text
                         🌫 연기 영향
                    ░░░░░░░░░░
                ░░░░░░░░░
              🔥🔥🔥
          🔥🔥🔥
       🔥🔥      ↗ 남서풍 8 m/s (북동쪽으로 이동)

─────────────── 방화선

                  🏥 요양시설  예상 도달 60분
                  🏘 주택      예상 도달 120분
        ─────────────→ 대피경로
```

불이 어디 있는지 → 어느 방향으로 가는지 → 연기가 어디를 덮는지 → 어떤 시설에 언제 도달하는지 → 어디에서 막거나 어디로 피할 수 있는지.
