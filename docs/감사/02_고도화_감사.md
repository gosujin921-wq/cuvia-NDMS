## K-1 · [상세 기록 보기] 클릭 불능 (2026-08-13 수정·재검증 완료)

| 항목 | 값 |
|---|---|
| 증상 | SCR-03 우하단 [상세 기록 보기]가 화면 검수에서 클릭해도 SCR-04 로 이동하지 않음 |
| 위반 조항 | 03 §3 구성(우측 하단 [상세 기록 보기]) · 03 §4 동작 · 05 S8 (S7→S8 공식 동선) |
| 판정 | **레이아웃 결함.** 클릭 핸들러·라우팅(`navigate('/scr-04?district=…')`)은 정상 |

### 재현 (수정 전)

playwright 좌표 클릭(`mouse.click` · 자동 스크롤 없음, 사람 클릭과 동일)으로 재현했다.

| 조건 | 버튼 위치 | 클릭이 닿은 곳 | 이동 |
|---|---|---|---|
| 1600x1000 · 진입 직후 | y=1013 (화면 1000 밖) | 지도 캔버스 | 실패 |
| 1440x810 · S7 실행 후 | y=896 (화면 810 밖) | 지도 캔버스 | 실패 |
| 1600x1000 · 버튼이 화면 안일 때 | 화면 안 | 버튼 | 성공 (핸들러 정상 확인) |

### 원인

셋이 겹쳤다 (`EventDispatchPage.tsx` 우측 레일 · `lib/layout.ts` `RAIL_BASE`).

1. 버튼이 우측 레일 스크롤 영역의 맨 마지막 자식인데, 자식 5개 중 4개가 `shrink-0` 이라 레일 세로가 넘치면 버튼이 가장 먼저 화면 밖으로 밀린다
2. 레일 자체가 `pointer-events-none` 인 채 `overflow-y-auto` 라 스크롤바를 잡을 수 없고, 패널 틈의 휠은 뒤의 지도 줌으로 새어 나간다. 버튼까지 스크롤해 내려가는 조작 자체가 안 된다
3. S6 승인·S7 실행 직후 SOP 패널·실행 결과·전파 내역이 늘어나 레일이 가장 길어진다. 정확히 이 버튼을 눌러야 하는 시점(S7→S8)에 버튼이 밖에 있다

### 기존 시각 검증(2회차)이 못 잡은 이유

`walkthrough.mjs` 의 `locator.click()` 은 클릭 전에 요소를 자동 스크롤한다. 사람이 못 누르는 버튼도
스크립트는 통과한다. 이후 시각 검증에서 클릭류 검증은 좌표 클릭(`mouse.click`)을 병용한다.

### 수정

우측 레일을 "스크롤되는 본문 wrapper + 하단 고정 버튼" 으로 재구성 (`EventDispatchPage.tsx`).

- 판정·SOP·문안·전파 내역 4개 패널을 `pointer-events-auto` + `overflow-y-auto` wrapper 안으로. 스크롤바·휠이 정상 동작하고 틈의 휠이 지도로 새지 않는다
- [상세 기록 보기]는 wrapper 밖 레일 하단 고정(`shrink-0`). 레일이 아무리 길어져도 항상 보인다

### 재검증 (수정 후)

같은 좌표 클릭 방식. 1600x1000 · 1440x810 각각 진입 직후(S0)와 SOP 실행 후(S7) 4개 케이스 전부
버튼이 화면 안에 있고, `elementFromPoint` = 버튼, 클릭 시 `/scr-04?district=seohang` 이동 확인.
