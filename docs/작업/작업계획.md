## 현재 상태

화면 다섯이 모두 돈다. 지구·장비·이벤트·기상·연계 수치는 [04 데모 데이터](../정본/04_데모_데이터.md) 에 확정됐다. `type-check` · `build` 통과.

시연 대본은 [05 시나리오](../정본/05_시나리오.md) 에 있다. **구현은 정본 개편(사건 서사 · CUVIA 문법 · v3 정합) 이전 기준**이라, 화면명·버튼명부터 아래 표의 기능까지 차수 I 가 따라잡아야 한다.

| 화면 | 상태 (구현 기준 · 괄호는 정본의 새 이름) |
|---|---|
| SCR-01 대시보드 (→ 종합상황) | 동작. 지도 · 지구 목록 · 기상 · 도넛 · 연계 현황 · 질의 바. **도시 대응단계 헤더 · 유형 도넛 · 특보 라벨 미구현** |
| SCR-02 조기경보 (→ 재난관제) | 동작. 지구 확대 지도 · 장치/이벤트 핀 · 센서/CCTV 팝업 · 실시간 수치. **격상 · 위험도 카드 · 조위 · 위험요소 레이어 미구현** |
| SCR-03 이벤트·상황전파 (→ 상황대응) | 동작. 카드 목록 · 지도 · CCTV 4분할 · 발령 기준표 · 전파. **판정 4층 · 승인 · SOP · 실행 결과 미구현** |
| SCR-04 통계·분석 | 동작. 지구·기간 조회 · 이중축 그래프 · CSV. **KPI 분리 · 시나리오 점선 · 이력 4행 미구현** |
| SCR-05 디지털트윈 | 동작. 3D 씬 · 레이어 · 침수 슬라이더 · 미니맵. **침수 영향 카드 · 시나리오 표식 · [이 판단으로 대응하기] 미구현** |

화면 간 이동은 [상세 측정현황 보기] → `/scr-04?device=`, [Twin 모드 실행](→ [디지털트윈 분석]) → `/scr-05/:districtId` 까지만 있다. SCR-05→03, SCR-03→04, 질의 바→06 은 차수 I 몫이다.

데모에 실제 CCTV 스트림이 없다. 영상 자리는 LIVE 표시로 두고 있고, 시연용 영상을 확보하면 바꿔 넣는다.

### 순서

I-1(상태 엔진 + 시계)이 먼저다. 시계가 서야 격상(I-2)이 서고, 격상이 서야 시나리오·판정(I-3·I-4)이 붙을 자리가 생긴다.
그다음 I-4 → I-5 → I-6 이 SCR-03 한 화면 안에서 이어진다. I-7~I-16 은 서로 독립이라 병행할 수 있고,
그중 I-10(화면명)·I-14(라벨)는 기계적이라 아무 때나 먼저 쳐도 된다. J 차수는 I 와 무관하게 아무 때나 끼워 넣는다.

**감사 재실시가 필요하다.** [감사 문서](../감사/01_구현_대조_감사.md) 는 2026-08-12 정본 기준이고, 그 뒤 정본 01~05 가 모두 바뀌었다. I 차수를 끝낸 뒤 다시 대조한다.

### 문서 밖 준비물

- **시연용 CCTV 영상.** 데모에 실제 스트림이 없다. 서항지구 2대 · 봉암지구 3대가 먼저 필요하다.
  확보 전까지 영상 자리는 LIVE 표시로 두고, 시연에서는 "이 자리에 현장 영상이 붙는다" 로 말한다
- **시연 녹화본.** 대본대로 한 번 녹화해 두면 현장 네트워크·지도 타일 사정과 무관해진다

## 공통 원칙

- **데모 상태 엔진이 단일 source of truth 다** — 화면별 하드코딩 금지. 규칙 전문은 [CLAUDE.md](../../CLAUDE.md), 선례는 CUVIA_IDC `state/DemoProvider.tsx`
- 부품은 DS(`@cuvia/components`) 우선, 없으면 이 앱 안에 신규. DS 저장소 수정 금지
- 목록형 화면은 DataTable + StatusDotLabel + PaginationBar 패턴
- 날짜·시각은 `src/lib/datetime.ts`, 최소 폰트 13px, 배경에 opacity 색 토큰 금지
- 지도 위 마커·팝업은 패널·버튼보다 아래 레이어
- API 규격·보관 정책 등 백엔드 결정 영역은 03 문서 §7 에 항목만 남기고 화면에서 지어내지 않는다
