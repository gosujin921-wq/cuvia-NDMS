# SCR-04 통계 분석 · 사건 이력 분리안

> **차수 N 이전 문서 (2026-08-13 이전 구조).** 이 문서가 말하는 SCR-03 상황대응 화면은 차수 N 에서 SCR-02 재난관제로 통합·결번됐다(정본 02 §1·§4 · 03 §2). 화면 구성 서술은 당시 기준의 기록이며, 현행 구조는 정본 03 §2(사건 블록 · 대응 실행 집중 팝업)를 따른다.

## 1. 결정

SCR-04는 하나의 메뉴와 경로를 유지하되, 화면 안에서 다음 두 업무를 탭으로 분리한다.

```text
[통계 분석] [사건 이력]
```

- **통계 분석**은 기간·지역·재난유형에 따른 집계와 비교를 담당한다.
- **사건 이력**은 개별 사건의 판단 근거·승인·실행·실패·대체 조치를 복기한다.
- 별도의 SCR-07은 만들지 않는다.
- 기존의 긴 `이벤트·대응 이력` 표를 통계 분석 하단에 상시 노출하지 않는다.
- SCR-03의 전체 전파 원장은 사건 이력 탭으로 옮긴다.

이 결정의 목적은 통계를 없애거나 사건 이력을 별도 제품으로 분리하는 것이 아니다. **수치 분석과 개별 사건 복기라는 서로 다른 업무를 같은 화면 안에서 명확히 구분**하는 것이다.

## 2. 화면이 답해야 하는 질문

### 통계 분석

> 어떤 재난이 어디서 얼마나 반복됐고, 대응 성과는 어땠는가?

### 사건 이력

> 이 사건에서 당시 무엇을 보고 판단했고, 무엇을 실행했으며, 실제 결과는 어땠는가?

두 질문은 같은 원장을 사용하지만 읽는 단위가 다르다.

| 구분 | 통계 분석 | 사건 이력 |
|---|---|---|
| 단위 | 기간·지역·유형의 집계 | 사건 한 건 |
| 목적 | 경향·분포·순위 비교 | 판단과 대응의 감사·복기 |
| 핵심 표현 | KPI·차트·비교표 | 사건 목록·상세·타임라인 |
| 기본 진입 | 메뉴에서 SCR-04 선택 | SCR-03 [상세 기록 보기] |

## 3. 탭과 진입 규칙

### 3-1. 메뉴 진입

사이드 메뉴의 `통계`를 누르면 다음 상태로 연다.

- 선택 탭: `통계 분석`
- 범위: 전체
- 기간: 최근 30일
- 분야·유형·단계: 전체
- 최다 발생 지구의 계측 상세 표시

권장 URL:

```text
/scr-04?tab=analytics
```

`tab`이 없을 때도 `analytics`를 기본값으로 처리한다.

### 3-2. 상황대응 진입

SCR-03의 `[상세 기록 보기]`를 누르면 다음 상태로 연다.

- 선택 탭: `사건 이력`
- 선택 사건: SCR-03에서 처리하던 사건
- 사건 상세: 펼침
- 사건 타임라인: 첫 주요 판단 지점이 보이는 위치

권장 URL:

```text
/scr-04?tab=history&event=EVT-260812-006
```

`district`만 전달하지 않는다. 사후검증의 단위는 지구가 아니라 사건이다.

### 3-3. 화면 안 이동

- 통계 분석의 사건 또는 이벤트 구간을 선택하면 사건 이력 탭의 해당 사건으로 이동할 수 있다.
- 사건 이력에서 지구·유형 링크를 선택하면 통계 분석 탭의 같은 필터로 이동할 수 있다.
- 탭 전환 시 공통 조회 기간은 가능한 한 유지한다.
- 존재하지 않는 사건 ID로 들어오면 사건 이력 탭의 최신 사건을 선택하고 안내 문구를 표시한다.

## 4. 통계 분석 탭

### 4-1. 정보구조

1. 조회 조건
2. 핵심 KPI
3. 발생 추이와 분포
4. 지구별 비교
5. 선택 지구 계측 상세

기존 하단의 전체 `이벤트·대응 이력` 표는 제거한다.

### 4-2. 조회 조건

- 범위: 전체·지구 12
- 기간: 1년·6개월·3개월·1개월·1주일·직접 지정
- 분야
- 재난유형
- 계측 단계
- CSV 다운로드

조회 조건은 통계 분석에 적용한다. 사건 이력 탭에서는 사건 목록 필터로 재사용할 수 있지만, 사건 상세의 원장 자체를 변경하지 않는다.

### 4-3. 핵심 KPI

계측·처리·대응 지표를 섞지 않는다.

#### 계측 지표

- 총 발생
- 경보 이상
- 대피 도달
- 최다 발생 지구

#### 처리 지표

- 최초 확인시간
- 최초 전파시간
- 종료까지 소요시간

#### 대응 지표

- 선제 대응 사건 수
- 승인 대응등급별 사건 수
- 전파 실행 횟수
- 전파 대상 사건 수
- 재전파 횟수
- SOP 성공·실패
- 대체 조치 건수

재전파는 전파 실행 횟수에는 포함하지만 전파 대상 사건 수와 최초 전파 소요시간을 부풀리지 않는다.

### 4-4. 발생 추이와 분포

- 기간별 단계 색 누적 막대
- 단계별 도넛
- 재난유형별 도넛
- SCR-01과 동일한 색·분류체계 사용

### 4-5. 지구별 비교

- 지구·유형
- 발생 건수
- 경보 이상
- 최고 수위
- 누적 강우
- 최초 전파
- 전파 대상 인원

행을 선택하면 같은 탭의 선택 지구 계측 상세가 갱신된다.

### 4-6. 선택 지구 계측 상세

- 최고 수위
- 누적 강우량
- 이벤트 수
- 발령 기준
- 수위·강우 이중축 그래프
- 단계 기준선
- 이벤트 구간
- 당시 조건 시나리오 점선

이 영역은 지구의 계측 경향을 보는 곳이다. SOP와 실패·대체조치 상세는 사건 이력 탭이 맡는다.

## 5. 사건 이력 탭

### 5-1. 정보구조

```text
┌──────── 사건 목록 ────────┐ ┌──────── 선택 사건 상세 ─────────┐
│ 8/12 서항 폭풍해일        │ │ 사건 요약                         │
│ 8/12 명동항 폭풍해일      │ │ 판단 근거와 실제 결과 비교        │
│ 8/11 창원천 하천범람      │ │ 단계·대응 타임라인                │
│ ...                       │ │ 전파·SOP·실패·대체조치            │
└───────────────────────────┘ └───────────────────────────────────┘
```

사건 목록과 상세를 분리한다. 기존처럼 모든 사건을 한 개의 넓은 표에 넣고 주인공 사건만 하위 행으로 펼치지 않는다.

### 5-2. 사건 목록

각 항목에 다음을 표시한다.

- 발생 일시
- 지구
- 재난유형
- 최고 계측 단계
- 처리상태
- 승인 대응등급
- 종료 여부

필터:

- 기간
- 지구
- 재난 분야
- 재난유형
- 계측 단계
- 처리상태
- 승인 대응등급
- 실패·대체조치 유무

### 5-3. 사건 요약

- 사건 ID
- 지구·위치
- 발생·확인·종료 시각
- 탐지 장비
- 최고 계측값과 단계
- 승인 대응등급
- 처리상태
- 최초 전파시간
- 선제 대응시간

### 5-4. 판단 근거와 실제 결과 비교

주인공 사건은 다음 네 값을 한 블록에서 비교한다.

| 항목 | 값 |
|---|---|
| 당시 계측 | 경보 · 3.41 EL.m · 17:22 |
| 당시 조건 시나리오 | 4.24 EL.m · 19:10 · 대피 기준 초과 |
| 대응등급 승인 | 대피 · 17:37 |
| 실제 결과 | 4.31 EL.m · 19:22 · 계측 대피 도달 |

핵심 결론:

> 실제 대피 기준 도달 1시간 45분 전에 대피 대응을 승인했다.

이를 예측 정확도나 오차율로 표현하지 않는다. 당시 어떤 조건과 영향정보를 보고 선제 대응했는지를 검증한다.

### 5-5. 사건 타임라인

다음 기록을 시간순으로 표시한다.

```text
17:05  발생 · 주의보 · 3.02 EL.m
17:07  담당자 확인
17:09  1차 전파 · 마을방송 · 412명
17:22  경보 격상 · 3.41 EL.m
17:22  만조 조건 시나리오 · 4.24 EL.m
17:37  대응등급 대피 승인
17:37  SOP 전파 · 재난문자·마을방송·전광판
17:38  경상남도 자동보고 실패
17:39  유선 보고 기록
19:22  실제 계측 대피 도달 · 4.31 EL.m
21:48  해제
```

타임라인은 별도 원장이 아니라 이벤트 단계 이력·승인·전파·SOP 결과·대체조치에서 파생한다.

### 5-6. 전파 상세

현재 사건에 속한 전파 기록을 모두 표시한다.

- 전파 유형: SOP 최초 전파·수정 문안 재전파
- 실제 전송 문안
- 수단
- 대상 인원
- 전송 시각
- 최초 전파 소요시간
- 기록자

`dispatchKind`를 사용해 최초 SOP 전파와 재전파를 구분한다.

### 5-7. SOP 실행 결과

- 실행 항목
- 자동 처리·승인 후 실행 구분
- 성공·실패
- 실행 시각
- 대상
- 실패 사유
- 대체 조치
- 대체 조치 시각·기록자

실행하지 않은 항목은 성공 결과처럼 표시하지 않는다.

## 6. SCR-03과의 역할 분리

### SCR-03 상황대응

- 현재 사건 판단
- 대응등급 승인
- SOP 실행
- 현재 실행 결과
- 즉시 필요한 실패 대체조치
- 현재 사건의 압축 타임라인

### SCR-04 사건 이력

- 종료된 사건 복기
- 전체 단계·판단·대응 타임라인
- 최초 전파와 재전파 상세
- SOP 실행 감사
- 당시 조건 시나리오와 실제 결과 비교
- 사건 간 검색과 필터

SCR-03에는 과거 다른 사건의 전체 전파 내역을 두지 않는다.

## 7. 다운로드

### 통계 분석 탭

- 현재 조회 조건의 사건 집계
- 지구별 비교
- 선택 지구 계측 시계열

### 사건 이력 탭

CUVIA_통계분석_20260713-20260812.csv

## 8. 정본 반영 대상

### 02 IA 화면구조

- SCR-04 내부 탭 `통계 분석·사건 이력` 명시
- SCR-03 → SCR-04 이동은 사건 이력 탭과 사건 ID를 유지한다고 명시

### 03 화면정의서 §3

- [상세 기록 보기]가 `사건 이력` 탭의 선택 사건으로 이동한다고 수정
- 전체 전파 원장은 SCR-04 사건 이력이 맡는다고 명시

### 03 화면정의서 §4

- 통계 분석·사건 이력 탭 구조 추가
- 기존 하단 이벤트·대응 이력 표를 사건 이력 탭 구조로 교체
- 메뉴 진입·상황대응 진입 규칙 구분
- 다운로드 규칙 분리

### 04 데모 데이터

- 사건 이력 상세의 파생 필드 명시
- 전파 기록·SOP 결과·실패·대체조치 연결 규칙 명시
- 통계 집계와 사건 상세가 같은 원장을 읽는다고 명시

### 05 시나리오 S8

- [상세 기록 보기] → 사건 이력 탭 진입
- 서항 사건 자동 선택
- 조건 시나리오·승인·실제 대피 도달 비교
- 1시간 45분 선제 대응 결론 확인

## 10. 수용 기준

- [ ] 메뉴로 SCR-04에 들어오면 통계 분석 탭이 열린다.
- [ ] SCR-03 [상세 기록 보기]로 들어오면 사건 이력 탭과 해당 사건이 열린다.
- [ ] 통계 분석 탭에 전체 이벤트·대응 이력 표가 상시 노출되지 않는다.
- [ ] 통계 분석 탭은 KPI·추이·분포·지구 비교·계측 상세에 집중한다.
- [ ] 사건 이력 탭은 사건 목록과 선택 사건 상세로 구분된다.
- [ ] 선택 사건에서 계측 단계와 승인 대응등급이 별도 값으로 보인다.
- [ ] 조건 시나리오·승인 시각·실제 최고수위가 한 블록에서 비교된다.
- [ ] 최초 전파·재전파·실제 문안·채널·대상·기록자가 조회된다.
- [ ] SOP 성공·실패와 대체 조치가 같은 사건에 연결된다.
- [ ] 주인공 사건의 1시간 45분 선제 대응을 화면 값으로 검증할 수 있다.
- [ ] 재전파가 전파 대상 사건 수와 평균 최초 전파 소요시간을 부풀리지 않는다.
- [ ] 새로고침해도 URL의 탭과 사건 선택이 복구된다.
- [ ] 존재하지 않는 사건 ID가 빈 화면이나 오류를 만들지 않는다.
- [ ] 1280×720에서 탭·사건 목록·핵심 비교·상세 이동 CTA를 조작할 수 있다.

## 11. 기대 효과

- 통계 차트와 긴 사건 원장이 한 화면에서 경쟁하지 않는다.
- 평시 분석과 시연의 사후검증 동선이 각각 분명해진다.
- SCR-03은 현재 판단·실행에 집중하고 SCR-04는 과거 복기와 감사에 집중한다.
- 통계 KPI의 숫자를 사건 원장으로 바로 검증할 수 있다.
- 같은 데이터를 집계 관점과 사건 관점에서 일관되게 보여준다.
- 별도 화면을 늘리지 않고도 `통계`와 `사건 이력`의 업무 차이를 사용자에게 설명할 수 있다.
