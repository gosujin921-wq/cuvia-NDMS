## 1. 결정

SCR-03 상황대응은 **현재 사건을 판단하고 승인해 실행하는 화면**으로 책임을 좁힌다.

화면의 중심 흐름은 다음 네 단계다.

```text
위험도 판정 → 대응등급 승인 → SOP 실행 → 실행 결과 확인·대체 조치
```

- **위험도 판정**은 항상 노출한다.
- **대응 절차(SOP)**는 항상 노출한다.
- **상황전파**는 독립 기능으로 두지 않고 SOP의 전파 항목에 통합한다.
- **전체 이벤트 전파 내역**은 SCR-03 본문에서 내리고 SCR-04 상세 기록이 맡는다.
- SCR-03에는 선택한 **현재 사건의 전파 결과만** 타임라인과 실행 결과에 남긴다.
- **[상세 기록 보기]**는 우측 레일 하단에 고정해 SCR-04로 연결한다.

이 결정의 목적은 기능을 없애는 것이 아니라, 같은 기능을 두 번 설명하던 구조를 하나의 사건 처리 흐름으로 합치는 것이다.

## 2. 화면이 답해야 하는 질문

SCR-03의 질문은 하나다.

> 이 사건에 대해 지금 어떤 결정을 내리고, 무엇을 실행해야 하는가?

다음 질문은 다른 화면이 맡는다.

| 질문 | 담당 화면 |
|---|---|
| 현재 어떤 징후가 발생했는가 | SCR-01 종합상황 · SCR-02 재난관제 |
| 조건을 적용하면 어디까지 영향을 받는가 | SCR-05 디지털트윈 |
| 지금 어떤 대응등급과 절차가 필요한가 | **SCR-03 상황대응** |
| 당시 무엇을 판단하고 어떻게 대응했는가 | SCR-04 통계·분석 |
| 흩어진 근거를 자연어로 어떻게 연결하는가 | SCR-06 AI 검색 |

## 3. 최종 정보구조

### 3-1. 좌측 — 사건 선택

- 진행 중·해제 탭
- 이벤트 카드 목록
- 지구명·재난유형·계측 단계·처리상태·측정값·경과 시간
- 선택한 사건을 분명히 표시

좌측의 첫 책임은 **사건 전환**이다. 긴 타임라인 때문에 다른 진행 사건이 지나치게 밀리지 않도록 한다.

### 3-2. 중앙 — 현장 확인

- 선택 지구 지도
- 장비·이벤트 핀
- 현장 CCTV
- 발령 기준
- 현재 계측값과 조건 시나리오 값

중앙은 판단의 현장 근거를 보여준다. 승인·실행 버튼을 두지 않는다.

### 3-3. 우측 — 판단과 실행

한 방향으로 읽히도록 아래 순서를 고정한다.

1. 위험도 판정
2. 대응등급 승인
3. 대응 절차(SOP)
4. 실행 결과
5. 실패 대체 조치

우측에는 과거 다른 사건의 전파 원장을 길게 나열하지 않는다.

### 3-4. 현재 사건 타임라인

현재 사건의 진행 이력만 보여준다.

```text
발생 → 담당자 확인 → 1차 전파 → 계측 격상 → 조건 시나리오
     → 대응등급 승인 → SOP 실행 → 실패 → 대체 조치
```

배치는 다음 두 안 중 화면 높이에 맞는 쪽을 사용한다.

1. 중앙 하단 가로 타임라인
2. 선택 사건 카드의 접을 수 있는 상세 영역

> **배치 확정 (2026-08-13): 2안 · 선택 사건 카드의 접이식 상세.**
> 1280×720 에서 1안은 지도·CCTV 가 이미 쓰는 세로 공간을 깎아 지도 유효 높이와 CCTV 썸네일이
> 줄고, 단계가 늘수록 가로 타임라인이 압축되거나 두 줄로 깨진다. 접이식 규칙: 선택 카드에만
> 토글 · 다른 카드 선택 시 닫힘 · 최대 높이 고정 + 내부 스크롤 · 주인공 사건 최초 진입 펼침 ·
> 일반·해제 사건 기본 접힘 · 접힌 토글 줄에 최신 진행 단계 한 줄. 차수 L 로 반영.

기본 원칙은 **사건 목록과 사건 상세를 시각적으로 구분하는 것**이다. 타임라인은 별도 원장을 만들지 않고 04 문서에 등재된 단계 이력·전파 기록·승인·SOP 결과에서 파생한다.

## 4. 상황전파를 SOP에 통합하는 방식

### 4-1. 최초 전파

최초 전파는 SOP의 승인 후 실행 항목이 담당한다.

```text
□ 주민 긴급 재난문자 발송
  대상 412명

□ 마을방송 · 전광판 송출
  마을방송 1 · 전광판 2

  문안 미리보기
  [문안 수정]
```

- 승인 전에는 제안 상태로 보여준다.
- 담당자는 문안을 미리 검토·수정할 수 있다.
- 대응등급 승인 뒤 실행 항목을 선택한다.
- **[승인·실행]**으로 선택 항목을 순차 실행한다.
- 별도의 최초 전파 버튼을 두지 않는다.

### 4-2. 실행 후 표시

SOP 실행이 끝나면 같은 자리가 실행 결과로 바뀐다.

```text
✓ 주민 긴급 재난문자 · 17:37 · 412명
✓ 마을방송 · 전광판 · 17:37
✓ 해안도로 차단 · 대피소 개방 요청 · 17:38
✕ 경상남도 재난안전상황실 보고 · 17:38
  연계 끊김 (09:02~)                     [유선 보고 기록]

[수정 문안 재전파]
```

### 4-3. 수정 문안 재전파

- SOP 실행 전에는 비활성이다.
- SOP 실행 후 활성화한다.
- 실제 수정한 문안과 선택한 수단을 저장한다.
- 직전 전파와 수단이 겹치면 확인창을 띄운다.
- 확인창에는 중복 수단·직전 전파 시각·대상 인원을 표시한다.
- 최초 SOP 전파와 재전파를 기록 유형으로 구분한다.

권장 기록 유형:

```ts
dispatchKind: "sop" | "manual-resend"
```

## 5. 전파 내역의 역할 분리

### SCR-03에서 보여줄 것

- 선택한 현재 사건의 1차 전파
- SOP 전파 결과
- 수정 문안 재전파
- 실패와 대체 조치

이 정보는 사건 타임라인과 실행 결과에 표시한다.

### SCR-04로 이동할 것

- 전체 사건의 전파 원장
- 다른 지구의 전파 이력
- 전파 실행 횟수
- 전파 대상 사건 수
- 최초 전파 소요시간
- 재전파 횟수
- 채널·대상 인원·실패·대체조치 상세

재전파를 단순 전파 건수에 합쳐 대응 사건 수가 부풀지 않도록 집계를 분리한다.

## 7. 인터랙션 규칙

- 사건을 바꾸면 지도·CCTV·발령 기준·판정·SOP·현재 사건 타임라인이 함께 바뀐다.
- 계측 단계와 승인 대응등급은 끝까지 별도 값으로 유지한다.
- 승인 전에는 되돌릴 수 없는 SOP 항목을 실행할 수 없다.
- 승인 후 선택한 항목만 실행 결과에 나타난다.
- 자동 처리도 성공·실패 결과를 남긴다.
- 실패는 성공처럼 표시하지 않고 사유와 대체 조치를 같은 기록에 남긴다.
- [상세 기록 보기]는 우측 내부 스크롤과 분리해 항상 화면 안에 둔다.
- 우측 내부 콘텐츠만 스크롤하고, 패널 사이 휠 입력이 지도 줌으로 전달되지 않게 한다.

## 8. 정본 반영 대상

### 03 화면정의서 §3

- 독립 `상황전파 문안` 블록을 SOP의 전파 항목으로 편입
- `이벤트 전파 내역` 블록을 전체 목록에서 현재 사건 결과로 축소
- 전체 전파 원장은 SCR-04가 맡는다고 명시
- 현재 사건 타임라인의 배치와 역할 명시
- 수정 문안 재전파 규칙 유지
- [상세 기록 보기] 하단 고정 명시

### 04 데모 데이터

- SOP 전파와 수정 문안 재전파의 기록 유형
- 실제 전송 문안·수단·대상·시각·기록자
- 최초 전파와 재전파의 집계 규칙
- 타임라인 파생 규칙

### 05 시나리오

- S6에서 별도 상황전파 패널을 조작하지 않음
- SOP 안에서 문안·대상·수단을 확인하고 승인·실행
- S7에서 실행 결과와 실패·유선 대체조치를 확인
- S8은 [상세 기록 보기]로 SCR-04 이동

## 9. 수용 기준

- [x] 상황전파 독립 패널이 사라지고 SOP 전파 항목 안에 문안·수단·대상이 보인다.
- [x] 최초 전파는 SOP 승인·실행 한 경로에서만 발생한다.
- [x] SOP 실행 전 재전파 버튼은 비활성이다. (실행 결과 하단으로 이동해 실행 전에는 존재하지 않는다)
- [x] 실행 후 수정 문안 재전파와 중복 확인이 가능하다.
- [x] 현재 사건의 전파·실패·대체 조치가 타임라인에 나타난다.
- [x] 다른 사건의 전체 전파 내역은 SCR-03을 차지하지 않는다.
- [x] 전체 전파 원장은 SCR-04에서 조회할 수 있다. (사건 이력 탭 · 사건별 하위 행)
- [x] [상세 기록 보기]는 1280×720에서도 항상 보이고 클릭할 수 있다. (승인 전·SOP 후 좌표 클릭 검증)
- [x] 승인 전·승인 후·SOP 실행 후에도 우측 핵심 CTA가 화면에서 사라지지 않는다.
- [x] 재전파가 최초 전파 소요시간이나 전파 대상 사건 수를 부풀리지 않는다. (`durationMin` 최초 전파 한정 · `eventId` 고유 수 집계)

## 10. 기대 효과

- 화면의 질문이 “무엇을 보내나”에서 “무엇을 판단하고 실행하나”로 명확해진다.
- SOP와 별도 전파 버튼의 중복이 사라진다.
- 현재 사건 처리와 과거 사건 복기의 책임이 SCR-03·SCR-04로 분리된다.
- 우측 정보 밀도가 낮아지고 승인·실행·실패 처리의 시선 흐름이 선다.
- CUVIA 공통 문법인 **판정 → 승인 → SOP → 실행 결과 → 기록**이 한 화면에서 끊기지 않는다.
