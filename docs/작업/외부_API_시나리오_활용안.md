## 1. 목적

외부 API를 많이 붙이는 것이 목적이 아니다. 각 API는 시연에서 다음 셋 중 하나를 맡아야 한다.

1. **상황 인지** — 도시 전체의 기상·위험 배경을 빠르게 보여준다.
2. **교차검증** — 센서·CCTV·공식 위험지도를 겹쳐 같은 사건을 여러 근거로 확인한다.
3. **공간 분석 표현** — 조건 수위를 적용했을 때 낮은 곳부터 차오르는 모습을 보여준다.

외부 API가 대응등급을 자동 결정하거나 미래를 예측하는 것처럼 말하지 않는다. 판정의 정본은 [04 데모 데이터](../레거시/정본/04_데모_데이터.md)이고, 외부 데이터는 그 판단을 설명하는 근거와 공간 표현이다.

## 5. API별 구체 활용

### 5-1. Open-Meteo 바람 격자

#### 사용할 장면

- S0 종합상황: 기본 ON
- S1~S3: 지도 입자 레이어를 다시 띄우기보다 우측 기상 패널의 풍향·풍속 값으로 요약

#### 보여줄 것

- 남해안에서 창원으로 들어오는 바람의 방향
- 해안 지구가 같은 기상 영향권에 놓였다는 공간적 맥락
- 서항·명동항·구항이 동시에 주의 상태인 배경

#### 말할 내용

> “창원시 전체 바람장과 해안 위험지구를 함께 봅니다. 서항을 포함한 해안 지구가 같은 강풍 영향권에 놓여 있습니다.”

#### 쓰지 않을 표현

- API가 폭풍해일을 예측했다
- 바람 격자가 서항 경보를 발령했다
- 현재 2026년 실시간 관측이라고 단정

#### 구현 규칙

- 현재 사전 수집 JSON을 사용해 시연 중 네트워크를 타지 않는다.
- 화면 시각은 시나리오 시계 17:16~17:39를 따른다.
- 원본 날짜와 출처는 레이어 정보 또는 데이터 메타데이터에 보존한다.
- S2 격상 순간 바람장이 불필요하게 바뀌지 않도록 같은 프레임 또는 부드러운 보간을 사용한다.

### 5-2. Open-Meteo 기온 격자

#### 사용할 장면

- S0 종합상황의 도시 배경 위험
- 메인 시연에서 시간이 부족하면 토글을 켜지 않고 폭염 카드만 설명
- 확장 시연에서 기온 레이어를 켜 폭염 분포를 보여줌

#### 보여줄 것

- 창원 시내의 기온 공간 분포
- 폭염경보와 체감온도 카드의 공간적 배경
- 하나의 플랫폼이 폭풍해일뿐 아니라 폭염도 함께 관리한다는 범위

#### 사용하지 않을 곳

- 서항 폭풍해일 위험도 산식
- 4.24 EL.m 조건 시나리오 계산
- 대응등급 대피 권고의 직접 근거

#### 말할 내용

> “같은 시각 창원시는 폭염경보도 발효 중입니다. 기온 분포를 겹쳐 복합재난 상황을 한 화면에서 확인할 수 있습니다.”

### 5-3. 강수·기압 추가 수집

현재 화면에는 정본 고정값이 있지만 외부 격자로는 아직 수집하지 않았다. 클로드가 API 활용을 고도화할 때의 우선 추가 대상이다.

#### 권장

- 바람과 동일한 태풍 사례일에서 시간당 강수량·기압을 함께 수집한다.
- S1~S3의 기상 패널 값에 사용한다.
- S5 판정 카드에는 원자료 전체가 아니라 `기압 하강`, `시간당 강우 지속`으로 요약한다.

#### 제한

- 정본의 `강우 유입 +0.38m`는 강수량 그 자체가 아니라 시나리오 가정이다.
- API 강수량을 그대로 수위 상승량으로 환산하지 않는다.
- 실제 수문 모델이 없는 상태에서 강수→수위 변환식을 만들지 않는다.

### 5-4. 생활안전지도 해안침수예상도

#### 사용할 장면

- S4 디지털트윈의 공식 비교 레이어
- S0에서는 기본 OFF. 레이어가 있다는 것만 보여줄 수 있음

#### 보여줄 것

- 행안부 공식 해안 위험구역
- 자체 조건 시뮬레이션 침수면과 공식 위험구역의 공간적 중첩
- 해안도로·저지대·대피소와의 관계

#### 권장 조작

1. 디지털트윈 진입 — 현재 3.41 EL.m
2. `[만조 조건 4.24]` 프리셋 선택
3. 영향 건물·도로·대피 대상 확인
4. `해안침수예상도` 레이어 ON
5. 조건 시뮬레이션과 공식 위험구역을 비교

#### 말할 내용

> “현재 조건을 적용한 시연용 침수 시뮬레이션에 행안부 해안침수예상도를 겹쳐, 공식 위험구역과 공간적으로 교차확인합니다.”

#### 구분해야 할 것

- 자체 침수면: 조건 수위에 따라 차오르는 시연용 공간 표현
- 공식 해안침수예상도: 행안부가 제공하는 위험지도
- 둘을 합쳐 API가 4.24m 침수범위를 계산했다고 말하지 않는다.

### 5-5. 생활안전지도 침수흔적도

#### 사용할 장면

- S4의 선택 비교 레이어
- S8 사건 이력에서 당시 참고한 공식 자료로 기록 가능

#### 보여줄 것

- 과거 실제 침수 흔적과 현재 위험구역의 관계
- 반복 위험 지역이라는 설명의 공간 근거

#### 우선순위

메인 7분 시연에서는 선택 사항이다. 해안침수예상도까지 보여준 뒤 시간이 있을 때만 켠다.

### 5-6. 생활안전지도 지방하천 범람지도

#### 사용할 장면

- 메인 서항 사건에는 사용하지 않음
- 창원천·남천 사건을 별도로 보여주는 확장 시연

#### 이유

해안 폭풍해일과 하천범람을 한 장면에 동시에 겹치면 재난유형과 공식 지도의 의미가 섞인다.

### 5-7. MapTiler 베이스맵

MapTiler는 시나리오 근거가 아니라 모든 공간 화면의 기반 인프라다.

- S0: 시 전체 위험지구 배치
- S1~S3: 서항 장비·위험요소 위치
- S4: 3D 건물·지형·침수 레이어 기반
- SCR-03: 선택 사건 현장 위치

발표에서 API 기능으로 별도 강조할 필요는 없다.

### 5-8. MapTiler 지형 고도와 사전 지형 격자

#### 사용할 장면

- S4 디지털트윈

#### 보여줄 것

- 수위가 오르면 낮은 지형부터 차오르는 과정
- 현재 3.41과 만조 조건 4.24의 시각적 차이

#### 제한

- 현재 고도 격자는 공식 침수 산정용 DEM이 아니다.
- 정확한 침수 범위의 공식 답은 해안침수예상도가 맡는다.
- 지형 격자는 차오르는 과정의 설득력과 3D 표현을 맡는다.

## 6. 시나리오 시간 매핑 규칙

외부 데이터의 실제 날짜와 데모 날짜가 다르므로 명시적인 매핑 계층을 둔다.

```ts
interface ScenarioExternalSnapshot {
  step: "S0" | "S1" | "S2" | "S3" | "S4" | "S8";
  demoAt: string;     // 화면과 상태 엔진이 사용하는 2026-08-12 시각
  sourceAt: string;   // 외부 API 원본 시각
  sourceName: string;
  wind?: unknown;
  temperature?: unknown;
  precipitation?: unknown;
  pressure?: unknown;
}
```

### 규칙

- 화면의 시계·이벤트 정렬·상대시간은 `demoAt`만 사용한다.
- `sourceAt`은 데이터 출처와 재현을 위한 메타데이터다.
- 화면에 원본 날짜를 크게 노출해 시연 흐름을 깨지 않는다.
- 출처 상세·정보 버튼·개발 문서에서는 원본 날짜를 확인할 수 있어야 한다.
- S0~S7 동안 같은 사건의 기상장은 시간적으로 단조롭고 자연스럽게 이어져야 한다.
- 외부 사례일을 바꾸더라도 정본의 이벤트·SOP·통계 원장은 바꾸지 않는다.

## 7. 정본 데이터와 외부 API의 우선순위

충돌 시 다음 순서를 따른다.

1. **04 데모 데이터의 사건·판정·시나리오 값**

3. 선정한 외부 사례일 데이터

## B-1 사례일: 2024-09-21 창원 집중호우

제14호 태풍 풀라산 약화 열대저압부. 창원 1시간 104.9mm(1985년 관측 개시 이래 9월 최고) · 하루 397.7mm(역대 최대) · 이틀 529.4mm. 호우특보 발효 이력과 대피·침수 보도(마산회원구 합성동 포함)가 있어 봉암 트랙의 사례일로 최적이다. 보조 후보는 2023-08-10 태풍 카눈(북창원 261.1mm).

Open-Meteo 실호출 검증: ERA5/IFS는 봉암(35.219, 128.583) 사례일 데이터를 정상 수신(21일 총량 약 173mm · 최대 36.3mm/h). kma_seamless 1.5km 모델은 이 사례일을 커버하지 않는다(전부 null · 보유 구간 2025년 중반 이후 추정).

**제한(화면 메타에 남길 것):** 재분석 격자는 실측 첨두(104.9mm/h)를 재현하지 못한다. 격자는 공간 배경(비구름 이동) 담당, 화면의 54mm/h·148mm는 정본 04 §15 고정값 담당. 본문 §7의 분업 그대로다. 수집물 전부에 `sourceAt(2024-09-21) → demoAt(2026-08-13)` 매핑 메타를 붙인다(§6 규칙).

## B-2 확인된 사실 (요약)

- **하천 수위 관측소 실재**: WAMIS 무인증 실호출로 창원 T/M 지점 5곳 확인. `2504660 창원시(창원천제1호교)`(창원천 · 2024년 국가하천 승격 · **도시침수예보 시범 지역**), `2504662 석전3교`(봉암 배수구역 인접) 등. 실시간·최근 시계열은 홍수통제소 공통 API `api.hrfco.go.kr/{키}/waterlevel/list/10M/{코드}.json`. 과거 사례일 시계열 보유는 미검증(WAMIS 시자료는 빈 응답).
- **침수흔적도가 봉암을 덮는다**: IF_0092 봉암 bbox 실호출 200 · 폴리곤 렌더 확인. B4 트윈·관제의 공식 과거 침수 근거. "과거 흔적이지 현재 예상 범위가 아니다" 구분 문구 유지.
- **배수펌프장은 실명으로 존재**: 공공데이터포털 창원시 배수펌프장 현황 CSV에 봉암(마산회원구) 포함 9개소. 서항1·2도 있다. 봉암펌프장 실제 펌프 대수와 시나리오 "3대" 일치 여부를 CSV로 대조할 것. 가동 상태·배수문 개폐의 공개 API는 없으므로 `08:47 폐쇄` · `펌프 3대 07:52~`는 시나리오 고정값으로 유지하고 외부 연동처럼 말하지 않는다.
- **재난문자 문안 참조 가능**: 재난안전데이터공유플랫폼 API(승인제)로 2024-09-21 창원·경남 발송 문안 수집 가능. B6 내수침수 어법(지하·반지하 대피) 교정의 참조 자료. 실제 문자를 복제하지 않는다.
