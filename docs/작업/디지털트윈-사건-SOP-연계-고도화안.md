# 디지털트윈 분석 결과의 사건·SOP 연계 고도화안

> 대상 화면: SCR-02 재난관제 · SCR-05 디지털트윈  
> 대상 데모: 서항지구 폭풍해일 · 봉암지구 호우·내수침수  
> 목적: 디지털트윈 상세 분석이 사건과 SOP에 언제, 무엇을, 어디까지 반영하는지 확정한다.

---

## 1. 핵심 결론

디지털트윈은 SOP를 자동 실행하는 화면이 아니다. **현재 사건의 공간 영향을 상세 검토하고, 그 결과를 SCR-02의 권고 대응과 SOP 초안에 구체적으로 채워 넣는 화면**이다.

전체 업무 흐름은 다음과 같다.

```text
사건 발생·계측 격상
  → SCR-02 기본 영향 자동 추정
  → 재난유형·권고등급에 맞는 SOP 템플릿 선택
  → SCR-05 디지털트윈 상세 분석
  → [분석 결과를 사건에 반영]
  → SCR-02 영향 분석 '검토 완료'
  → 권고 사유·SOP 대상·전파 문안 구체화
  → 담당자 대응등급 승인
  → 승인 대상 SOP 실행
  → 성공·실패·대체조치 기록
```

따라서 흔히 말하는 `SOP 발생`은 한 시점의 일이 아니다. 화면과 데이터에서는 아래 네 단계로 구분한다.

| 단계 | 의미 | 디지털트윈과 관계 |
|---|---|---|
| SOP 템플릿 선택 | 재난유형과 권고등급에 맞는 표준 절차를 불러옴 | 분석 전에도 가능 |
| SOP 초안 구성 | 대상 인원·도로·시설·문안을 채운 제안 상태 | 디지털트윈 결과 반영으로 구체화 |
| SOP 승인 | 담당자가 대응등급과 되돌릴 수 없는 조치를 확정 | SCR-02에서 수행 |
| SOP 실행 | 문자·방송·통제 요청 등을 실행하고 결과를 수집 | 승인 후 수행 |

화면 문구는 `SOP 발생` 대신 다음을 사용한다.

- 분석 전: `기본 대응 절차 제안`
- 분석 반영 후: `영향 분석이 반영된 대응 절차`
- 승인 후: `승인된 대응 절차`
- 실행 후: `대응 절차 실행 결과`

## 2. 디지털트윈 반영의 경계

### 2-1. 사건에 반영되는 것

사용자가 SCR-05에서 **[분석 결과를 사건에 반영]**을 눌렀을 때 다음 한 벌을 해당 사건의 최신 영향 분석 결과로 저장한다.

- 분석 기준 시각
- 선택한 시간대 또는 조건
- 현재 조건과 선택 조건
- 공간 영향 범위
- 영향 인구와 대응 대상
- 영향 건물·취약시설
- 통제 검토 도로
- 대피소·지원시설·현장 확인 지점
- 사용한 자료의 이름
- 분석이 전제로 삼은 가정
- 분석 수행자와 반영 시각

SCR-02는 이 결과를 읽어 다음을 갱신한다.

1. `영향 분석` 상태를 `자동 추정/상세 분석 필요`에서 `검토 완료`로 변경
2. 현재 조건과 선택 조건의 영향 차이를 표시
3. 위험도 판정의 권고 사유를 구체화
4. SOP 초안의 대상·구간·시설·문안을 구체화
5. 사건 진행에 `디지털트윈 영향 분석 완료` 기록 추가

### 2-2. 반영되어도 바뀌지 않는 것

디지털트윈 결과는 **관측 사실이나 담당자 결정을 대신하지 않는다.** 다음 값은 바꾸지 않는다.

- 실제 계측값
- 계측 단계(주의보·경보·대피)
- 사건 유형과 발생 시각
- 탐지 장비
- 처리상태(신규·확인중·대응중·종료)
- 승인 대응등급
- 도시 대응단계
- 문자·방송 발송 여부
- 도로 통제·대피소 개방 실행 여부

예를 들어 서항 수위가 `경보 3.41 EL.m`인 상태에서 19:10 영향 시나리오가 `4.24 EL.m`로 나타나더라도, 지도 핀과 계측 단계는 계속 **경보 3.41**이다. 디지털트윈은 `선제 대피 권고의 근거`를 붙일 뿐 계측을 대피 단계로 덮어쓰지 않는다.

### 2-3. 반영 전·후·승인 후의 차이

| 항목 | 분석 전 | 분석 결과 반영 후 | 승인·실행 후 |
|---|---|---|---|
| 계측 단계 | 실제 관측 단계 | 그대로 | 그대로 |
| 영향 분석 | 자동 추정 | 검토 완료 | 검토 완료 |
| 권고 대응 | 기본 권고 | 상세 영향 근거가 붙은 권고 | 승인 대응등급과 병기 |
| SOP | 템플릿·제안 상태 | 대상과 문안이 구체화된 초안 | 실행 결과로 전환 |
| 처리상태 | 확인중 | 확인중 | 대응중 |
| 사건 기록 | 발생·확인·격상 | 분석 완료 추가 | 승인·실행·실패·대체조치 추가 |

## 3. 공통 SOP 생성·실행 원칙

### 3-1. SOP 템플릿 선택 시점

재난유형과 권고 대응수준이 정해질 수 있는 시점에 시스템이 SOP 템플릿을 선택한다.

```text
재난유형 + 권고 대응수준 + 지구
  → SOP 템플릿 선택
```

예:

- `폭풍해일 + 대피 권고 + 서항지구` → `SOP-해일-대피`
- `내수침수 + 대피 권고 + 봉암지구` → `SOP-내수침수-대피`

템플릿 선택은 실행이 아니다. 이 단계에서는 절차의 종류만 정해지고, 실제 대상은 아직 기본값 또는 자동 추정값이다.

### 3-2. 디지털트윈이 SOP에 채우는 값

| SOP 필드 | 서항 폭풍해일 | 봉암 내수침수 |
|---|---|---|
| 분석 조건 | 19:10 바닷물 최고 시각 영향 | 09:35 강우 지속 영향 |
| 대응 대상 | 해안 저지대 주민 412명 | 저지대 주민 328명 |
| 통제 대상 | 해안도로 640m · 물양장 진입로 | 저지대 도로 470m · 수로변 도로 |
| 대피·지원 시설 | 해일 대피소 | 봉암 대피소·행정복지센터 |
| 집중 확인 장비 | 해안도로·방파제 CCTV | 배수문·수로 합류부·저지대 CCTV |
| 문안 조건 | 19:10 영향 우려 | 09:35 영향 우려 |
| 핵심 근거 | 천문조·해일 편차·강우 유입 | 강우 지속·내수위·배수 제약 |

### 3-3. 자동 처리와 승인 후 실행

SOP 항목은 되돌릴 수 있는지에 따라 두 부류로 구분한다.

**자동 처리**

- 사건 기록 저장
- 담당 부서 내부 알림
- CCTV 집중 감시 전환
- 배수시설 상태 확인 요청
- 승인 후 상급기관 자동 보고

자동 처리는 사전 승인 없이 시스템이 수행할 수 있다. 다만 **자동이라는 말은 결과 확인이 필요 없다는 뜻이 아니다.** 실패하면 반드시 실패 결과와 대체조치를 남긴다.

**담당자 승인 후 실행**

- 주민 재난문자
- 마을방송·전광판
- 도로 통제 요청
- 대피소 개방 요청
- 주민 대피 등 되돌리기 어려운 조치

이 항목들은 디지털트윈 결과가 반영돼도 자동으로 실행되지 않는다.

## 4. 서항지구 폭풍해일 상세 순서

### 4-1. 시나리오 기준

| 시각 | 상태 |
|---|---|
| 17:05 | 폭풍해일 사건 발생 · 수위 주의보 3.02 EL.m |
| 17:07 | 담당자 확인 |
| 17:09 | 1차 마을방송 |
| 17:22 | 수위 경보 3.41 EL.m 격상 · 시간대별 영향 시나리오 생성 |
| 17:25 | CCTV 현장 확인 |
| 17:29 | SCR-05 상세 분석 |
| 17:34 | 분석 결과 사건 반영 · SOP 초안 확인 |
| 17:37 | 대응등급 대피 승인 · 승인 대상 실행 |
| 17:38 | 도로 통제·대피소 개방 요청 접수 |
| 17:38~17:39 | 경상남도 보고 실패 확인 |
| 17:39 | 유선 보고 대체조치 기록 |

### 4-2. 분석 전 SCR-02

17:22 경보 격상 뒤 SCR-02는 다음을 자동으로 알고 있다.

```text
계측 단계       경보 3.41 EL.m
시간 영향       19:10 바닷물 최고 시각에 수위 상승 가능
기본 추정       영향 건물 47동 · 대응 대상 412명
권고 대응       선제 대피
영향 분석       상세 분석 필요
```

이 시점에 시스템은 `SOP-해일-대피` 템플릿을 선택할 수 있다. 하지만 도로·대피소·대상 범위는 아직 자동 추정이며, 담당자는 상세 공간 범위를 검토하지 않았다.

### 4-3. SCR-05 상세 분석

시연자는 다음 두 시간대를 비교한다.

```text
17:29 현재
수위 3.41 EL.m · 0.4ha · 건물 6동 · 도로 120m · 대응 대상 없음

19:10 바닷물 최고 시각
수위 4.24 EL.m · 3.1ha · 건물 47동 · 도로 640m · 대응 대상 412명
```

분석 근거와 가정:

- 수위계 관측 3.41 EL.m
- 천문조 2.71 EL.m
- 폭풍해일 편차 +1.15m가 19:10까지 유지된다고 가정
- 강우 유입 +0.38m가 현재 강도로 지속된다고 가정
- 생활안전지도 위험지구·침수취약도로·대피소 자료

### 4-4. [분석 결과를 사건에 반영]

버튼을 누르면 다음만 발생한다.

1. 서항 사건에 최신 영향 분석 스냅샷 저장
2. 사건 진행에 `17:34 디지털트윈 영향 분석 완료` 추가
3. SCR-02로 복귀
4. 영향 분석 카드가 `검토 완료`로 변경
5. SOP 초안의 대상과 구간 갱신

아직 발생하지 않는 것:

- 대피 대응등급 승인
- 문자·방송 발송
- 도로 차단
- 대피소 개방
- 처리상태 `대응중` 전환

### 4-5. 서항 SOP 초안

`SOP-해일-대피`는 총 7항목이다.

| 순서 | 항목 | 구분 | 분석 결과 반영값 |
|---:|---|---|---|
| 1 | 이벤트 기록·격상 이력 저장 | 자동 처리 | 사건 ID·경보 격상 17:22 |
| 2 | 담당 부서 알림 | 자동 처리 | 마산합포구 안전총괄과 4명 |
| 3 | CCTV 집중 감시 전환 | 자동 처리 | 해안도로·방파제 CCTV |
| 4 | 주민 긴급 재난문자 | 승인 후 실행 | 해안 저지대 412명 · 19:10 영향 우려 문안 |
| 5 | 마을방송·전광판 | 승인 후 실행 | 마을방송 1 · 전광판 2 |
| 6 | 해안도로 통제·대피소 개방 요청 | 승인 후 실행 | 해안도로 640m · 해일 대피소 |
| 7 | 경상남도 재난안전상황실 보고 | 승인 후 자동 처리 | 승인등급·영향 분석 요약 |

`경상남도 보고`는 시스템 자동 처리지만 **대응등급 승인 뒤에 실행 조건이 충족되는 항목**이다. 승인 체크박스 대상은 아니지만 실행 결과 확인 대상이다.

### 4-6. 승인과 실행

17:37 담당자가 다음 순서로 수행한다.

1. 판정 요약 확인
2. `대응등급 대피로 상향` 승인
3. 승인자·승인시각 기록
4. 처리상태 `확인중 → 대응중`
5. 주민문자·방송·도로 통제 항목 선택
6. `[승인·실행]`
7. 실행 결과를 위에서 아래로 표시

실행 결과:

```text
17:37  주민 긴급 재난문자 412명 발송
17:37  마을방송 1 · 전광판 2 송출
17:38  해안도로 차단 · 대피소 개방 요청 접수
17:38  경상남도 보고 실패 — 연계 끊김
17:39  유선 보고 완료 — 대체조치 기록
```

```text
계측 단계       경보 4.02 EL.m
강우 조건       현재 강우 지속
배수 상태       배수문 폐쇄 · 펌프 3대 가동

```

이 시점에 `SOP-내수침수-대피` 템플릿을 선택하지만, 어느 도로와 취약지역을 우선 대응할지는 상세 분석 결과로 구체화한다.

### 5-3. SCR-05 상세 분석

시간대별로 다음 세 장면을 비교한다.

```text
08:52 현재
내수위 4.02 EL.m · 0.6ha · 건물 2동 · 도로 150m · 대응 대상 없음

09:26 저지대 영향 시작
내수위 4.30 EL.m · 1.4ha · 건물 11동 · 도로 240m · 대응 대상 328명

09:35 강우 지속 영향
내수위 4.68 EL.m · 2.9ha · 건물 41동 · 도로 470m · 대응 대상 328명
```

분석 근거와 가정:

- 현재 내수위 4.02 EL.m
- 시간당 강우 지속
- 배수문 폐쇄 상태 유지
- 펌프 3대 가동 상태와 배출 한계
- 저지대 영향 시작 수위 4.30 EL.m
- 반지하·저지대·수로변 도로·배수시설 자료

`만조 09:12`는 봉암 화면의 주 분석명이 아니다. 외수위가 높아 배수문을 열 수 없는 **배수 제약의 근거**로만 표시한다.

### 5-4. [분석 결과를 사건에 반영]

09:01 반영 뒤 SCR-02는 다음처럼 선다.

```text
계측 단계       경보 4.02 EL.m
영향 분석       검토 완료
선택 조건       09:35 · 4.68 EL.m
영향 결과       건물 41동 · 도로 470m · 대응 대상 328명
권고 대응       선제 대피
권고 사유       계측 대피 기준 전 저지대 영향 시작 · 배수 제약 지속
```

계측 대피 기준은 5.83 EL.m이므로 계측 단계는 끝까지 경보일 수 있다. 승인 대응등급만 대피로 올라갈 수 있으며 두 상태를 합치지 않는다.

### 5-5. 봉암 SOP 초안

`SOP-내수침수-대피`는 총 8항목이다.

| 순서 | 항목 | 구분 | 분석 결과 반영값 |
|---:|---|---|---|
| 1 | 이벤트 기록·격상 이력 저장 | 자동 처리 | 내수침수 경보 격상 08:52 |
| 2 | 담당 부서 알림 | 자동 처리 | 마산회원구 안전총괄과 5명 |
| 3 | CCTV 집중 감시 전환 | 자동 처리 | 배수문·수로 합류부·저지대 도로 3대 |
| 4 | 배수펌프장 가동 상태 확인 | 자동 처리 | 봉암 배수펌프장 3대·배수문 상태 |
| 5 | 주민 긴급 재난문자 | 승인 후 실행 | 저지대 주민 328명 · 09:35 영향 우려 문안 |
| 6 | 마을방송·전광판 | 승인 후 실행 | 마을방송 3 · 전광판 2 |
| 7 | 저지대 도로 통제·대피소 개방 요청 | 승인 후 실행 | 도로 470m · 마산회원구청 |
| 8 | 경상남도 재난안전상황실 보고 | 승인 후 자동 처리 | 승인등급·영향 분석 요약 |

### 5-6. 승인과 실행

09:04 담당자가 다음 순서로 수행한다.

1. `계측 경보 / 권고 대피 / 승인 전` 상태 확인
2. `대응등급 대피로 상향` 승인
3. 승인자·승인시각 기록
4. 처리상태 `확인중 → 대응중`
5. 문자·방송·도로 통제 항목 선택
6. `[승인·실행]`
7. 자동 항목과 승인 항목의 결과 확인

실행 결과:

```text
09:04  이벤트 기록 저장
09:04  마산회원구 안전총괄과 5명 알림
09:05  CCTV 집중 감시 2/3대 성공
09:05  수로 합류부 CCTV 실패 — 통신끊김 · 원인 확인 중
09:05  펌프 3대 가동·배수문 폐쇄 상태 확인
09:05  주민 긴급 재난문자 328명 발송
09:06  마을방송 3 · 전광판 2 송출
09:06  저지대 도로 통제·대피소 개방 요청 접수
09:06  경상남도 상황실 보고 결과 확인
09:07  실패 CCTV 현장 확인 요청 · 대체조치 기록
```

통신 장애만 보고 `CCTV 함체 침수`로 원인을 확정하지 않는다. 이 시점에는 `통신끊김 · 원인 확인 중`으로 기록하고, 이후 현장 확인 결과가 들어왔을 때 원인을 갱신한다.

## 6. 서항과 봉암의 차이

| 구분 | 서항 폭풍해일 | 봉암 내수침수 |
|---|---|---|
| 현재 계측 | 경보 3.41 EL.m | 경보 4.02 EL.m |
| 주요 시간 | 19:10 바닷물 최고 시각 | 09:26 저지대 영향 시작 · 09:35 강우 지속 영향 |
| 위험 확대 원인 | 천문조 + 해일 편차 + 강우 유입 | 강우 지속 + 배수문 폐쇄 + 펌프 배출 한계 |
| 선제 대응 근거 | 시나리오 수위가 계측 대피 기준 초과 | 계측 대피 기준 전 저지대 영향 발생 |
| 대응 대상 | 412명 | 328명 |
| 통제 대상 | 해안도로·물양장 | 저지대 도로·수로변 |
| SOP 항목 | 7개 | 8개 |
| 추가 자동 항목 | 없음 | 배수펌프장 상태 확인 |
| 시연 실패 | 경상남도 보고 연계 실패 | CCTV 집중 감시 일부 실패 |
| 대체조치 | 유선 보고 | 현장 확인 요청 |

공통점은 다음과 같다.

- 디지털트윈은 계측 단계를 바꾸지 않는다.
- 분석 결과는 권고와 SOP 초안을 구체화한다.
- 담당자가 승인하기 전에는 주민 전파와 통제가 실행되지 않는다.
- 실행 실패는 숨기지 않고 대체조치로 연결한다.
- 승인 대응등급과 계측 단계는 별도 축으로 유지한다.

## 9. 현재 구현 확인과 남은 갭

현재 구현에는 다음이 들어가 있다.

- SCR-05 `[분석 결과를 사건에 반영]`
- 분석 스냅샷 임시 저장
- SCR-02로 복귀
- 사건 연계 분석과 사전 모의분석의 저장소 분리 방향
- 서항·봉암 SOP 템플릿과 실행 결과 더미

그러나 현재 코드 기준으로 다음 배선은 아직 완료되지 않았다.

1. SCR-02가 반영된 분석 스냅샷을 읽어 `검토 완료`로 표시하지 않는다.
2. 위험도 판정은 반영 스냅샷이 아니라 기존 조건 시나리오·침수 영향표를 직접 읽는다.
3. SOP 대상 인원·도로·시설이 분석 결과에서 파생되지 않고 더미에 고정돼 있다.
4. 분석 완료가 사건 타임라인에 연결되지 않았다.
5. 사전 모의분석 설정·저장 구조는 있으나 실제 화면 진입 배선이 미완성이다.
6. 봉암 시나리오를 선택한 뒤 화면 전환 상태가 서항 트랙과 섞이지 않는지 재검증이 필요하다.

### 데이터 불일치 정리 필요

현재 문서와 코드 사이에 다음 차이가 있다. 한쪽으로 확정한 뒤 04 데이터·05 시나리오·코드를 같이 맞춘다.

## 10. 구현 권장 순서

1. 분석 반영 데이터의 단일 소유자를 `ScenarioProvider`로 통합
2. 사건별 최신 분석 결과 조회 기능 연결
3. SCR-02 영향 분석 카드에 반영 결과 표시

5. SOP 초안 생성 시 분석 결과의 대상·구간·시설을 주입
6. 전파 문안에 선택 시간과 영향 대상 반영
7. 승인 전·승인 후·실행 후 상태 분리
8. 서항 시나리오 좌표 클릭 검증
9. 봉암 시나리오 좌표 클릭 검증
10. 새로고침과 `0` 시나리오 전환 시 데이터 격리 검증

## 11. 수용 기준

- [ ] 디지털트윈 진입만으로 사건 단계·처리상태·승인등급이 바뀌지 않는다.
- [ ] `[분석 결과를 사건에 반영]` 전에는 SCR-02가 `검토 완료`로 바뀌지 않는다.
- [ ] 반영 후 동일 사건의 SCR-02로 복귀한다.
- [ ] 계측 단계는 그대로 유지되고 권고 대응과 승인 대응등급은 별도 표시된다.
- [ ] 분석 조건·영향·근거·가정이 사건에 저장된다.
- [ ] 사건 타임라인에 분석 완료 시각이 추가된다.
- [ ] SOP 초안의 주민 수·도로·시설이 반영된 분석 결과와 일치한다.
- [ ] 분석 반영만으로 문자·방송·통제·보고 원장이 생성되지 않는다.
- [ ] 담당자 승인 전에는 되돌릴 수 없는 SOP 항목을 실행할 수 없다.
- [ ] 자동 처리 항목도 성공·실패 결과를 남긴다.
- [ ] 서항은 경남 보고 실패 뒤 유선 보고로 연결된다.
- [ ] 봉암은 CCTV 일부 실패 뒤 현장 확인 요청으로 연결된다.
- [ ] 봉암은 `계측 경보 / 승인 대피`가 끝까지 분리된다.
- [ ] 사전 모의분석 결과는 실제 사건·SOP·통계에 섞이지 않는다.
- [ ] 같은 사건을 재분석해도 사건 수와 최초 대응시간이 늘지 않는다.

## 12. 클로드 전달용 작업 지시

> 디지털트윈 분석은 사건의 계측 단계나 처리상태를 직접 변경하지 않는다. 사용자가 `[분석 결과를 사건에 반영]`을 선택했을 때 분석 조건·선택 시각·영향 범위·대상 인원·건물·도로·시설·근거·가정을 해당 사건의 최신 분석 결과로 저장한다. SCR-02는 이를 읽어 영향 분석 상태를 `검토 완료`로 바꾸고 권고 사유, SOP 초안의 대상·지역·시설·전파 문안을 구체화한다. SOP 템플릿은 재난유형과 권고등급으로 먼저 선택할 수 있지만 주민 전파·도로 통제·대피소 개방은 담당자 승인 전에는 실행하지 않는다. 분석 완료는 사건 타임라인에 기록하되 전파·통제 원장은 SOP 실행 뒤에만 생성한다. 서항은 7항목 SOP와 경남 보고 실패→유선 보고, 봉암은 8항목 SOP와 CCTV 일부 실패→현장 확인 요청 흐름을 적용한다. 계측 단계와 승인 대응등급은 끝까지 별도 축으로 유지한다.
