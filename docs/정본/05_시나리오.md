# 05 시나리오

시연 스크립트. 화면 구성은 [03 화면정의서](./03_화면정의서.md), 값은 [04 데모 데이터](./04_데모_데이터.md) 를 따르고,
이 문서는 **무엇을 어떤 순서로 눌러 무슨 말을 하는지**만 다룬다.

## §0 이 시연이 파는 한 줄

CUVIA 제품군은 어디서나 같은 척추를 쓴다. **위험도를 판정하고, 그 등급의 표준 절차(SOP)를 내놓고,
사람이 승인해 실행하고, 실행 결과가 기록으로 남는다.** DSMS 도 같다.

```
평시 감시 → 위험 징후 → 자동 경보(계측 격상) → 현장 교차검증 → 영향 분석(조건 시나리오)
   → 선제 대응 권고 → 담당자 승인 → SOP 실행 → 결과 확인(실패 포함) → 사후 검증
```

이 한 줄이 다섯 화면을 관통한다. 화면을 소개하는 시연이 아니라 **사건 한 건을 끝까지 처리하는
시연**이다. 그래서 화면 순서가 메뉴 순서와 다르다 — 디지털트윈이 통계보다 먼저 오고, 상황전파보다도
먼저 온다. 영향 분석은 대응을 결정한 뒤에 보면 아무것도 바꾸지 못하기 때문이다.

**주인공 사건** — 서항지구(해일) 수위 상승. 폭풍해일주의보가 발효된 8월 12일 오후, 주의보로 시작해
시연 도중 경보로 격상되고, 만조 조건 시나리오가 대피 기준을 넘어 선제 대피 대응으로 간다.

### 이전 판과 무엇이 달라졌나

이전 판은 남해군 원본 영상(38초)의 **메뉴 순서**를 그대로 늘린 것이었다. 화면 하나하나는 잘 서 있었지만
사건이 움직이지 않았다 — 시작 시점에 서항 경보가 이미 22분 전 일이라, 관제사가 지나간 일을 뒤따라
훑는 구조였다.

| | 이전 | 이번 |
|---|---|---|
| 출발점 | 원본의 메뉴 순서(전체→지구→센서→이벤트→통계→3D) | 사건 한 건의 시간 순서 |
| 사건 | 시연 시작 시점에 이미 끝나 있음 | **시연 도중 격상된다** |
| 트윈 | 전파를 끝낸 뒤 맨 마지막 | 대응을 결정하기 **전** |
| 통계 | 기능 소개 | 판단이 맞았는지 검증하는 증적 |
| 전파 | [전파] 버튼 하나 | **위험도 판정 → SOP 표출 → 승인·실행** 의 한 항목 |
| 연계 끊김 | 대시보드에서 한 번 짚고 버림 | 복선으로 심고 SOP 실행에서 **실제로 실패시킨다** |
| 폭염·가뭄 | 기능 나열 | 배경으로만. 별도 시나리오로 뺀다(§8) |

원본 영상의 흐름을 버린 것이 아니다. 원본이 보여준 화면 여섯은 그대로 다 나온다.
**순서만 사건의 순서로 바꿨다.**

## §1 시연 준비

| 항목 | 값 |
|---|---|
| 실행 | `cd designs && pnpm dev` → `http://localhost:5173` |
| 화면 | 브라우저 전체화면(F11). 1920×1080 이상. 다크 고정이라 조명 어두운 자리가 낫다 |
| 시작 자리 | `/` 로 들어가면 종합상황으로 넘어간다 |
| 시계 | 고정 시각이 아니라 **시나리오 시계**다. 17:16 에서 시작해 조작을 따라 흐르고, S8 에서 22:10 으로 넘어간다 (04 §0). 시연 시작 전에 사건은 이미 17:05 발생 → 17:07 확인 → 17:09 주의보 방송까지 와 있다 |
| 주인공 지구 | **서항지구**(해일 · 폭풍해일). 처음부터 끝까지 이 지구 하나다 |
| 데모 컨트롤 | 숫자 `0` 키로 여닫는 발표자 조작판(04 §0-2). **트랙 발사 전용**이다 — 서항·봉암 두 편을 고르고, 같은 편을 다시 쏘면 처음으로 되감긴다(리허설 복구). 시나리오 진행은 조작판이 아니라 화면 조작이 맡는다 |
| 분량 | 본편 약 6분 30초 + 에필로그 30초. 줄여야 하면 §7 |

사이드바는 80px 로 접혀 시작한다. 메뉴를 처음 누르면 240px 로 펼쳐지고 그대로 남으므로,
지도를 넓게 쓰려면 펼쳐진 뒤 로고 옆 `«` 로 다시 접는다.

시작 전에 한 번 훑을 것 — 지도 타일이 처음 뜨는 데 잠깐 걸린다. 시연 직전에 5개 화면을 한 바퀴
눌러 두면 본 시연에서 "지도를 불러오는 중" 이 뜨지 않는다.

> **시나리오 시계는 되감아야 한다.** 리허설로 격상을 한 번 지나가면 시계가 앞으로 가 있다.
> 본 시연 직전에 새로고침해 17:16 으로 되돌린다. 이 리셋을 잊으면 첫 화면부터 경보가 떠 있어
> 이번 개편의 핵심(사건이 시연 중에 움직인다)이 통째로 죽는다.

화면을 옮기는 길은 전부 **화면 안의 길**을 쓴다. 이번 대본에서 사이드바를 누르는 자리는 없다.
사건을 따라가면 다음 화면이 저절로 나오는 것이 이 개편의 요지이기 때문이다.

```
SCR-01  서항지구 클릭
   └→ SCR-02  [디지털트윈 분석]
         └→ SCR-05  [분석 결과를 사건에 반영]
               └→ SCR-02  [대응 실행] → 집중 팝업
                     [대응등급 대피로 상향] · SOP 실행 → [관제 화면으로 돌아가기] → 좌측 메뉴 [통계·분석]
                     └→ SCR-04  → 로고로 SCR-01 복귀 → 질의 바
                           └→ SCR-06  (에필로그)
```

> 그래서 이 화면이 대응을 결정한 다음이 아니라 결정하기 **전**에 있어야 합니다.
> 사고가 난 뒤가 아니라 나기 전을 보는 자리입니다.

**자막** — `대응을 결정하기 전에 영향을 확인한다` / `수위가 아니라 시간을 옮겨 본다` / `남은 시간이 결정을 만든다`

> 영향 분석이 판단 앞으로 오면 **분석에서 대응으로 넘어가는 길**이 반드시 있어야 한다.

## §4 예상 질문

| 질문 | 답 |
|---|---|
| 4.24 는 예측인가 | 아니다. 기상청 조위표의 천문조에 지금 관측 중인 해일 편차·강우를 더한 **만조 조건 시나리오**다(04 §10). 편차가 유지된다는 가정이 들어 있어 "예측" 이라 부르지 않고, 자동 예측 모델은 백엔드 협의 항목이다(03 §7) |
| 시나리오가 틀리면 | 이 데모에서도 7cm 틀렸다. 그래서 시나리오 하나로 자동 발령하지 않는다. 시스템은 **권고까지**, 등급 확정과 발령은 담당자가 승인한다(04 §10-1) |
| SOP 를 왜 자동 실행하지 않나 | 주민 문자·도로 차단·대피소 개방은 되돌릴 수 없는 조치다. 기록·알림·CCTV 전환처럼 되돌릴 수 있는 것만 자동 처리다. 자동 처리도 결과 확인은 남는다 — 실패하면 대체 조치로 잇는다(04 §11-1) |
| SOP 항목은 누가 정하나 | 지자체 매뉴얼을 그대로 옮긴다. 데모는 해일 3단계분을 세워 두었다. 단계·지구별 편집은 백엔드 협의 항목이다 |
| 도 상황실 연계가 실제로 끊기나 | 데모 연출이다. 다만 실제 현장에서 상급기관 연계 실패는 드물지 않고, 그때 화면이 성공처럼 보이는 것이 진짜 사고다 |
| CCTV 영상이 왜 안 나오나 | 데모에 실제 스트림을 연결하지 않았다. 채널 상태(LIVE · 통신끊김)까지 화면에 세워 두었고, 영상은 연동만 하면 이 자리에 그대로 붙는다 |
| 전파 버튼을 누르면 진짜 나가나 | 데모에서는 화면에 기록만 남는다. 실제 발송 경로와 결과 회신은 백엔드 협의 항목이다(03 §7) |
| 폭염·가뭄은 왜 안 쓰나 | 이 시나리오의 사건이 폭풍해일이라 배경으로만 둔다. 폭염 시나리오는 같은 척추(판정→권고→승인→SOP)로 따로 세울 수 있다(§8) |
| 열돔이 왜 판정에 없나 | 판정할 데이터(상층 고도·지속일수)가 없다. 폭염 카드의 정보성 표기(`열돔 영향 가능`)까지만 쓴다(04 §5) |
| AI 검색은 진짜 AI 인가 | 데모는 준비된 질의 3종에 확정 데이터로 답한다(04 §14). 답을 지어내지 않는 것이 원칙이고, 자연어 처리의 폭은 백엔드 협의 항목이다(03 §7) |
| 지도가 위성사진이 아니다 | 어두운 관제 화면에서 위성 타일은 마커 대비가 떨어진다. 제품군 공통 지도 톤을 쓴다(01 개요 §정한 것) |
| 3D 가 실사 모델인가 | 아니다. 지형(DEM)과 건물을 세우고 그 위에 수면을 얹는 방식이다. 실사 모델은 이번 범위 밖이다 |
| 침수 면적·건물 수는 실제인가 | 시연용 고정값이다(04 §12). 실제 산정은 DEM·건물 데이터와 겨뤄야 하는 백엔드 항목이다(03 §7) |
| 등고선은 없나 | 등고선 데이터가 없어 지형 음영으로 대신한다. 어디가 높고 낮은지를 보이는 목적은 같다. S4 에서 켜 보인 그 화면이다 |
| 레이어에 날씨효과가 있던데 | 비 내리는 결을 씬에 얹는 표현이다. 오늘 데모 기상이 맑음이라 켜지 않았다. 강우 상황을 재현할 때 쓴다 |
| 장비 좌표가 실제인가 | 시연용 근사값이다. 실제 설치 정보를 받으면 04 문서의 표만 교체한다 |
| 로그인·권한은 | 이번 데모 범위 밖이다. 상황실 담당자 한 명으로 고정했다 |

## §6 시연 중 피할 것

| 피할 것 | 왜 | 대신 |
|---|---|---|
| 격상을 보지 않고 트윈으로 넘어가는 것 | 격상 없이는 판정·대응 국면이 열리지 않는다. 이 데모에서 가장 좋은 컷이다 | 팝업을 열고 3초를 기다린다. 기준선 세 줄을 또박또박 읽으면 그 사이에 들어온다 |
| 격상 **전에** 다른 지구 칩을 누르는 것 | 사건이 없는 화면에서 격상이 나 아무도 못 본다 | 곁가지(여좌천 · 주남저수지)는 격상을 보고 난 뒤에만 |
| S5 에서 SOP 일곱 항목을 다 읽는 것 | 40초가 지나가고 리듬이 죽는다 | "위 셋은 자동, 아래 셋은 승인" 두 덩어리로만 말한다 |
| S7 에서 실패 줄을 빨리 넘기는 것 | 복선 회수가 회수되지 않는다 | 빨간 줄을 짚고 **3초 멈춘다.** 침묵이 이 장면의 연출이다 |
| 사이드바로 화면을 옮기는 것 | 다섯 화면이 따로 노는 것처럼 보인다 | 화면 안의 길만 쓴다(§2 이동도) |
| 리허설 뒤 새로고침을 잊는 것 | 시계가 앞으로 가 있어 첫 화면부터 경보가 떠 있다 | 본 시연 직전 반드시 새로고침 |
| **"시스템이 예측합니다" 라고 말하는 것** | 자동 예측 모델은 범위 밖이다(04 §10). "그 모델이 뭐냐" 질문에 답이 없다 | "만조 조건을 넣으면" 으로 말한다. 조위표 + 지금 관측값이라는 근거가 항상 붙는다 |
| S6 에서 [대응등급 대피로 상향] 없이 [승인·실행]부터 찾는 것 | 실행 버튼이 잠겨 있다. 등급 승인이 먼저다 | 카드 → 승인 → 실행 순서를 몸에 익힌다 |
| S9 에서 즉석 질문을 받는 것 | 준비된 질의 3종 밖은 답을 지어내지 않게 만들어져 있다 | 칩 3종만 누른다(04 §14) |

> 감사에서 나온 제약은 모두 해소됐다(2026-08-13 구현). A-1 은 SCR-03 재설계로 발생 그래프가

> 물 밖 자리로 교정했다). 검증 스크립트는 `designs/scripts/flood-check.mjs`.

## §7 짧게 해야 할 때

**3분 판** — S0 · S3 · S8 · S9 를 뺀다. S1 에서 바로 시작해 격상(S2) → 영향 분석(S4) → 권고·승인(S5 · S6) →
실패(S7) 로 간다. 사건의 척추는 그대로 남는다.
단, S0 을 빼면 S7 의 복선 회수가 약해진다. S1 도입부에 "경상남도 연계가 오전부터 끊겨 있습니다"
한 줄을 옮겨 심는다.

**90초 판** — S2 격상과 S5 · S6 만 남긴다.
"경보가 자동으로 판정되고, 권고에 맞는 절차가 뜨고, 승인 한 번으로 나간다" 세 컷이다.
이것이 CUVIA 문법의 최소 단위다.

**절대 빼지 않는 것** — S2 격상 · S5 위험도 판정과 SOP · S7 실패 처리.
셋 중 하나라도 빠지면 다시 "기능 데모" 로 돌아간다.

## §8 아직 없는 것

- **시연용 CCTV 영상.** 확보하면 S3 의 경고 문단을 지우고, SCR-02 팝업과 현장영상 타일의
  검은 자리에 넣는다. 서항지구 2대가 먼저 필요하다
- **폭염 시나리오.** 종합상황의 폭염경보·가뭄 카드가 이 시나리오에서는 배경으로만 쓰인다.
  같은 척추(위험도 판정 → SOP → 승인·실행 → 기록)로 폭염 대응 시나리오를 하나 더 세우면
  "물 재해 전용 시스템이 아니다" 가 구호가 아니라 대본으로 증명된다.
  독거노인 안부 확인 · 무더위쉼터 개방 · 야외작업 중지 권고가 그 SOP 항목이 된다
- **녹화본.** 이 대본대로 한 번 녹화해 두면 현장 네트워크나 지도 타일 사정과 무관하게 틀 수 있다.
  특히 S2 격상 타이밍이 녹화본에서는 항상 정확하다
