# 02 IA 화면구조

## 1. 메뉴

그룹 없이 6개 단층이다. 메뉴 순서는 **평시 업무 순서**다 — 전체를 보고, 지구로 좁히고, 대응하고, 되짚고, 앞을 본다. AI 검색은 그 어느 칸에도 속하지 않아 맨 뒤에 둔다.

메뉴명은 기능명이 아니라 **역할명**이다(참고자료 §1-1). 화면마다 답하는 질문이 하나씩 있다 — 종합상황 "지금 어떤 위험이 있고 어디를 먼저 보나", 재난관제 "이 지역이 왜 위험한가", 상황대응 "지금 무엇을 해야 하는가", 통계·분석 "반복과 대응은 어땠나", 디지털트윈 "조건이 악화되면 어디까지 잠기나".

| 순서 | 화면 ID | 메뉴명 | 경로 | 아이콘 | 전면 |
|---|---|---|---|---|---|
| 1 | SCR-01 | 종합상황 | `/scr-01` | `mdi:view-dashboard-outline` | O |
| 2 | SCR-02 | 재난관제 | `/scr-02` | `mdi:map-marker-radius-outline` | O |
| 3 | SCR-03 | 상황대응 | `/scr-03` | `mdi:bell-ring-outline` | O |
| 4 | SCR-04 | 통계·분석 | `/scr-04` | `mdi:chart-line` | |
| 5 | SCR-05 | 디지털트윈 | `/scr-05` | `mdi:cube-scan` | O |
| 6 | SCR-06 | AI 검색 | `/scr-06` | `mdi:creation-outline` | |

**SCR-06 은 순서가 아니라 옆길이다.** 나머지 다섯은 담당자가 순서대로 밟는 칸이고, AI 검색은 어느 칸에 서 있든 말로 물어 답을 받는 자리다. 그래서 메뉴 맨 뒤에 두되 진입은 SCR-01 종합상황 하단 중앙의 자연어 질의 바가 맡는다(03 §1). 사이드바 항목은 시연 중 눌릴 자리가 아니라 "이 화면이 있다"를 보이는 자리다.

**재난 기준 진입은 이번 범위 밖이다.** 분류 축(04 §4-0)이 서면 "풍수해 → 폭풍해일 → 영향지역" 으로 들어가는 두 번째 진입 UX 도 가능해지지만, 이번 데모의 강점은 창원 전체 → 서항지구가 빠르게 읽히는 것이다. 재난 분야·유형은 필터·통계·데이터 구조까지만 쓰고, 재난 중심 진입은 확장 사항으로 남긴다(03 §7).

**메뉴 순서와 시연 순서는 다르다.** [05 시나리오](./05_시나리오.md) 는 사건 한 건의 시간 순서를 따르므로 디지털트윈(SCR-05)이 상황대응(SCR-03)보다 먼저 온다. 영향 분석은 대응을 결정하기 전에 봐야 결정을 바꿀 수 있기 때문이다. 메뉴는 평시 순서, 시연은 사건 순서 — 둘을 맞추려고 메뉴를 뒤집지 않는다. 평시에 트윈을 먼저 여는 담당자는 없다.

전면(fullBleed) 화면은 상단바 없이 본문이 화면 전체를 쓴다. 지도나 3D 가 배경인 화면이고, 나머지 화면 요소는 그 위에 오버레이로 얹는다.

코드: `designs/src/layout/nav.ts`, `designs/src/router.tsx`. 진입 경로 `/` 는 곧바로 SCR-01 로 보내고 별도 진입 화면을 두지 않는다.

## 2. 화면 간 이동

화면 안에 다음 화면으로 가는 길이 있다. **[05 시나리오](./05_시나리오.md) 는 사이드바를 한 번도 누르지 않고 이 길만으로 끝까지 간다.** 메뉴로 다니면 다섯 화면이 따로 노는 것처럼 보이고, 화면 안의 길로 다니면 사건 하나를 처리하려고 이어져 있는 것으로 보인다. 데모에서 끊기면 안 되는 연결이다.

```
SCR-01 종합상황
  │ 지구 목록·지도 라벨 클릭         → SCR-02 (해당 지구로 확대)
  │ 자연어 질의 바 · 질의 칩         → SCR-06 (그 질의의 답)
  │
SCR-06 AI 검색
  │ 답변 카드의 [바로가기]           → SCR-02 / SCR-04 / SCR-05 (근거가 있는 화면)
  │
SCR-02 재난관제
  │ [디지털트윈 분석]               → SCR-05 (해당 지구 3D · 시점 유지)
  │ 센서 팝업 [상세 측정현황 보기]   → SCR-04 (해당 지구 기간 조회)
  │
SCR-05 디지털트윈
  │ [이 판단으로 대응하기]           → SCR-03 (그 지구 진행 중 이벤트 선택)
  │ 해당 지구 이벤트 목록 항목 클릭   → SCR-03 (같은 곳)
  │ 미니맵 지구 클릭                → 같은 화면, 다른 지구
  │
SCR-03 상황대응
  │ 이벤트 카드 선택                → 같은 화면 지도·CCTV·판정·SOP·문안 갱신
  │ [상세 기록 보기]                → SCR-04 (그 지구·그 사건 기간, 4단으로 스크롤)
```

**시연이 도는 길은 이 한 줄이다.**

```
SCR-01 → SCR-02 → SCR-05 → SCR-03 → SCR-04 → (에필로그) SCR-06
```

**SCR-06 은 이 줄의 끝에 에필로그로 붙는다**(05 §3 S9). 사건 여덟 장면에 질의 화면을 끼우면 시간이 끊기므로 본편에는 넣지 않고, 사건이 끝난 뒤 종합상황으로 돌아와 질의 바에서 연다 — 방금 처리한 사건을 말로 복기하는 20~30초다.

선택한 지구는 화면을 옮겨도 유지한다. SCR-02 에서 고른 지구가 SCR-05 에서 그대로 열려야 "이 지구를 3D 로 본다"가 성립하고, SCR-05 에서 판단한 사건이 SCR-03 에서 선택된 채 열려야 "이 판단으로 대응한다"가 성립한다.

**SCR-05 → SCR-03 은 새로 뚫은 길이다**([감사 B-2](../감사/01_구현_대조_감사.md)). 예전에는 트윈이 시연 맨 뒤라 나갈 길이 필요 없었지만, 영향 분석이 대응 판단 앞으로 오면서 필수가 됐다. 미니맵은 SCR-01 로 나가지 않고 같은 화면의 다른 지구로 옮겨 간다(03 §5).

## 3. 공통 골격

```
┌──────────┬───────────────────────────────┐
│          │ 상단바: 화면명 · 화면 ID        │
│ 사이드바  ├───────────────────────────────┤
│  (6메뉴)  │           본문 영역             │
└──────────┴───────────────────────────────┘
```

- 사이드바: 80px 접힘 ↔ 240px 펼침. 접힘 상태에서도 아이콘 아래 라벨을 보여 아이콘만 눌러 오가는 시연 조작이 가능하다
- 브랜드 영역 클릭 → SCR-01
- 다크 테마 고정. 24×365 상황실 환경 기준
- 전면 화면은 상단바를 쓰지 않는다

코드: `designs/src/layout/`.

## 4. 화면 번호

번호는 **메뉴 순서(평시 업무 순서)** 다. 시연 순서와는 무관하다(§1) — 시연은 SCR-05 가 SCR-03 보다 먼저 온다. 화면을 추가할 때는 이 문서를 먼저 고치고, `nav.ts` · `router.tsx` · `pages/scr-NN/` · [03 화면정의서](./03_화면정의서.md) 를 같은 번호로 맞춘다.
