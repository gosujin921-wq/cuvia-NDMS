# 01 데모 개요

## 무엇을 만드는가

지자체 안전재난관제 데모. **대상 지역은 창원특례시**다. 시 전체 조망에서 지구·센서·CCTV로 좁히고, 경보 이력을 판단해 주민에게 전파하고, 통계로 되짚고, 3D 침수 시뮬레이션으로 앞을 내다보는 흐름을 화면 5개로 보여준다.

화면 구성과 흐름은 남해군 조기경보시스템 시연 자료를 기준으로 삼았다. 지명·지구·수치는 창원시 것으로 새로 정했다(§정한 것).

참고 자료는 [참고자료/남해군_조기경보시스템_시연영상_상세시나리오](../참고자료/) 다. 남해군 시연 영상(38초, 7장면)을 초 단위로 분석한 문서이고, 원 제품은 타사 제품이다.

**타사 자료는 구성과 흐름만 참고한다.** 어떤 화면이 필요하고 어떤 순서로 이어지는지는 가져오되, 지구·장비 명칭과 전파 문안, 수치는 [04 데모 데이터](./04_데모_데이터.md) 에서 우리 표기로 새로 정한다. 원본 자료 안에서 표기가 엇갈리는 자리도 그대로 옮기지 않고 데모 기준으로 확정했다(아래 §정한 것).

## 대상과 설득 메시지

보는 사람은 지자체 재난안전 담당자와 상급기관이다.

### 관통하는 한 줄

CUVIA 제품군은 어디서나 같은 척추를 쓴다. **위험도를 판정하고, 그 등급의 표준 절차(SOP)를 내놓고, 사람이 승인해 실행하고, 실행 결과가 기록으로 남는다.** DSMS 도 같다.

```
평시 감시 → 위험 징후 → 자동 경보(계측 격상) → 현장 교차검증 → 영향 분석(조건 시나리오)
   → 선제 대응 권고 → 담당자 승인 → SOP 실행 → 결과 확인(실패 포함) → 사후 검증
```

화면 다섯이 각각 있는 것이 아니라 **사건 하나를 처리하려고 이어져 있다.** [05 시나리오](./05_시나리오.md) 가 이 한 줄을 사건 한 건으로 끝까지 밟는다.

### 여섯 가지 설득 메시지

| 메시지 | 어느 화면이 맡나 |
|---|---|
| 담당자가 아침에 켜자마자 시 전체 상황을 한 화면에서 판단한다 | SCR-01 |
| 숫자(계측값)와 영상(CCTV)을 같은 지도 위에서 교차검증한다 | SCR-02 |
| 사고 난 뒤가 아니라 나기 전에 침수 범위를 미리 본다 | SCR-05 |
| **계측값과 만조 조건 시나리오를 한자리에 놓고, 담당자가 선제 대응 등급을 승인한다. 그 등급의 표준 절차가 자동으로 나온다** | SCR-03 |
| **시스템은 제안까지, 실행은 승인이 있어야 한다. 실패한 것은 실패라고 말하고 대체 조치까지 기록한다** | SCR-03 |
| 쌓인 데이터로 "그때 왜 그렇게 판단했는지"를 근거로 말한다 | SCR-04 |

굵은 두 줄이 CUVIA 문법이 서는 자리다. 이전 판에서 SCR-03 은 "판단한 자리에서 전파하고 기록이 남는다" 한 줄이었고, 화면에는 [전파] 버튼 하나가 그 자리를 대신했다. 버튼 하나로는 **왜 그 등급인지 · 전파 말고 무엇을 더 해야 하는지 · 무엇이 자동이고 무엇이 사람 몫인지**가 보이지 않는다.

표의 순서는 시연 순서다(SCR-05 가 SCR-03 앞에 온다). 이유는 [02 IA §1](./02_IA_화면구조.md).

## 범위

- 사이드바 메뉴와 화면은 1:1. **위험도 판정 · SOP · 실행 결과는 화면을 새로 만들지 않고 SCR-03 안에 세운다** — 사건 하나를 처리하는 자리가 둘로 갈리면 "판단한 그 자리에서 대응한다" 가 깨진다
- 위험지구 12개. 지구 유형은 내수·하천·해일·저수지
- 계측 장비는 수위계·강우량계·변위계·CCTV. 마을방송은 전파 수단이자 트윈 레이어
- 이벤트 단계는 주의보·경보·대피 3단계. 그 위에 **권고 대응수준과 승인 대응등급**을 얹는다 — 조건 시나리오를 근거로 시스템이 권고하고 담당자가 승인한다 (04 §10)
- 재난 분류는 4분야(풍수해·기상·기후·수자원·산지·지반) + 재난유형(위험현상). 분야는 필터, 집계·도넛은 유형 축 (04 §4-0)
- SOP 는 **해일 3단계분**만 세운다. 다른 재해 유형은 이번 범위 밖
- 사건은 **한 건**이다. 서항지구 해일. 여러 사건을 늘어놓지 않는다
- 로그인·권한·설정 화면은 범위 밖. 데모 사용자는 상황실 담당자 한 명으로 고정한다

## 원본 시연에서 더하는 것

기준 문서 §4 의 요청 두 가지를 반영한다. 원본 영상에는 없는 내용이다.

**폭염·가뭄.** 원본은 폭풍해일·침수·수위 상승 등 물 재해 중심이고, 더위는 기상 카드의 기온·체감온도 숫자로만 스친다. SCR-01 기상 카드에 폭염 특보와 가뭄 항목을 세워, 여름 시즌 재해까지 같은 화면에서 받는 것을 보인다.

**연계 현황.** 상급기관 연계는 제안서에만 있고 화면에는 나오지 않는다. SCR-01 우측 하단에 연계 현황 패널을 세워, 기관별 연계 상태와 최근 전송 시각을 화면에서 바로 확인하게 한다.

## 정한 것

원본 자료에서 엇갈리거나 비어 있던 자리를 데모 기준으로 확정했다. 타사 자료를 대조할 일이 아니므로 되묻지 않고 이대로 만든다.

| 항목 | 결정 |
|---|---|
| 이벤트 단계 명칭 | 주의보 · 경보 · 대피 3단계. "경계"는 쓰지 않는다 |
| 위험도 표현 | IDC 제품의 Lv1~5 를 그대로 쓰지 않는다. 안전재난 분야는 주의보·경보·대피가 법정·관행 용어라, 그 3단계를 계측 단계로 두고 위에 대응 등급을 얹는다 |
| SOP 자동/승인 | 되돌릴 수 있는 것은 **자동 처리**, 되돌릴 수 없는 것은 **승인 후 실행**. 주민 문자·도로 차단·대피소 개방은 승인 없이 나가지 않는다. 자동 처리도 결과 확인은 필요하다 — 실패하면 대체 조치로 이어진다 (04 §11-1) |
| 예측 표현 | "AI 예측 · 자동 예측 · 침수 확률" 로 쓰지 않는다. 조위표 + 현재 관측을 합친 **만조 조건 시나리오**와 담당자 승인으로 표현한다 (04 §10) |
| 재난 분류 | 분류 기준은 시설이 아니라 발생 현상. 주남 변위는 저수지 지구지만 산지·지반/지반변위다. 임계 초과 이벤트는 `하천범람 위험` 처럼 "위험" 을 붙여 표시한다 (04 §4-0) |
| 처리상태 | 신규→확인중→대응중→종료. 상태 변경 버튼 없이 담당자 행동(열람·승인·해제)에 물린다 (04 §4-5) |
| 도시 대응단계 | 상시대비→초기대응(보강)→비상Ⅰ~Ⅲ. 종합상황 헤더에만. 데모는 시나리오 상태값 (04 §0-1) |
| 열돔·열대야 | 열돔은 폭염 카드의 정보성 표기(`열돔 영향 가능`)까지만 — 판정·센서 없음. 열대야는 범위 밖 (04 §5) |
| 화면명 | 종합상황 · 재난관제 · 상황대응 · 통계·분석 · 디지털트윈 · AI 검색 (02 §1) |
| 시연 시계 | 고정 시각이 아니라 시나리오 시계. 사건이 시연 도중 진행한다 |
| 대상 지역 | 창원특례시. 참고자료(남해군)의 지명은 쓰지 않는다 |
| 위험지구 | 12개로 고정. 창원시가 실제로 배수펌프장·우수저류시설을 둔 지구, 지방하천, 주남저수지, 항만에서 골라 5개 구에 나눈다 |
| 연계 기관 | 행정안전부 NDMS · 기상청 · 한국농어촌공사 · 경상남도 재난안전상황실 4곳 |
| 폭염·가뭄 | 폭염은 기상특보, 가뭄은 저수지 저수율에서 끌어온 4단계로 기상 카드 안에 함께 둔다. 별도 센서를 두지 않는다 |
| 장비 종류 | 수위계 · 강우량계 · 변위계 · CCTV · 마을방송 5종. 변위계 마커는 초록 |
| 지도 배경 | CUVIA 제품군 공통 MapLibre 스타일. 위성 타일은 쓰지 않는다 |
| 3D 표현 | 실사 모델 대신 지형·건물 압출 위에 침수면을 얹어 슬라이더로 올린다 |

수치·명칭·문안의 확정값은 [04 데모 데이터](./04_데모_데이터.md) 에 있다.
